# 合盖后 HUD 多显示器位置恢复讨论纪要

## 原始需求

用户发现电脑合盖后再打开，Traceflow 悬浮 HUD 会移到主显示器。希望记住原显示器上的位置，并在多显示器场景下恢复。

## 现有代码与原因

- HUD 已按横向、纵向分别保存显示器标识、显示器名称／像素尺寸及相对位置。
- 恢复位置时，若目标显示器暂时不可用，当前实现会把 HUD 放到主屏，随后无条件保存该位置，覆盖原显示器记录。
- `windowDidMove` 在窗口移动时保存位置；系统因合盖、断屏或显示器重排移动窗口时，也可能触发这个回调，将临时位置误当成用户选择。
- 应用监听显示器参数变化，但睡眠唤醒回调目前只检查会话完成超时，不触发 HUD 位置恢复。
- 当前显示器匹配在找不到唯一标识时，会依次尝试显示器 ID、名称＋分辨率、名称；多台同型号显示器可能产生错误匹配。

## 逐问记录

1. **问：合盖期间原显示器暂时消失，重新打开后又出现时如何处理？** 推荐临时显示在可用主屏，保留原显示器的位置记录；原显示器重新出现后自动移回。**用户答：**确认。
2. **问：原显示器不可用时，如果手动把 HUD 拖到主屏新位置，之后原显示器恢复应怎么办？** 推荐留在主屏；手动拖动代表重新选择位置，覆盖旧记录。**用户答：**确认。
3. **问：应用启动时原显示器尚未连接，之后再接上是否也自动移回？** 推荐要；启动时临时放主屏，原显示器回来后恢复，期间手动拖动可覆盖。**用户答：**确认。
4. **问：原显示器恢复时若分辨率或排列改变，位置怎么算？** 推荐保留在该显示器可用区域中的相对位置，并确保 HUD 完整可见。**用户答：**确认。
5. **问：两台同型号同分辨率显示器无法唯一识别原显示器时怎么办？** 推荐不猜测。**用户答：**无法自动识别时显示在主屏，等待用户操作。
6. **问：范围是否包括 HUD 控制器区分临时位置与手动拖动、显示器歧义匹配、睡眠唤醒／屏幕变化恢复，自动测试位置状态与匹配、人工验收合盖场景？** **用户答：**确认。

## 最终共同理解

1. HUD 只有一个；原屏暂时缺席时在主屏临时可见，但保存的原屏身份和相对位置不被覆盖。
2. 原屏再次出现后自动回到原屏，并用当前可见区域计算相对坐标；屏幕尺寸或排列改变时仍保证 HUD 完整可见。
3. 原屏缺席期间用户主动拖动 HUD，视为新位置选择，保存新屏位置；之后不自动回旧屏。
4. 启动时原屏缺席与运行中断屏使用相同规则；睡眠唤醒和显示器参数变化均触发恢复检查。
5. 显示器身份有歧义时停留在主屏，等待用户手动放置，不随机选择同型号显示器。
6. 针对临时回退、系统程序化移动、用户拖动、重新连接、显示器歧义和布局切换写明确规则与测试。旧 PRD 中“目标屏缺席时立即保存主屏回退位置”的要求被本次讨论更新。
