# HUD 钉住与鼠标穿透讨论纪要

## 原始需求

用户要求增加“钉住”功能：钉住时 HUD 不可移动、不可点击，鼠标事件穿透到下方窗口；在菜单栏下拉菜单中增加钉住与取消钉住的控制。

## 逐问记录

1. **菜单形式怎么选？** 推荐直接菜单项：未钉住显示“钉住 HUD”，钉住后显示“取消钉住 HUD”，点击即切换。**用户答：**确认。
2. **钉住状态是否在重启后保留？** 推荐保留；首次使用默认未钉住。**用户答：**确认。
3. **钉住后仍可通过菜单隐藏／显示 HUD，以及通过设置恢复默认位置吗？** 推荐可以；钉住只影响鼠标对 HUD 的直接操作。**用户答：**确认。
4. **钉住后仍按会话状态更新、在显示器变化时恢复正确位置吗？** 推荐是；只禁用 HUD 的鼠标事件。**用户答：**确认。
5. **鼠标点击和拖动钉住的 HUD 所在区域，是否由下方应用接收？** 推荐是；取消钉住后立即恢复 HUD 拖动。**用户答：**确认。
6. **实现范围？** 推荐窗口级鼠标穿透、菜单与持久化状态同步；自动测试默认值、重启恢复、切换状态，实际点击穿透人工验收。**用户答：**确认。

## 代码现状

- 目前菜单栏下拉菜单包含“隐藏／显示 HUD”“设置…”和“退出 Traceflow”。菜单标题由应用控制器在切换显隐时更新。
- HUD 为单个不抢焦点的悬浮 `NSPanel`。当前 `HUDDragView` 处理鼠标按下、拖动、松手，并在松手后保存位置；窗口级鼠标穿透尚未设置。
- HUD 显隐已存于用户偏好；布局与光晕也使用偏好存储。位置恢复与显示器变化处理独立于拖动。

## 最终共同理解

1. 在现有菜单栏下拉菜单中加入一个动态标题的直接操作项：“钉住 HUD”／“取消钉住 HUD”。
2. 钉住状态持久化，首次默认为未钉住；应用重启后在 HUD 显示前恢复鼠标穿透状态和菜单标题。
3. 钉住时整个 HUD 窗口忽略鼠标事件；点击、拖动、滚轮等鼠标操作穿透到下方应用，不启动 HUD 拖动、不改保存位置。取消钉住后立即恢复正常拖动。
4. 钉住不冻结 HUD 的会话状态、灯效、显示／隐藏、设置页恢复默认位置、显示器变化及合盖唤醒后的位置恢复。
5. 自动测试状态读写与切换结果；macOS 实机人工验收鼠标真正穿透、取消后的拖动及不抢键盘焦点。
