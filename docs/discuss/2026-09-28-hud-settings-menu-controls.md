# HUD 设置与菜单控制讨论

## 原始需求

用户提供设置弹窗和菜单栏截图，要求设置弹窗顶部依次显示“显示 HUD”“钉住 HUD”“HUD 布局”三个选项；菜单栏下拉列表也显示这三项。“HUD 布局”在菜单中使用二级菜单展示横向左、横向右、竖向上、竖向下，用对勾表示当前启用布局。当前阶段要求思考并给出实现规划。

## 问答记录

1. **问题：**菜单顶部的“显示 HUD”“钉住 HUD”，保留现有“隐藏 HUD／取消钉住 HUD”动态动作文案，还是改为固定名称并用对勾表示开关状态？**推荐：**固定名称和对勾，三项位置、名称稳定。**用户回答：**截至规划编写时尚未收到。**临时假设：**采用推荐方案；此项待用户批准 PRD 时一并确认。

## 代码现状与已确认的含义

- 设置页“常规”顶部已有“显示 HUD”开关和四项“HUD 布局”选择器，缺少“钉住 HUD”开关。
- 菜单栏当前前两项是动态文案的显隐、钉住操作，然后是“设置…”与退出；布局只能在设置页更改。
- `AppModel` 已持有并持久化 `isHUDVisible`、`isHUDPinned`、`hudLayoutMode`，窗口控制器已订阅布局及钉住状态。新入口应操作这些同一属性。
- 现有四种布局的语义按三色灯组所在端命名；新需求不修改排列、位置保存、透明度阈值或鼠标穿透行为。
- 本次设置页顶部顺序解释为同一“常规”分组内连续三行：显示 HUD、钉住 HUD、HUD 布局。菜单最前方也按同一顺序显示三项。

## 暂定共同理解

两个入口展示同一 HUD 状态。设置页新增钉住开关；菜单将显隐和钉住显示为固定名称及勾选状态，并增加四项布局子菜单，其中仅当前布局有对勾。菜单或设置页操作后立即生效，打开另一个入口时读取最新状态。菜单原有“设置…”和“退出 Traceflow”保留。

## 后续补充

用户要求 PRD 增加足够细节，供低智能模型编码。正式 PRD 因此补充现有状态映射、菜单层级、AppKit 子菜单 `target` 接线、`@Published` 赋值时序、单一窗口显隐调用入口、隐藏时改布局及钉住、测试矩阵与完成定义。菜单前两项的固定文案假设仍待批准时确认。
