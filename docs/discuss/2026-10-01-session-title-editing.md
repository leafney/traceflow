# 会话标题编辑：讨论记录

日期：2026-10-01

## 原始需求

“下一个功能，我希望能够支持会话的标题编辑功能。例如在置顶区或会话区，用户点击相应的标题区域，可以自定义当前会话显示的标题。思考该需求，然后给出功能实现规划。”

## 全部问答

1. 问：自定义标题是否只保存在 Traceflow 本地，并同时用于置顶区、会话区和 HUD？推荐本地保存、重启保留，HUD 沿用“项目名 · 自定义标题”，不修改 Codex 原始名称。
   - 用户答：“确认，另外只需要修改以上HUD格式中的 标题部分”。
2. 问：是否采用单击标题打开编辑弹窗，提供输入框、“保存”“取消”“恢复默认标题”，恢复后重新使用摘要或 Codex 名称？
   - 用户答：“确认”。
3. 问：是否采用单行、最多 100 字符、保存时去首尾空白、空白不可保存、恢复默认用于清除自定义值，同步和 Hook 不覆盖自定义标题？
   - 用户答：“确认”。

## 代码事实

- 会话数据具有 codexThreadName，运行快照具有仅内存保存的 conversationSummary，目前没有独立自定义标题字段。
- 两个列表通过 SettingsView.sessionListTitle 获取标题；HUD 通过 SessionSnapshot.displayTitle 拼接项目名。
- 导入器更新 Codex 名称；Hook 状态机更新摘要和项目元数据。自定义标题应独立保存，避免被这两条链路覆盖。
- 当前刷新选择的方法会触及调度；纯改名应只发布快照并更新当前 HUD 文本，不重置轮播周期。
- 会话保存接口可失败并更新健康状态；编辑弹窗不能在写入失败时宣称保存成功。

## 最终共同理解

- 点击任一区域的会话标题进入同一编辑弹窗；只编辑标题，不编辑项目名。
- 自定义值本地持久化；两个列表与 HUD 共用；不修改 Codex 原会话。
- 单行最多 100 个 Swift Character，去首尾空白；空白输入不保存，使用独立恢复默认动作。
- 自定义值优先于摘要及 Codex 名称；后台更新仍正常记录默认来源，不覆盖自定义值。
- 规划细化保存失败、编辑草稿、目标消失和 HUD 刷新处理；不改变会话状态、参与资格、活动时间或调度。
- 本轮只写讨论和 PRD，等待批准后实施。
