# Traceflow 项目分组与会话管理产品需求文档

Related discussion: [`docs/discuss/2026-09-22-grouped-session-management.md`](../discuss/2026-09-22-grouped-session-management.md)

状态：待批准
目标版本：MVP 0.1 设置页优化

## 0. 文档执行规则

本文是可直接交给编码模型执行的实现规范。实现者不得只完成视觉分组而遗漏默认关闭、批量操作、排序持久化或 HUD 联动。遇到本文已规定的行为时不得自行选择另一种实现；遇到未规定且会改变用户数据、排序或交互的事项时，应先更新 PRD 并获得用户批准。

实现者必须保留当前已经工作的 Hooks、App Server 会话同步、HUD 状态灯、轮播、日志和安装流程。不得为了简化本需求而删除功能、读取 transcript、把所有会话重新设为启用或改用数据库。

本文中的“会话”是 Codex thread/session 在 Traceflow 中的一条本地记录；用户口语中提到的“绘画”均按“会话”理解。

## Problem Statement

Traceflow 同步 Codex 历史会话后会产生一百多个会话记录。当前所有新增会话默认参与 HUD，导致大量不再使用的历史会话进入轮播；用户只能逐项关闭。设置页又使用单层列表混合展示不同项目的全部会话，难以定位和管理目标会话。

## Solution

将会话设置改为按项目组织的二级折叠列表。项目层显示项目信息、启用统计和批量开关，会话层保留独立开关和删除操作。所有新发现会话默认关闭，只有用户主动选择后才参与 HUD。Hook 实时发现的新会话及所属项目置顶，便于用户快速找到刚产生的会话。

## User Stories

1. 作为同步大量历史会话的用户，我希望新导入会话默认关闭，从而避免历史记录立即填满 HUD 轮播。
2. 作为创建新 Codex 会话的用户，我希望 Hook 新发现的会话也默认关闭，从而保持对 HUD 内容的主动控制。
3. 作为拥有多个项目的用户，我希望先看到项目列表，再展开查看项目内会话，从而快速理解信息层级。
4. 作为存在同名项目目录的用户，我希望不同完整路径的项目保持独立，从而避免会话错误混合。
5. 作为管理大量会话的用户，我希望一键启用项目内全部会话，从而减少重复点击。
6. 作为管理大量会话的用户，我希望一键关闭项目内全部会话，从而快速清空某个项目的 HUD 内容。
7. 作为只关心部分会话的用户，我希望仍可单独勾选会话，从而实现精确控制。
8. 作为用户，我希望项目行看到总会话数和已启用数，从而不展开也能了解选择情况。
9. 作为用户，我希望项目默认折叠，从而同步大量数据后页面保持紧凑。
10. 作为用户，我希望应用记住项目展开状态，从而再次打开设置时延续管理位置。
11. 作为正在使用新会话的用户，我希望 Hook 新发现的会话出现在所属项目顶部，从而无需在历史列表中寻找。
12. 作为正在使用新项目的用户，我希望产生新会话的项目移动到项目列表顶部，从而立即可见。
13. 作为用户，我希望项目置顶时不自动展开，从而不会突然改变正在浏览的界面。
14. 作为用户，我希望新会话置顶时不自动启用，从而不会绕过我的选择。
15. 作为用户，我希望关闭当前 HUD 会话后立即切到下一个已启用会话，从而让设置即时生效。
16. 作为用户，我希望没有任何会话启用时 HUD 显示 Traceflow 占位，从而明确知道当前未选择会话。
17. 作为用户，我希望同步已有记录时保留手动勾选结果，从而重复同步不会撤销我的选择。
18. 作为用户，我希望删除单条会话仍只删除 Traceflow 本地记录，从而不影响 Codex 对话。
19. 作为键盘和辅助功能用户，我希望项目展开、批量开关和会话开关都使用原生可聚焦控件，从而能通过键盘和 VoiceOver 操作。

## Implementation Decisions

### 总体数据流

实现后的单向数据流必须是：

1. App Server 同步或 Hook 事件产生/更新扁平会话记录。
2. 扁平记录持久化到现有会话 JSON。
3. 纯逻辑分组器按项目键和设置页排序键生成项目分组。
4. 设置页只读取项目分组，并通过 AppModel 暴露的单条/批量方法修改记录。
5. AppModel 修改完成后只调用一次会话刷新和一次持久化。
6. CarouselScheduler 继续接收扁平会话快照；它不知道项目分组，也不应新增项目概念。

不得让 SwiftUI View 直接修改 JSON、直接操作状态机字典或复制分组排序算法。

### 数据与分组

- 继续以会话 ID 作为会话唯一键，不引入数据库，不复制会话状态。
- 新增纯逻辑的项目分组模型或构建器，输入扁平会话快照，输出稳定有序的项目分组及组内会话。
- 项目分组键优先使用标准化完整项目路径。缺少路径时使用独立的“未知项目”分组，不使用显示名称作为唯一键。
- 项目显示名称优先使用已有项目名；缺失时显示“未知项目”。辅助文字显示完整路径或“未知路径”。
- 项目行显示“已启用数量 / 总数量”。项目批量控件需要表达全部关闭、部分启用和全部启用三种状态；部分启用不能被误显示为全部启用。

新增以下纯值语义，具体类型名可以保持项目风格，但字段含义不得改变：

```text
ProjectGroup
  id: String                    // 项目分组键
  displayName: String           // 项目标题
  projectPath: String?          // 标准化完整路径
  sessions: [SessionSnapshot]   // 已按设置页顺序排列
  enabledCount: Int
  totalCount: Int
  selectionState: none | partial | all
  listSortAt: Date              // 组内最大 settingsListSortAt
```

项目键生成规则必须逐条遵守：

1. `projectPath` 非空时，先使用 `URL(fileURLWithPath:).standardizedFileURL.path` 标准化，再作为分组键。
2. 路径末尾斜杠、`.` 和 `..` 标准化后相同的记录属于同一项目。
3. 不解析符号链接，不访问文件系统判断目录是否存在，避免同步旧会话时产生副作用。
4. `projectPath` 缺失或清理后为空时，统一放入固定键 `__traceflow_unknown_project__`。
5. 不允许仅用 `projectName` 分组；例如 `/Users/a/demo` 与 `/tmp/demo` 必须是两个项目。
6. `displayName` 使用分组中第一个非空 `projectName`；没有则从标准化路径取最后一级；仍没有则为“未知项目”。

为持久化会话增加一个可选设置页排序时间字段，建议语义名为 `settingsListSortAt`：

```text
settingsListSortAt: Date?
```

- 这是设置页排序专用字段，不能替代 `lastUpdatedAt`、`discoveredAt` 或 `rotationIndex`。
- 读取旧 JSON 时字段缺失必须成功解码；计算有效排序时间时依次回退到 `settingsListSortAt ?? lastUpdatedAt ?? discoveredAt`。当前模型中 `lastUpdatedAt` 非空，因此最终一定有值。
- 写回 JSON 时新记录必须包含该字段。
- 运行状态变化只更新 `lastUpdatedAt`，不得更新 `settingsListSortAt`，否则列表会在用户操作时不断跳动。
- 不提高现有会话 JSON schema 版本；该字段是向后兼容的可选新增字段。

### 默认选择规则

- `PersistedSession` 不再把新会话默认设为参与 HUD；构造新记录时必须显式或默认设置为关闭。
- App Server 同步新导入的会话设置为关闭。
- Hook 实时新发现的会话设置为关闭。
- 重复同步已存在的会话时保留其 `isIncludedInHUD`，不得重新关闭或重新启用。
- 本版本处于开发测试阶段，不提供一次性旧数据迁移。验收时可以清空 Traceflow 会话记录后重新同步。

必须明确区分“新记录”和“已存在记录”：

| 输入场景 | 本地是否已存在同 ID | `isIncludedInHUD` | `settingsListSortAt` |
|---|---:|---|---|
| App Server 同步 | 否 | `false` | Codex `updatedAt` |
| App Server 同步 | 是 | 保持原值 | 保持原值；旧记录缺失时补 `updatedAt` |
| Hook 首次发现 | 否 | `false` | App 接收事件的当前时间 |
| Hook 更新会话 | 是 | 保持原值 | 保持原值 |
| 用户单条勾选 | 是 | 设置为用户选择 | 保持原值 |
| 用户项目批量操作 | 是 | 统一设置目标值 | 保持原值 |

不要修改 `PersistedSession` 初始化器的默认值后就认为任务完成。App Server 导入器和 Hook 创建路径都必须有测试明确证明新记录为关闭；最好将初始化器默认值也改为 `false`，形成安全默认值。

### 排序规则

- 为“最近由 Hook 实时发现或活动”的项目维护内存或可持久化排序依据，确保最新项目位于顶部。
- Hook 首次发现的新会话排到所属项目会话列表顶部；后续普通状态事件不应在每次变化时反复打乱列表，避免用户点击目标跳动。
- 同步导入的历史会话按最后更新时间降序排列；重复同步保持确定性。
- 同步批次不按逐条导入顺序连续抢占项目顶部，项目顺序根据项目内最近会话时间稳定排序。
- `rotationIndex` 继续服务 HUD 公平轮播，不直接承担设置页的最近发现排序，防止 UI 排序改变轮播语义。

排序算法必须是确定性的：

1. 组内会话先按有效 `settingsListSortAt` 降序。
2. 排序时间相同，按 `rotationIndex` 降序；仍相同则按 `sessionID` 升序。
3. 项目的 `listSortAt` 为组内会话有效排序时间的最大值。
4. 项目先按 `listSortAt` 降序。
5. 项目时间相同，按 `displayName` 使用用户可见的本地化不区分大小写比较升序；仍相同则按项目键升序。
6. Hook 新会话使用当前时间，所以自然成为组内第一项，并使所属项目成为项目列表第一项。
7. Hook 已存在会话发生 `UserPromptSubmit`、`PermissionRequest`、`Stop` 等状态变化时不改变设置页排序。
8. App Server 同步一批历史记录时使用各自 `updatedAt`，不能使用同步执行时间，否则一百多个项目会得到同一时间并产生随机顺序。

“置顶”只指排序结果，不设置永久固定标记。之后发现另一个更新的 Hook 新会话时，后者可以成为新的第一项。

### 设置页交互

- 会话区保持 SwiftUI 原生设置表单风格，每个项目使用原生披露控件形成二级层级。
- 项目默认折叠；用户手动展开或收起后，将项目分组键保存到本地偏好。不存在的项目键在适当时机清理。
- Hook 新会话和项目置顶时不自动展开项目、不改变键盘焦点、不滚动抢占当前位置。
- 项目行提供明确的批量启用与关闭能力。为了兼容部分选中状态，可使用三态复选语义，或使用“全部启用”“全部关闭”菜单；最终控件必须有文字或辅助功能标签，不能只靠颜色表达。
- 批量修改同一项目时，先在内存更新该组全部会话，再统一刷新调度器并持久化一次，避免一百次 UI 重排和磁盘写入。
- 会话行保留独立勾选、标题、路径之外的短会话标识、更新时间、运行状态和删除按钮。
- 删除项目内最后一个会话后，项目分组立即消失。
- 会话较多时避免在一个不可控的嵌套滚动容器中渲染；设置窗口应提供足够高度，并使用平台原生滚动行为。

设置页会话区从上到下固定为：

1. 第一行：“同步 Codex 会话”按钮、同步中的进度指示。
2. 第二行：同步结果或错误信息。成功文案追加“新会话默认关闭，请展开项目并选择需要参与 HUD 的会话”。
3. 无数据时显示“尚未发现会话”。
4. 有数据时显示项目披露列表。
5. 最底部保留“清空全部记录”破坏性操作。

每个项目头部必须包含：

- 展开/收起按钮或系统披露箭头。
- 项目名称，单行尾部省略。
- 辅助文本：完整路径，单行尾部省略；未知路径显示“未知路径”。
- 统计文本：`已启用 X / Y`。
- “全部启用”和“全部关闭”两个文字操作。窗口宽度不足时可放入名为“批量操作”的菜单，但不能只放无标签图标。

项目批量操作按钮状态：

- `enabledCount == totalCount` 时禁用“全部启用”。
- `enabledCount == 0` 时禁用“全部关闭”。
- 部分启用时两个按钮都可用，统计必须明确显示部分选中。
- 项目没有会话时不应出现在分组结果中。

每个会话行必须包含：

- “参与 HUD”复选框，不能改成仅点击整行切换。
- 会话标题。由于项目名已在父级展示，子项标题不得重复拼接项目名；优先使用内存 `conversationSummary`，其次持久化 `codexThreadName`，都没有时显示“未命名会话”。
- 辅助文本：短会话 ID、最后更新时间。项目路径不必在每个子项重复显示。
- 当前运行状态，界面文案映射为“待机 / 执行中 / 等待权限 / 已完成”，不得直接显示英文枚举值 `idle` 等。
- 删除按钮及可访问标签“删除会话 <标题>”。

展开状态实现规则：

- 使用项目键集合表达展开项目，例如 `expandedProjectKeys: Set<String>`。
- 保存到 UserDefaults 的字符串数组；不得写进会话 JSON。
- 第一次看到任何项目时均为折叠，因为集合默认空。
- 用户点击披露控件时立即更新集合并保存。
- 同步或删除后，可移除已经不存在的项目键；清空会话时清空展开集合。
- Hook 新会话到达时不得自动把项目键加入集合。

批量方法必须由 AppModel 提供类似以下语义接口：

```text
setIncluded(sessionID, included)
setProjectIncluded(projectKey, included)
deleteSession(sessionID)
```

`setProjectIncluded` 的处理顺序固定为：找到该项目的全部会话 ID → 在内存逐条修改 → 调用一次 `refreshSessions()` → 调用一次 `persistSessions()`。禁止循环调用现有单条 `setIncluded`，因为那会导致每项各刷新和写盘一次。

### HUD 与状态

- HUD 和 CarouselScheduler 继续只消费 `isIncludedInHUD == true` 的会话，不改变红、黄、绿状态语义与公平轮播算法。
- 单条或批量关闭当前 HUD 会话时，调度器立即选择下一个已启用会话。
- 没有任何启用会话时显示 Traceflow 占位，三灯熄灭。
- 未启用会话仍接收和保存 Hook 状态更新，只是不参与 HUD。

注意：默认关闭只影响 `isIncludedInHUD`。不得因为关闭而停止接收 Hook、停止更新时间、丢失会话名称或过滤掉设置页记录。

### 模块职责

- 持久化会话模型：增加可选设置页排序时间，并提供向后兼容解码。
- App Server 导入器：新会话默认关闭并赋予 Codex `updatedAt` 排序时间；已有会话保留选择和排序时间。
- Hook 会话创建逻辑：新会话默认关闭并使用当前时间作为设置页排序时间。
- 项目分组器：纯 Swift、无 AppKit/SwiftUI 依赖，负责项目键、分组、统计和确定性排序。
- AppModel：发布项目分组或提供由 sessions 计算的分组，处理批量选择与展开偏好。
- SettingsView：只负责原生分层呈现和调用 AppModel，不自行实现业务排序。
- CarouselScheduler：原则上不修改；只有现有测试暴露选择切换缺陷时才做最小修正。

## Edge Cases

1. 两条会话拥有相同项目名但路径不同：显示两个项目分组。
2. 路径分别为 `/work/app` 与 `/work/app/`：标准化后显示一个分组。
3. 会话没有路径：进入“未知项目”，多个无路径会话位于同一未知分组。
4. 同步结果中同一会话 ID 重复出现：沿用当前去重，只保留一条记录。
5. 已手动启用的会话再次同步：仍保持启用。
6. 已手动关闭的会话再次同步：仍保持关闭。
7. 用户正在查看项目 A，项目 B 收到新会话并置顶：不得自动展开 B、不得抢键盘焦点、不得强制滚动到顶部。
8. 用户批量关闭包含当前 HUD 会话的项目：HUD 立即选择其他已启用会话；没有则显示占位。
9. 用户删除项目最后一个会话：该项目消失，其展开状态清理。
10. 同步失败：保留原列表和所有选择，只显示错误，不清空数据。
11. 项目名称或会话名称很长：单行尾部省略，鼠标悬停或辅助功能仍可获取完整值。
12. 会话当前未启用但收到红灯事件：设置页状态更新为“等待权限”，但 HUD 不抢占显示。

## Testing Decisions

- 测试公开排序、分组、选择和 HUD 输出，不断言 SwiftUI 私有视图层级。
- 为项目分组纯逻辑模块增加单元测试：同路径合并、同名异路径分开、未知路径分组、项目与会话排序、数量统计。
- 为导入逻辑增加测试：新同步会话默认关闭，重复同步保留已有选择，批量导入顺序稳定。
- 为 Hook 创建逻辑增加测试：新会话默认关闭，新会话在组内置顶，所属项目置顶，后续状态更新不反复重排。
- 为批量选择增加测试：全部启用、全部关闭、部分启用三态；一次操作后持久化结果正确。
- 复用 CarouselScheduler 测试，补充从零启用、批量关闭当前会话和全关闭回到占位的场景。
- 手动验证一百个以上会话时的展开、滚动、批量切换和设置窗口响应速度。
- 手动验证键盘导航、VoiceOver 标签、浅色与深色模式，以及项目置顶时不抢焦点、不自动展开。

最低自动测试用例必须包含以下输入与断言：

### 分组器

1. 输入 `/a/demo` 两条会话，输出一个项目、两条子项。
2. 输入 `/a/demo` 与 `/b/demo`，输出两个同名项目，ID 不同。
3. 输入 `/a/demo/` 与 `/a/demo`，输出一个项目。
4. 输入两个空路径，输出一个“未知项目”。
5. 新会话排序时间更晚时位于组内第一，项目也位于项目列表第一。
6. 时间完全相同时结果仍按规定后备键稳定排序。
7. 启用状态分别为全关、部分、全开时，统计与 selectionState 正确。

### 导入与 Hook

1. 空本地数据同步一个 thread，得到 `isIncludedInHUD == false`，排序时间等于 thread `updatedAt`。
2. 已存在且启用的会话重复同步，仍为启用，原排序时间不变。
3. 已存在且关闭的会话重复同步，仍为关闭。
4. Hook 首次发现会话，默认关闭，排序时间接近注入的当前时间。
5. 同一会话后续 Hook 状态更新，排序时间不变。

### 批量选择与 HUD

1. 项目三条会话全部关闭后执行全部启用，三条全部启用且只进行一次持久化语义更新。
2. 部分启用后执行全部关闭，三条全部关闭。
3. 批量关闭当前 HUD 所属项目后，切换到另一个项目的启用会话。
4. 关闭最后一个启用会话后，当前 HUD 会话为 nil 并显示占位。

### 持久化兼容

1. 不含 `settingsListSortAt` 的旧会话 JSON 仍可加载。
2. 新记录保存再读取后排序时间和关闭状态保持不变。
3. 项目展开键保存并重新创建 AppModel 后恢复；清空后集合为空。

## Acceptance Criteria

只有同时满足以下条件才算完成：

1. 同步任意数量的新历史会话后，所有新会话均未勾选，HUD 不自动轮播它们。
2. Hook 新发现会话未勾选，位于所属项目第一；所属项目位于项目列表第一。
3. 项目和会话置顶不会自动展开、滚动或抢焦点。
4. 设置页按标准化完整路径形成项目二级分组，同名异路径不合并。
5. 项目默认折叠，手动展开状态在重开设置窗口和重启 App 后保持。
6. 项目批量启用和关闭均有效，部分选中状态可辨识。
7. 单条勾选、单条删除、清空全部仍正常。
8. 重复同步保留用户已有选择，不重置开关。
9. 子会话标题不重复显示项目名，运行状态使用中文。
10. HUD 只轮播启用项，批量关闭当前项后立即切换；全关闭时显示占位。
11. 一百个以上会话的同步、展开和批量操作无明显界面卡顿。
12. 全部新增和既有自动测试通过，发布构建和本地端到端测试通过。

## Implementation Plan

编码模型必须按以下顺序实施，每步完成后先运行相关测试再继续：

1. 扩展持久化模型，加入可选排序字段和兼容测试。
2. 修改 App Server 导入器，使新会话默认关闭并正确赋排序时间；补导入测试。
3. 修改 Hook 新会话创建，使其默认关闭并赋当前排序时间；将当前时间设计为可测试输入或在纯逻辑层测试。
4. 实现纯逻辑项目分组器及全部分组、排序、统计测试。
5. 在 AppModel 增加项目分组输出、展开状态偏好和项目批量选择方法。
6. 重构设置页为项目披露列表，补齐中文状态、子项标题和辅助功能标签。
7. 补充 HUD 选择联动测试，并进行一百条以上数据的手动响应检查。
8. 运行完整单元测试、发布构建、本地 E2E 和差异检查。

## Out of Scope

- 迁移或自动修正开发测试阶段已有会话的启用状态。
- 会话搜索、过滤、分页和虚拟化。
- 项目自定义名称、拖动排序和固定置顶。
- 按 Git 仓库根目录重新推断项目；本版继续使用 Codex 会话的 `cwd`。
- 自动根据最近活跃状态启用会话。
- 删除整个项目对应的 Codex 数据或磁盘目录。
- 修改 HUD 的状态规则、尺寸、颜色或轮播优先级。

## Further Notes

- 项目批量选择是解决“逐项关闭一百多个会话”的核心能力，不能只做视觉分组。
- 默认关闭会让首次同步后 HUD 暂时显示占位，这是预期行为；设置页应在同步结果附近提示用户展开项目并选择需要参与 HUD 的会话。
- `ui-ux-pro-max` 的本地规则建议大量重复操作提供批量能力，并在 SwiftUI 设置界面继续使用原生 `Form` 和列表/分区控件。本方案据此采用渐进披露、批量选择和原生可访问控件。
