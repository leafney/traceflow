## 实施后缺陷修复补充

本节由实现后审查确认，属于本文既有规则的实现补全，不改变用户可见业务语义。

1. 调度器返回的 `animated` 必须传递到 HUD 标题容器：真实会话之间切换使用既有方向动画，占位与首个活跃会话之间切换不执行位移动画；系统“减少动态效果”始终只淡入淡出。
2. HUD 外层不能裁剪状态灯双层光晕。毛玻璃背景仍保持胶囊裁剪，标题区仍独立裁剪，只有光晕允许在 HUD 边缘视觉溢出。
3. 纵向原生标题更新时必须同步完整原标题到辅助功能标签；旋转 latin 片段必须根据真实 Core Text glyph bounds 围绕 40 点标题区中心对齐，不得保留未使用的宽度计算。
4. 本地端到端脚本必须覆盖真实 Hook 事件序列：运行、权限等待、完成、待机；并验证会话持久化、状态更新时间、完成事件和待机事件均被应用接收。HUD 精确当前项仍由调度器自动化测试覆盖。
5. 会话列表继续仅在项目展开后创建会话行；本轮不重构设置窗口为 List，以免改变既有表单交互。后续实测存在滚动性能问题时，再独立优化。

## 0. 覆盖规则与执行约束

本文覆盖历史规格中的以下冲突规则：

1. 已启用但待机的会话不再参与 HUD 轮播；旧的“所有会话待机时仍轮播”规则作废。
2. 完成状态自动转待机时限保持现有 10 分钟（600 秒）；本轮不延长到 30 分钟。
3. 三灯实体直径从 28 改为 27 点，灯间距从 4 改为 6 点。
4. 灯体不再固定尺寸：活跃灯的实体灯和双层光晕共同在 0.8～1.2 缩放；父布局占位必须固定，不能挤动其它灯。
5. “标准／强烈”不再改变最大缩放倍数，只改变双层光晕亮度和扩散半径。
6. 纵向标题不再将整行 SwiftUI Text 统一旋转；改为中英文混合竖排的原生矢量绘制。
7. 项目“批量操作”菜单由原生 Switch 替代。

实现者必须先完整阅读本文。不得只修改截图可见样式而遗漏轮播过滤、完成超时、立即切换、标题分词和测试。除上述明确覆盖项外，横纵 HUD 尺寸、位置记忆、红灯抢占、毛玻璃、减少动态效果、非激活窗口及现有 Hooks／会话数据逻辑保持不变。

## Problem Statement

当前 HUD 实测有三类问题：灯体偏大、明暗谷值仍很亮，红黄动效不醒目且三灯缩放语义不统一；待机会话仍参与轮播，用户会看到没有实际交互的历史会话；纵向标题将整行 SwiftUI 文字旋转后产生虚影，也不能让中文以正常朝向逐字排列；设置页项目级批量菜单操作成本高，不如直接使用 Switch。

## Solution

将轮播输入收紧为“已启用且当前活跃”的会话，完成状态保留 10 分钟后转待机并立即退出；重新定义三灯为共同 0.8～1.2 的状态呼吸，红黄灯真正降至待机暗度、绿灯恒亮；使用 AppKit/Core Text 建立纵向混合标题排版器，精确绘制旋转英文片段与正向汉字；将项目批量菜单替换为与会话行一致的原生 Switch。

## User Stories

1. 作为启用了多个会话的用户，我只想轮播当前真正有交互的会话，从而不被历史待机会话干扰。
2. 作为所有会话均待机的用户，我希望 HUD 显示统一占位，而不是继续切换待机标题。
3. 作为待机会话的用户，我希望启用选择继续保留，从而下次交互无需重新打开开关。
4. 作为收到新活动的用户，我希望已启用会话自动重新进入轮播。
5. 作为等待权限处理的用户，我希望红灯继续立即抢占黄灯或绿灯会话。
6. 作为同时有多个权限请求的用户，我希望多个红灯会话按进入顺序展示。
7. 作为当前会话结束的用户，我希望它立即退出轮播，不等待剩余展示时间。
8. 作为完成任务的用户，我希望绿灯保留 10 分钟，以便看见完成状态且不过久占用轮播。
9. 作为完成状态超过 10 分钟的用户，我希望它自动转待机并立即退出轮播。
10. 作为查看灯光的用户，我希望灯体略小且灯间距更大，从而三灯更清晰。
11. 作为查看红灯的用户，我希望它快速缩放并在谷值接近熄灭，从而体现紧急性。
12. 作为查看黄灯的用户，我希望它平滑呼吸并在谷值接近熄灭，从而明显看出运行节奏。
13. 作为查看绿灯的用户，我希望它亮度恒定但缓慢缩放，从而表示稳定完成。
14. 作为查看非当前灯的用户，我希望其它两盏保持暗色静止，从而一眼识别当前状态。
15. 作为开启减少动态效果的用户，我希望三灯固定 1.0 倍且不闪烁，同时仍能辨认状态。
16. 作为选择光晕档位的用户，我希望两档只改变光晕强弱，不改变灯体缩放节奏。
17. 作为查看英文标题的用户，我希望英文片段整体旋转 90°，保持单词可读性。
18. 作为查看中文标题的用户，我希望汉字保持正向并逐字向下排列，不需要侧头阅读中文。
19. 作为查看中英文混合标题的用户，我希望片段按原文顺序连贯排列。
20. 作为查看 `usb-hub` 或 `Codex-5.3` 的用户，我希望连接符和版本号保持原样。
21. 作为查看带中文标点标题的用户，我希望标点删除后不在汉字之间制造空洞。
22. 作为查看超长标题的用户，我希望底部出现正向 `…`，而不是文字溢出灯区。
23. 作为在纵向模式下阅读的用户，我希望文字边缘清晰，不出现旋转位图虚影。
24. 作为轮播用户，我希望混合标题仍按屏幕方向左进右出。
25. 作为项目管理用户，我希望一个 Switch 控制项目下全部会话。
26. 作为部分启用项目的用户，我希望看到准确的“已启用 X / Y”，并能一次全部启用。
27. 作为只调整单个会话的用户，我希望会话级 Switch 继续保留。
28. 作为辅助功能用户，我希望项目与会话 Switch 都有明确的项目／会话名称和参与 HUD 语义。

## Implementation Decisions

### 1. 活跃资格与轮播集合

定义两个互相独立的事实：

- `isIncludedInHUD`：用户持久选择的参与资格，只能由项目或会话 Switch 改变。
- `isActiveForHUD`：实时状态是否可展示，纯逻辑为 `state != idle`；即 attention、running、completed 为真，idle 为假。

轮播可用集合必须是两者交集。不能因为进入待机而把 `isIncludedInHUD` 改成 false，设置页“已启用 X / Y”和 Switch 也只读取持久选择。

调度器每次更新会话、接收状态事件、完成超时或用户改变参与选择后，必须清除不可用会话的红灯队列、普通事件队列和当前显示。具体行为：

1. 可用集合为空：当前会话设为空，返回占位决策；HUD 显示 `Traceflow` 和三盏 0.18 暗灯。
2. 当前会话仍可用：更新集合不强制切换。
3. 当前会话已变待机或被关闭：立即选择下一可用会话，不等待轮播时长；优先尚在排队的红灯，再选择普通事件队列，最后依轮播顺序选择。
4. 非当前已启用会话从待机进入 attention：继续立即抢占非红灯当前会话；多个红灯按原有队列顺序。
5. 非当前会话进入 running 或 completed：加入普通事件队列，按正常轮播展示。
6. 当前红灯转待机：立即选下一可用会话；若另一个红灯已排队，优先显示它。
7. `SessionStart`、`Interrupt`、`SessionEnd` 映射 idle；`UserPromptSubmit`、`PostToolUse` 映射 running；`PermissionRequest` 映射 attention；`Stop` 映射 completed，既有映射保持。
8. 所有已启用会话均待机时不轮播其标题。新的活跃事件到达后，应立即从占位切到该会话，不等下一轮 tick。

调度器必须依据“可用集合”而非“已启用集合”判断数量、选择下一项和计算是否需要动画。不得在界面层临时隐藏待机会话来伪装过滤，否则队列和当前 ID 会继续错误运行。

#### 1.1 调度器内部不变量

实现者必须在调度器内部维护以下不变量，任何公开方法返回前都必须成立：

- `eligibleIDs = includedIDs ∩ activeIDs`，其中 `activeIDs` 只包含 `attention`、`running`、`completed`。
- `currentSessionID` 要么为 nil，要么一定属于 `eligibleIDs`。
- 红灯队列只允许包含“可用、状态为 attention、不是当前会话”的 ID；普通事件队列只允许包含“可用、状态为 running 或 completed、不是当前会话”的 ID。
- 同一 ID 在同一队列最多出现一次，且不能同时存在于红灯队列和普通事件队列。
- 轮播顺序仍按现有 `rotationIndex` 升序；过滤待机只改变候选集合，不重写或重新编号 `rotationIndex`。
- 队列清理顺序固定为：先更新会话 ID／参与资格／状态，再计算 `eligibleIDs`，再剔除不可用或状态不匹配的排队项，最后校验当前会话并产生决策。

#### 1.2 唯一选择流程

所有“需要选一个当前会话”的路径必须复用同一个选择函数，不允许在多个方法中各写一套优先级。该函数接受“当前会话是否仍有效”和“切换原因”，按下列顺序只选择一次：

1. 从红灯队列头部取第一个仍可用的 attention 会话。
2. 若无红灯，取普通事件队列头部第一个仍可用的 running／completed 会话。
3. 若队列均为空，从 `rotationOrder` 选择当前项之后的下一个可用会话；没有有效当前项时选择第一个可用会话。
4. 若可用集合为空，选择 nil，并返回 placeholder。

选择成功后必须立即：从两个队列移除所选 ID、写入 `currentSessionID`、把 `displayedSince` 设为本次调用的 `now`。选择 nil 时也要把 `displayedSince` 设为 `now`，防止恢复后沿用旧计时。

以下伪代码是业务约束，不要求逐字照抄名称：

```text
reconcile(now, invalidCurrentReason):
  pruneQueuesUsingEligibleState()
  if eligibleIDs.isEmpty:
    if currentSessionID == nil and alreadyShowingPlaceholder: return nil
    setCurrent(nil, now)
    return decision(nil, placeholder, animated: false)

  if currentSessionID is in eligibleIDs:
    return nil

  next = dequeueValidRed()
      ?? dequeueValidEvent()
      ?? firstEligibleInRotation()
  setCurrent(next, now)
  return decision(next, invalidCurrentReason,
                  animated: previousCurrent != nil && previousCurrent != next)
```

从占位恢复到首个活跃会话不需要等待 tick，决策的 `animated` 固定为 false；当前真实会话切到另一个真实会话才使用现有标题过渡动画。重复同步同一个空集合不能持续产生 placeholder 决策或重启动画。

#### 1.3 状态事件的精确处理顺序

单个 Hook 事件只能让应用模型消费一次最终切换决策。现有“先同步会话、再报告状态”结构可以保留，但顺序必须固定：

1. 状态机接受事件并产出新快照。
2. 发布最新会话数组。
3. 调用会话同步；该调用仅同步成员关系，对已经存在的 ID 不提前覆盖调度器旧状态。
4. 调用状态变更报告，让调度器看到明确的旧状态到新状态转换。
5. 只执行一次 `finalDecision = stateDecision ?? membershipDecision`，然后只调用一次 HUD 显示更新。
6. 若两个决策都为空但当前显示的就是本次标题发生变化的会话，则只刷新标题，不重置 `displayedSince`。

状态变更报告按以下决策表执行：

| 新状态 | 当前关系 | 必须执行的动作 |
| --- | --- | --- |
| idle | 是当前会话 | 从两队列删除，立即运行唯一选择流程 |
| idle | 不是当前会话 | 从两队列删除，不切换当前会话 |
| attention | 当前不是 attention 会话或当前为空 | 从普通队列删除；立即抢占并重置展示计时；原当前会话仍可在后续正常轮播出现 |
| attention | 当前已经是另一个 attention 会话 | 追加到红灯队尾，不立即切换 |
| attention | 本身就是当前会话 | 从两队列删除；仅在确实发生状态变化时重置展示计时，不产生重复决策 |
| running/completed | 当前为空 | 立即显示该会话，不等待 tick |
| running/completed | 本身就是当前会话 | 从两队列删除，保持显示，不重置展示计时 |
| running/completed | 当前为 attention | 从红队列删除后加入普通事件队列，不得抢占红灯 |
| running/completed | 当前为 running/completed | 从红队列删除后加入普通事件队列，等待正常轮播 |

`stateChanged == false` 时仍可更新内部状态镜像，但不得重复排队、重置计时或产生切换决策。未参与 HUD 的会话发生状态变化时只更新状态镜像，不能进入任何队列。

#### 1.4 tick、选择变更与批量超时

- tick 仅在至少两个可用会话且当前展示时长已达到设置值时轮播；只有一个可用会话时保持它，不生成指向自身的动画决策。
- 正常 tick 仍按“红灯队列 → 普通事件队列 → 轮播顺序”选择。取出的 ID 若在等待期间失效，跳过并继续寻找，不能先显示再隐藏。
- 单会话或项目 Switch 关闭后，先发布最新持久选择，再同步调度器，并立即消费同步返回的决策。
- Switch 开启的是待机会话时，可用集合仍为空，不得从占位切换；它以后收到活跃事件时才进入显示。
- 一次定时检查可能让多个 completed 会话同时超时。应用模型应先让所有状态机完成过期处理，再发布一次最终会话数组，再让调度器统一同步和选择，并消费一次最终决策；不得在循环中丢弃每个状态报告返回的切换决策。

### 2. 完成状态 10 分钟超时

完成超时默认参数固定为 600 秒。计时基于本次进入 completed 时记录的 `completedAt`：

- 10 分钟内保持 completed 和绿灯活跃。
- 任意后续有效事件进入其它状态时清空 `completedAt`，旧倒计时作废。
- 满 600 秒的首次定时检查将其转为 idle、清空完成时间、更新持久化更新时间，并向调度器报告真实状态变化。
- 若它正在显示，调度器必须立即返回下一会话或占位决策；应用模型必须消费该决策，而不是只刷新会话列表。
- MVP 重启恢复逻辑不改变：运行状态不持久化，重启后会话为 idle，不跨重启恢复剩余绿灯时间。
- 边界采用“大于或等于”：`now - completedAt >= 600` 即超时；负时间差或不足 600 秒均不超时。
- `Stop` 再次到达时即使枚举状态仍为 completed，也必须用本次事件时间更新 `completedAt`，新一轮 600 秒从本次 Stop 开始；调度器不因枚举值未变化而重复排队或重启动画。
- 超时检查继续由现有应用 tick 驱动，不新增长驻线程或第二套计时器。

### 3. 灯光尺寸、相位和强度

实体灯直径固定布局基准为 27 点，灯间距 6 点；三灯基准占用 `27 × 3 + 6 × 2 = 93` 点。现有灯区 104 点保留，沿长轴两端各约 5.5 点。若实机证明双层光晕严重被相邻标题区裁切，允许将灯区等量向标题区扩展，但必须保持 HUD 总长 420 点并同步更新共享布局常量与测试。

每盏 `StatusLight` 的父布局占位始终为 27 × 27，只有对应当前状态的灯将“实体灯＋内层光晕＋外层光晕”作为整体缩放。其它两灯固定 1.0 倍、亮度 0.18、光晕透明度 0。

三种周期均须经过 0.8、1.0、1.2、1.0、0.8，可使用连续函数产生等价轨迹，但一个完整周期必须从谷值回到谷值：

| 状态 | 周期 | 实体灯亮度 | 光晕强度 |
| --- | ---: | --- | --- |
| attention 红灯 | 0.56 秒 | 与快速相位同步在 0.18～1.0 之间变化，保留急促亮起／熄灭停顿 | 谷值 0，峰值使用档位参数 |
| running 黄灯 | 2.30 秒 | 平滑正弦或等价缓入缓出，在 0.18～1.0 之间变化 | 与亮度同步从 0 到档位峰值 |
| completed 绿灯 | 2.80 秒 | 始终 1.0，不随相位闪烁 | 始终有档位基础强度，并随缩放自然扩散 |

缩放公式统一为 `0.8 + 0.4 × phase`，phase 为 0...1...0 的完整往返波形。标准／强烈继续沿用现有各自内外层模糊半径和透明度，只能影响光晕，不得影响缩放值。红黄谷值的光晕必须为零；绿灯光晕不得因 phase 为零而消失。

系统减少动态效果开启时：活跃实体灯固定 1.0 倍；红黄绿亮度都固定 1.0；显示对应档位的静态双层光晕；不运行灯光时间线和标题位移动画。待机／非当前灯仍为 0.18 且无光晕。

#### 3.1 必须使用的相位函数

为避免实现者把“缩放”和“明暗”写成不同步的多套动画，灯光只允许从一个标准化 `phase` 推导。设：

```text
progress = positiveRemainder(referenceTime, period) / period  // 0..<1
scale = 0.8 + 0.4 * phase                                   // 0.8...1.2
```

`positiveRemainder` 必须保证系统参考时间为负数时仍返回 0..<period。正常运行可继续使用绝对参考时间生成稳定相位，不需要为每个灯保存动画状态。

红灯周期 0.56 秒，使用明确的急促分段波形：

```text
0.00 <= progress < 0.15: phase = progress / 0.15
0.15 <= progress < 0.55: phase = 1
0.55 <= progress < 0.70: phase = 1 - (progress - 0.55) / 0.15
0.70 <= progress < 1.00: phase = 0
```

这表示快速放大、短时间保持警示、快速缩小、短时间完全暗下。黄灯与绿灯使用平滑往返波形：

```text
phase = (1 - cos(2 * π * progress)) / 2
```

因此一个完整周期都从 0.8 开始，经过 1.0、1.2、1.0，最后回到 0.8。不得继续沿用旧的 `1.0...maximumScale` 算法，也不得让“强烈”档把最大缩放改成 1.3。

#### 3.2 实体亮度和光晕系数

从同一个 phase 计算三个相互独立的输出：

| 状态 | 实体亮度 | 光晕系数 | 整体缩放 |
| --- | --- | --- | --- |
| attention | `0.18 + 0.82 × phase` | `phase` | `0.8 + 0.4 × phase` |
| running | `0.18 + 0.82 × phase` | `phase` | `0.8 + 0.4 × phase` |
| completed | `1.0` | `1.0` | `0.8 + 0.4 × phase` |
| 非当前灯／占位灯 | `0.18` | `0` | `1.0` |

光晕最终透明度为“档位峰值透明度 × 光晕系数”。标准档继续使用现有内层 `0.50`、外层 `0.28`；强烈档继续使用现有内层 `0.70`、外层 `0.45`。标准档模糊半径继续为内层 6、外层 12；强烈档继续为内层 9、外层 18。现有内外光晕基准直径 34／40 点保持，实体和两层光晕放在同一个缩放容器中，只应用一次 scale，不能分别缩放造成相位偏差。

父级布局槽位始终为 27 × 27，三个槽位间距始终为 6；光晕允许视觉溢出槽位，但不能改变 HStack／VStack 的测量尺寸。灯区和 HUD 最外层不得使用会裁掉光晕的额外裁剪；标题区仍单独裁剪，避免移动标题覆盖灯区。

减少动态效果开启时不要创建运行中的 Timeline：phase 视为 0.5、scale 强制 1.0；活跃灯实体亮度强制 1.0、光晕系数强制 1.0。关闭减少动态效果后可从当前绝对时间相位继续，不要求衔接旧帧。

### 4. 纵向标题解析模型

新增可独立测试的纯逻辑标题排版模型，将原始标题解析成有序片段，至少支持：

- `latin(text)`：英文字符、数字、英文内部空格以及被允许的连接符组成，绘制时整体顺时针旋转 90°。
- `han(character)` 或连续汉字集合：每个汉字保持正向，沿纵向逐字向下绘制。
- `gap`：英文片段之间或中英文方向切换时的小间距；连续 gap 合并，首尾 gap 删除。

字符分类与规范化必须确定性执行：

1. Unicode 汉字归入正向中文；不能只用 ASCII 范围判断所有非英文字符。
2. ASCII／全角普通标点默认作为分隔符。若标点夹在连续中文之间，直接删除且不生成 gap，例如 `小米，遥控器。设置` 等价于 `小米遥控器设置`。
3. `/`、`\`、`:` 作为分隔符。
4. `_`、`-` 仅在与英文或数字相邻并属于英文片段时保留；例如 `usb-hub` 保留，纯中文 `项目-设置` 中的 `-` 不绘制。
5. `.` 仅在英文／数字片段内部、且两侧属于英文或数字时保留，例如 `v2.0`、`Codex-5.3`、`example.com`；句末点删除或作为英文片段边界。
6. 连续英文、数字及内部空格组成一个 latin 片段，例如 `hello world`、`usb-hub v2.0` 不按单词再拆。
7. 中英文交界产生一个小 gap。普通标点分隔两个英文数字片段时产生一个 gap。中文之间删除标点后不产生 gap。
8. 连续空白折叠；最终首尾不保留 gap。

推荐解析示例：

| 输入 | 语义结果 |
| --- | --- |
| `hello world 小米遥控器` | 旋转 `hello world` → gap → 正向“小”“米”“遥”“控”“器” |
| `usb-hub_Codex-5.3` | 一个旋转英文数字连接片段，原连接符保留 |
| `小米，遥控器。设置` | 连续正向“小米遥控器设置”，中文内部无标点间隙 |
| `项目-设置` | 连续正向“项目设置”，中划线不显示且无额外空洞 |
| `foo/bar:baz` | 旋转 `foo` → gap → 旋转 `bar` → gap → 旋转 `baz` |

#### 4.1 对外数据类型

解析和截断必须放在可独立测试的纯逻辑模块中，不依赖 SwiftUI、NSView 或全局设置。对外结果至少表达以下三种语义；实际 Swift 命名可以遵循项目风格，但不得把所有内容降级成一个加工后的 String：

```text
VerticalTitleSegment:
  latin(String)    // 整段旋转 90°
  han(Character)   // 单个扩展字素保持正向
  gap              // 固定 4 点视觉间距

VerticalTitleLayout:
  visibleSegments
  showsEllipsis
```

遍历单位必须是 Swift `Character`（Unicode 扩展字素），不得按 UTF-8 字节或 UTF-16 下标遍历。这样组合音标、变体选择符和 Emoji 不会被截成无效字符。

#### 4.2 字符分类

每个 Character 先按以下顺序分类，前面的规则优先：

1. **汉字**：Character 中的基础 Unicode scalar 落在 CJK Unified Ideographs 及其扩展区、CJK Compatibility Ideographs 时归为 han；变体选择符跟随基础汉字，不单独生成片段。实现至少覆盖 `3400...4DBF`、`4E00...9FFF`、`F900...FAFF`、`20000...2FA1F`、`30000...3134F`。
2. **英文数字主体**：Unicode 字母或十进制数字且不是上述汉字时，归入 latin。这样带重音的拉丁字母不会被删除；其它非汉文字母采用与英文相同的旋转回退行为。
3. **可保留连接符**：ASCII `_`、`-` 只有在它紧邻的前后 Character 都是“英文数字主体”时才归入 latin；否则作为普通分隔符。例如 `usb-hub`、`a_b` 保留，`项目-设置`、`foo-中文` 不保留连接符。
4. **可保留句点**：ASCII `.` 只有在紧邻的前后 Character 都是“英文数字主体”时才归入 latin；例如 `v2.0`、`example.com` 保留，`.foo`、`foo.` 的首尾点不保留。
5. **空白**：连续空白先折叠。只有当空白左右最近的非空白字符最终都属于 latin 内容、且中间没有其它分隔符时，向同一个 latin 片段写入一个 ASCII 空格；其它空白转换为 gap 候选。
6. **强制分隔符**：`/`、`\`、`:` 永不绘制，结束当前 latin 片段并产生 gap 候选。
7. **普通标点、Emoji 和其它符号**：不绘制。若跳过连续这类字符后，左右最近的可绘制字符都是 han，则不产生 gap；其它情况下产生 gap 候选。Emoji 按分隔符处理，不作为标题图形绘制。

“紧邻”特指原始 Character 数组中的直接前后项，不跨越空白或其它标点。因此 `a - b` 中的 `-` 不保留，解析结果为旋转 `a`、gap、旋转 `b`。

#### 4.3 合并和规范化算法

解析按以下固定过程执行：

1. 对原始 Character 数组进行分类和上下文判断。
2. 连续 latin 字符和允许的内部空格合并为一个 `latin(String)`。
3. 每个汉字单独输出一个 `han(Character)`；相邻汉字之间不自动插入 gap。
4. latin 与 han 直接相邻时插入一个 gap；两个被强制分隔的 latin 片段之间插入一个 gap。
5. 连续多个 gap 候选合并成一个；删除结果首尾 gap。
6. 删除空的 latin 片段。解析结果为空时，绘制层使用原始占位标题 `Traceflow` 的 latin 结果，避免 HUD 出现无标题状态。

以下用例是强制预期输出，不只是示意：

| 输入 | 精确片段序列 |
| --- | --- |
| `中文` | `han(中), han(文)` |
| `hello world` | `latin("hello world")` |
| `hello world 小米` | `latin("hello world"), gap, han(小), han(米)` |
| `usb-hub_Codex-5.3` | `latin("usb-hub_Codex-5.3")` |
| `小米，遥控器。设置` | `han(小), han(米), han(遥), han(控), han(器), han(设), han(置)` |
| `项目-设置` | `han(项), han(目), han(设), han(置)` |
| `foo/bar:baz` | `latin("foo"), gap, latin("bar"), gap, latin("baz")` |
| `a - b` | `latin("a"), gap, latin("b")` |
| `中文🙂标题` | `han(中), han(文), han(标), han(题)` |
| `foo🙂bar` | `latin("foo"), gap, latin("bar")` |
| `...中文。` | `han(中), han(文)` |

### 5. AppKit/Core Text 混合竖排视图

纵向标题必须使用 `NSViewRepresentable` 包装原生 `NSView`，由 Core Text／Core Graphics 在 `draw(_:)` 中绘制，不得再对整个 SwiftUI Text 使用 `rotationEffect`。横向标题继续使用 SwiftUI Text 和原始完整标题。

原生绘制视图要求：

1. 使用与横向标题一致的 13 点圆体、中等字重和当前系统前景色；不得增加阴影。
2. 获取窗口 backing scale，并将绘制基线、片段边界对齐到设备像素，避免半像素和离屏位图重采样造成虚影。
3. latin 片段在绘图上下文中使用矢量坐标变换顺时针旋转 90°后直接绘制；中文逐字以正常方向绘制。不能先把文字渲染成图片再旋转。
4. 片段按标题区顶部到底部的逻辑顺序排列；起点保持当前距图标约 6 点的内边距。
5. 先测量所有片段所需纵向长度。若超过可用长度，必须为底部正向 `…` 预留空间；允许在 latin 片段内部按 Unicode 字符边界缩短，禁止切断 UTF-8 字节或组合字符；中文按完整字符截断。
6. `…` 始终保持正向，位于标题可用区底部；不缩小字体、不拆分第二列。
7. 提供与原标题一致的辅助功能标签，不能让屏幕阅读器逐字、按旋转片段读出。
8. 整个原生标题视图保持在现有 40 × 275 标题裁剪区内。会话变更时，由外层 SwiftUI 容器将完整视图按屏幕方向左进右出；减少动态效果时仅淡入淡出。
9. AppKit 视图更新必须比较标题内容和外观，仅在必要时重新布局／重绘；灯光 30fps 时间线不能导致标题每帧重绘。

#### 5.1 固定几何和字体

- 纵向标题容器固定为宽 40、高 275 点；内部顶部和底部各保留 6 点，因此沿纵轴可用长度恰好为 263 点。不得把 40 和 275 互换，也不得把整个 HUD 的 420 点误当标题长度。
- 内容水平中心固定在容器 x = 20。每个正向汉字、旋转 latin 片段和省略号都依据自身实际 glyph bounds 围绕该中心放置，不能简单写死左边距导致不同字符偏向一侧。
- 字体优先通过系统字体描述符的 rounded design 取得 13 点 medium 字重；若 rounded design 返回 nil，则回退 13 点系统 medium 字体。解析与测量必须共用同一个最终字体对象。
- gap 的纵向 advance 固定为 4 点。汉字 advance 使用 `ceilToPixel(font.ascender - font.descender + font.leading)`；不得直接假设每个汉字恰好 13 点。
- latin advance 使用 Core Text 单行 `CTLineGetTypographicBounds` 得到的宽度，因为片段旋转后原横向宽度就是纵向占用长度。不得使用字符数乘字号估算。

像素对齐统一使用以下规则，其中 scale 来自当前 window 的 backingScaleFactor，window 尚未连接时临时回退 2.0，并在 `viewDidMoveToWindow` 后重新布局：

```text
align(value) = round(value * scale) / scale
ceilToPixel(value) = ceil(value * scale) / scale
```

起点、中心线、baseline、advance 和裁剪边界均使用同一 scale 对齐，不能只对外框取整。

#### 5.2 截断算法

先用上述真实 advance 测量完整片段序列。总长度不超过 263 点时完整显示且 `showsEllipsis = false`。超出时严格执行：

1. 测量正向 `…` 的行高，将其作为 `ellipsisAdvance`；可用正文预算为 `263 - ellipsisAdvance`。
2. 从头累加片段。完整片段能放下则保留；gap 只有在其前后最终都有可见内容时才保留。
3. han 放不下时直接停止，不能画半个字。
4. latin 放不下时，以 Character 边界二分查找能放入剩余预算的最长前缀；删除该前缀末尾的空格以及悬空的 `_`、`-`、`.` 后再次测量。前缀非空才加入。
5. 删除正文结尾 gap，然后在可用区底部绘制一个保持正向的 `…`。省略号不是 latin 片段，不随前面的英文旋转。
6. 不缩小字体、不压缩字距、不增加第二列，也不从标题中间截取。

解析器负责语义片段，测量器负责依据字体和可用长度产生截断布局；不要把 Core Text 尺寸依赖塞进字符解析器。测量结果的缓存键至少包含原标题、字体描述、字号、backing scale 和可用长度。

#### 5.3 矢量绘制和坐标系

- 原生 NSView 覆盖 `isFlipped = true`，布局坐标统一为左上原点、y 向下；不要在绘制开头再做第二次全局 y 轴翻转。
- 绘制 latin 片段时保存 CGContext 状态，平移到该片段锚点，在 flipped 坐标下旋转 `+π/2`，直接绘制 Core Text 行，然后恢复状态；正值必须在屏幕视觉上表现为顺时针 90°。若底层 API 的文本矩阵另有默认翻转，只修正文本矩阵，不能改变业务要求的视觉方向。
- han 和 `…` 不旋转，逐项按纵向 cursor 绘制；每绘制一项后按其 advance 推进 cursor。
- 颜色从 SwiftUI 环境传入当前主文字色；外观由浅色切到深色时必须触发重绘，但无需重新解析字符。
- 只缓存片段和 Core Text 测量结果，不生成、缓存或旋转 NSImage／CGImage 位图。
- NSView 的 `draw(_:)` 只负责当前标题；SwiftUI 外层继续用会话 ID（占位使用固定 ID）标识整个标题视图，并在 40 × 275 裁剪容器中执行屏幕坐标的 leading 插入、trailing 移除，也就是用户看到的左进右出。
- SwiftUI 更新桥接层只在标题、颜色、字体、scale 或 bounds 改变时调用 `needsDisplay = true`。灯光 Timeline 刷新不得修改标题桥接参数。

### 6. 项目与会话 Switch

设置页项目头部移除“批量操作”菜单，在“已启用 X / Y”右侧放置原生 Switch 样式 Toggle。会话行现有 Toggle 也显式使用相同 Switch 样式。

项目 Switch 绑定规则：

- `.all` 显示开；`.none` 与 `.partial` 显示关。
- 用户将关切到开：调用现有项目批量设置逻辑，将全部会话 `isIncludedInHUD` 设为 true。
- 用户将开切到关：将全部设为 false。
- `.partial` 点击后的第一步必须全部开启，不能全部关闭。
- “已启用 X / Y”继续显示，计数只依据持久参与选择，不依据实时 active 状态。
- 存储不可写时项目和会话 Switch 都禁用，沿用现有规则。
- 项目 Switch 隐藏视觉标签但设置辅助功能标签“项目〈名称〉全部参与 HUD”；会话 Switch 继续使用“〈标题〉参与 HUD”。

Switch 只改变参与资格，不直接改变会话运行状态。关闭当前项目／会话后，调度器应立即切换到下一可用会话或占位。

项目 Toggle 的 Binding 必须采用以下等价语义，避免 `.partial` 被错误地当成 true：

```text
get: project.selectionState == .all
set(newValue): setProjectIncluded(newValue, projectKey: project.id)
```

因此 `.partial` 的 getter 为 false，用户第一次点击时 SwiftUI 传入 true，结果是全部启用。不得用 `selectionState != .none`，也不得在 setter 内对旧值自行取反。项目与会话 Toggle 都显式指定原生 `.switch` 样式并隐藏视觉标签；项目头部排列顺序固定为“展开按钮 → 项目信息 → 弹性空白 → 已启用 X / Y → Switch”。删除原菜单及“全部启用／全部关闭”按钮，不保留两个并行入口。

批量更新必须作为一次用户动作处理：修改该项目全部状态机后只发布一次会话列表、只保存一次 sessions 数据、只同步一次调度器。不能在 for 循环内逐项刷新 HUD 或逐项写磁盘，否则百条会话会产生闪烁和大量写入。

### 7. 实施阶段

#### 7.0 现有模块职责与修改边界

实现者应沿用现有模块边界，不要新建第二套会话源或 UI 状态：

| 现有模块／类型 | 本轮职责 | 禁止事项 |
| --- | --- | --- |
| `SessionStateMachine` | 保持 Hook 到状态的映射；完成时间写入、清空和 600 秒过期 | 不读取 HUD 设置，不决定轮播对象 |
| `CarouselScheduler` | 维护状态镜像、eligible 集合、红灯／普通队列、当前 ID 与切换决策 | 不直接访问磁盘或 SwiftUI，不修改 isIncludedInHUD |
| `AppModel` | 串联状态机、调度器、持久化和 displayedSession；保证每次动作只消费一个决策 | 不在 View 内复制调度规则，不丢弃超时决策 |

## Testing Decisions

测试只断言公开行为：给定快照／事件／时间，断言决策、当前 ID、片段和视觉参数。不测试私有数组的存储方式、循环次数或具体 Core Text API 调用次数。现有核心模块使用 XCTest，因此新增纯业务测试继续放入同一测试目标，不为本轮引入第三方测试框架。应用可执行目标当前没有单独测试目标；难以从核心测试访问的 AppKit 绘制由纯解析／测量模型测试加人工验收覆盖，不为截图而暴露私有 UI。

### 业务逻辑自动化测试

1. `a=idle included`、`b=running included`：首次同步选择 b；5 秒后 advance 返回 nil，不能切到 a。
2. `a=idle included`、`b=idle included`：首次同步返回 placeholder；重复同步相同数组返回 nil，current 保持 nil。
3. 从上述占位状态把 a 报告为 running：同一次报告立即返回 a，原因是 initial，animated 为 false，无需 advance。
4. 当前 a=running、b=completed：a 报告 idle 时同一次调用返回 b，displayedSince 等于事件 now。
5. 当前 a=running 且其它均 idle：a 报告 idle 时返回 placeholder；三灯输入随 displayedSession nil 变为全暗。
6. 当前 a=running、b=attention：b 立即返回 redPreemption；随后 c=attention 只排队；达到展示时长后选择 c；b 在期间 idle 不应破坏 c。
7. 当前 a=attention：b 进入 running 或 completed 均不抢占；a idle 后优先取另一排队 attention，再取普通事件队列。
8. 同一 b 连续报告相同 running 且 `stateChanged=false`：只出现一次队列资格，不重置 current 的 displayedSince。
9. 已排队会话被关闭 Switch 或转 idle：下一次选择跳过它，不出现一帧无效标题。
10. 只有一个 eligible 会话 a：任意多个 displayDuration 后 advance 始终 nil，不生成 a → a 动画。
11. 当前会话关闭：若有其它 eligible，立即选择下一项；若只有已启用 idle，会立即 placeholder；重新开启 idle 仍保持 placeholder。
12. 状态机完成边界：`completedAt + 599.999` 返回 false，`completedAt + 600` 返回 true 并转 idle、清空 completedAt。
13. completed 后 300 秒再次收到 Stop：completedAt 更新到第二次 Stop；距第二次 599 秒不超时，600 秒超时，即使两次枚举状态相同。
14. 同一 tick 有两个 completed 同时超时：最终发布数组中二者均 idle，调度器只向 HUD 交付一个最终决策，不能留下已超时 current。
15. 项目状态 `.none/.partial/.all` 的 getter 精确为 false／false／true；对 partial Binding 写入 true 后，该项目每个会话都 included，写磁盘和发布动作各一次。

如需验证“只发布／保存一次”，应通过应用模型可注入的存储／发布边界做行为计数，不要依赖日志文本。

### 灯光纯函数自动化测试

1. 红灯 progress 为 `0、0.075、0.15、0.55、0.625、0.70、0.99` 时，phase 依次约为 `0、0.5、1、1、0.5、0、0`。
2. 黄／绿 progress 为 `0、0.25、0.5、0.75、1` 时，phase 依次约为 `0、0.5、1、0.5、0`；浮点断言使用小容差。
3. phase 为 `0、0.5、1` 时 scale 精确为 `0.8、1.0、1.2`，且标准／强烈结果相同。
4. 红黄 phase 为 `0、1` 时实体亮度分别为 `0.18、1.0`，光晕系数为 `0、1`。
5. 绿灯任意 phase 的实体亮度和光晕系数都为 1.0，仅 scale 变化。
6. 非活动灯参数固定为亮度 0.18、光晕 0、scale 1.0；减少动态效果下活动灯固定为亮度 1、光晕 1、scale 1，Timeline 标记为暂停。

### 标题解析自动化测试

解析测试必须逐项断言 4.3 表格的精确片段序列，并额外覆盖：`usb_hub v2.0` 为一个 latin、`example.com` 为一个 latin、`foo.` 为 latin("foo")、`a - b` 为两个 latin 加一个 gap、连续标点／空白只产生一个 gap、标题首尾不含 gap、组合字符不被拆分。

截断测试不得依赖某台机器字体的魔法字符串宽度；向测量器注入确定的 fake advance：han=10、gap=4、ellipsis=10、每个 latin Character=5。在可用长度 30 时至少断言：

- `中文` 总长 20，完整显示且无省略号。
- `中文标题` 需要截断，正文预算 20，结果保留“中文”并显示正向省略号。
- `abcdef` 长度 30，完整显示且无省略号。
- `abcdefg` 长度 35，正文预算 20，保留 latin("abcd") 后显示正向省略号。
- `abc-defgh` 在 latin 内部截断后不得以悬空 `-` 结尾；中英交界截断不得以 gap 结尾。

测试应断言对外片段序列、截断结果及是否需要 `…`，不测试私有循环或 Core Text 调用次数。Core Text 视图采用确定尺寸验证测量结果，不增加脆弱的全像素截图基线。

### 人工视觉与交互验收

1. 横纵两种灯体直径约 27 点、间距 6 点，缩放不会挤动相邻灯或标题。
2. 红灯 0.56 秒快速缩放并能降至无光晕暗态；黄灯 2.30 秒平滑变化并能明显熄暗；绿灯常亮且 2.80 秒缩放。
3. 标准／强烈两档缩放范围相同，强烈档只在光晕上更明显。
4. 减少动态效果后没有灯体缩放或亮暗闪烁。
5. 纵向纯英文、纯中文和混合标题边缘清晰，无重影；中英文方向和间距符合示例。
6. 长标题底部显示正向 `…`，不覆盖灯区；纵向标题切换仍为屏幕方向左进右出。
7. 项目 Switch 和会话 Switch 外观一致；partial 显示关闭，点击后全部启用；计数同步更新。
8. 当前会话进入待机、关闭 Switch 或完成超时后，HUD 立即切换；所有活跃会话消失时显示占位。
9. HUD 仍不抢键盘焦点，横纵位置和毛玻璃无回归。
