## 0. 编码模型执行约束

本文将交给低智能编码模型执行。实现者必须把下列规则视为强制要求，而不是设计建议：

1. 先完整阅读本文，再按“阶段一 → 阶段二 → 阶段三”顺序实施。不得只完成最容易看到的设置项，也不得只调整几个尺寸后宣称完成。
2. 本文中的“横向／纵向”表示两套真实布局。**禁止**把整个横向 HUD 旋转 90° 来伪造纵向模式；否则图标、圆灯、动画方向和拖动坐标都会错误。
3. 本文中的“光晕扩散”只改变灯体背后的光晕层。**禁止**缩放 28 点实体圆灯，禁止通过改变布局宽高实现动画。
4. “纵向标题左进右出”以用户屏幕坐标为准：左边是显示器左边，右边是显示器右边。文字旋转不改变这个方向。
5. 保持现有菜单栏应用、无 Dock 图标、HUD 不成为主窗口或键盘窗口、可拖动、点击 HUD 无业务动作、多空间可见等行为。不能为了方便重建为普通可激活窗口。
6. 所有 UserDefaults 迁移必须幂等：应用启动一次或一百次，结果相同；新设置保存后，旧键不能在下次启动把它覆盖回去。
7. 每阶段必须完成该阶段所有验收项，再进入下一阶段。若实现与本文发生冲突，先更新本文并获得用户批准，不能自行改变需求。

### 0.1 名词与状态对照

| 本文名词 | 精确定义 |
| --- | --- |
| 长轴 | 横向模式中的水平方向；纵向模式中的垂直方向，长度均为 420 点 |
| 短轴 | 横向模式中的垂直方向；纵向模式中的水平方向，长度均为 40 点 |
| 灯体 | 固定直径 28 点的红／黄／绿实体圆，不参与缩放 |
| 内层光晕 | 紧贴灯体、颜色较浓、扩散较小的模糊层 |
| 外层光晕 | 颜色较淡、扩散较大、负责“向外溢出”观感的模糊层 |
| 标准 | 默认光晕档；有持续扩散，但视觉较克制 |
| 强烈 | 更大的扩散比例、更宽的模糊半径和更高透明度 |
| 减少动态效果 | macOS 辅助功能环境值为真；此时不得运行位置或透明度的周期动画 |
| 左进右出 | 新标题从屏幕左侧越过标题视区左边界进入；旧标题穿过标题视区右边界退出 |

### 0.2 不得回归的现有功能

- 标题来源、标题模式、轮播间隔、会话筛选和红黄绿业务状态含义不变。
- 没有参与 HUD 的会话仍不显示；所有参与 HUD 的会话即使都待机仍继续轮播。
- 无会话时继续显示当前占位标题 `Traceflow`，三盏灯均为未点亮状态。
- 浅色／深色系统外观继续自动适配，不新增主题选择。
- HUD 显示／隐藏开关继续有效；隐藏时修改布局，重新显示必须直接采用新布局。

## Problem Statement

现有 HUD 灯体过小、内边距偏宽，即使光晕设为最高仍难以看清绿灯的光感；只有横向布局，不适合希望将状态条贴在显示器右侧的用户。三级光晕设置难以取舍，现有光晕和灯体缩放逻辑也无法实现用户示意图所示的持续扩散效果。

## Solution

在保持横向 HUD 整体 420 × 40 点及原有毛玻璃质感的基础上，将灯体增至 28 点、紧凑化间距并绘制双层光晕；光晕设置改为“标准／强烈”两档，红／黄／绿灯各按自身状态节奏持续扩散。增加可选的 40 × 420 点纵向 HUD，按图标、顺时针旋转 90° 的标题、红黄绿灯由上至下排列；纵向标题换会话时，整体在屏幕坐标上左进右出。两种布局各自记忆拖动位置。

## User Stories

1. 作为查看 HUD 的用户，我希望在设置里选横向或纵向，以匹配顶部或侧边工作区。
2. 作为新用户，我希望默认仍是横向，并在主屏幕顶部居中看到 HUD。
3. 作为首次选纵向的用户，我希望 HUD 出现在主屏幕右边缘垂直居中，且完整可见。
4. 作为经常切换布局的用户，我希望横纵布局各自记住拖动位置，不需要每次重新摆放。
5. 作为多显示器用户，我希望布局切换和显示器变化后仍能找到完整 HUD。
6. 作为重置位置的用户，我希望只恢复当前布局的默认位置，不改变另一个布局。
7. 作为查看纵向 HUD 的用户，我希望正向图标在顶部、顺时针旋转的整行标题在中间、圆形红黄绿灯在底部。
8. 作为查看长标题的用户，我希望纵向文字不拆开词组，超过标题范围时仅在末尾省略。
9. 作为查看会话切换的用户，我希望纵向标题沿屏幕水平方向从左进、向右出，不沿竖向滑动。
10. 作为切换布局的用户，我希望毛玻璃、淡灰色底调和弱分隔线在横向和纵向保持一致。
11. 作为需要介入的用户，我希望红灯快速闪烁，同时其光晕急促扩散。
12. 作为等待运行的用户，我希望黄灯柔和呼吸，同时其光晕缓慢扩散。
13. 作为任务已完成的用户，我希望绿灯本体持续常亮，而其光晕持续缓慢扩散和收回，不仅完成瞬间闪一次。
14. 作为查看待机灯的用户，我希望三灯仍能以暗红、暗黄、暗绿区分灯位，但没有活跃光晕。
15. 作为选择标准动效的用户，我希望光晕可见而不过于抢眼。
16. 作为选择强烈动效的用户，我希望双层光晕和扩散幅度明显增强，同时不出现窗口边缘硬截断。
17. 作为开启系统“减少动态效果”的用户，我希望三灯停止闪烁及扩散，仍保留可识别状态和静态光晕。
18. 作为已有设置的用户，我希望升级后旧版低／中／高光晕偏好得到确定性映射。
19. 作为正在输入的用户，我希望 HUD 更换布局、轮播或播放动画均不抢键盘焦点。
20. 作为移动 HUD 的用户，我希望依然能直接拖动面板，点击本体不触发新的业务操作。

## Implementation Decisions

### 1. 模块职责与边界

- 偏好模型统一暴露布局枚举 `horizontal`／`vertical` 及光晕枚举 `standard`／`strong`，负责读写 UserDefaults 与旧值迁移；无效持久化值安全退回默认值。设置页只绑定这两个稳定语义值，不直接把旧版数字当成 Picker 标签。
- HUD 内容视图根据布局构建两种区域顺序；共享灯体和光晕绘制与同一套状态语义，不重复实现红、黄、绿的行为。标题过渡明确使用屏幕坐标系中的水平方向，不能把整幅横向视图旋转来替代纵向布局。
- 非激活 HUD 窗口负责尺寸、原生毛玻璃容器的胶囊圆角／遮罩、拖动、分布局位置持久化、显示器变化后的可见性。应抽取纯粹的几何计算与位置选择规则，以便不启动界面也可测试位置行为；不改变 Hooks、会话存储与轮播逻辑。
- 设置页在原 HUD 通用设置旁新增“显示方向”横向／纵向选择；光晕 Picker 只显示“标准”“强烈”；现有“恢复 HUD 默认位置”只作用于当前选中布局。

当前自动化测试目标只依赖核心模块。因此，偏好值解析／迁移决策和窗口矩形计算必须提取为不依赖 SwiftUI、NSWindow、NSScreen 单例的纯逻辑，输入普通值或矩形、输出解析结果或目标矩形；应用层再负责读取 UserDefaults 和 NSScreen 并调用它们。不要为了写测试让核心模块反向依赖应用界面模块，也不要把只能人工验证的动画图层强塞进核心模块。

### 1.1 对外状态的唯一语义

偏好层只允许以下四个有效原始值，禁止同时在不同模块继续传播 `0／1／2` 这类魔法数字：

| 偏好 | 有效原始值 | 设置页中文 | 默认值 |
| --- | --- | --- | --- |
| HUD 布局 | `horizontal` | 横向 | 是 |
| HUD 布局 | `vertical` | 纵向 | 否 |
| 光晕档位 | `standard` | 标准 | 是 |
| 光晕档位 | `strong` | 强烈 | 否 |

建议采用独立的新键：布局 `hudLayoutMode`，新光晕 `hudGlowMode`。旧键 `glowStrength` 只用于一次兼容读取，不再作为新界面的写入目标。设置页控件顺序固定为：显示 HUD、显示方向、轮播间隔、光晕效果、恢复 HUD 默认位置。控件标签使用“显示方向”和“光晕效果”，不要继续显示“光晕强度：低／中／高”。

布局和光晕值由应用模型发布；窗口控制器必须持续观察布局变化并更新现有同一个面板，不能创建第二个面板，也不能要求重启。观察对象必须由控制器持有，避免局部订阅离开初始化函数后被释放。

### 2. 几何与内容

| 指标 | 横向 | 纵向 |
| --- | --- | --- |
| 固定面板尺寸（点） | 420 × 40 | 40 × 420 |
| 区块排列 | 图标 → 标题 → 红黄绿灯 | 图标 ↓ 标题 ↓ 红黄绿灯 |
| 图标区沿长轴尺寸 | 40 | 40 |
| 灯区沿长轴尺寸 | 104 | 104 |
| 两条分隔线厚度 | 各 0.5 | 各 0.5 |
| 标题区沿长轴尺寸 | 275 | 275 |
| 灯体直径、两灯间距 | 28、4 | 28、4 |
| 灯区短轴内边距 | 6 | 6 |

1. 三盏灯及图标始终按 40 点短轴居中；三灯实际占用长轴 28 × 3 + 4 × 2 = 92 点，104 点灯区两端各剩 6 点。横向为水平灯组、纵向为竖直灯组；不因为扩散调整灯区大小，也不让实体灯体相互推挤。
2. 精确长轴加总为 `40 + 0.5 + 275 + 0.5 + 104 = 420`。不得使用会挤压图标区或灯区的“自适应剩余宽度”替代这个约束。三灯实际占用长轴 `28 × 3 + 4 × 2 = 92` 点，104 点灯区两端各剩 6 点。
3. 横向标题区总长 275 点，左右各留 6 点，因此文字最大排版长度为 263 点；标题保持单行、尾部省略、左对齐，字体继续为当前 13 点中等字重圆体。纵向标题区总长同样是 275 点，沿长轴上下各留 6 点，因此旋转前文字最大排版长度同样是 263 点。
4. 纵向标题只旋转文字内容顺时针 90°，即从正常水平文字旋转 `+90°`，使文字起点靠近顶部图标、文字末尾朝底部灯区延伸。图标、圆灯、分隔线、整个窗口本身均不旋转。实现顺序必须是：先给未旋转文字 263 点最大单行宽度并应用尾部省略，再旋转文字，再将旋转结果放入 40 × 275 点标题视区；不能先让文字无限排版后靠遮罩截断。
5. “靠近图标下方”不表示取消 6 点标题内边距：纵向文字可见起点距标题区顶部约 6 点。标题较短时不沿 275 点长轴居中，其起点仍固定在顶部；下面自然留白，符合用户手绘图。
6. 纵向分隔线对应原横向两条竖线的位置，转为 40 点宽、0.5 点高的横线。颜色、透明度、细线质感沿用现状，尤其不得显著加深标题／灯区分隔线；图标仍正向。
7. 纵向标题切换以**屏幕坐标**为准：旧标题整体向 HUD 右侧离开，新标题整体从 HUD 左侧进入，各自文字仍顺时针旋转 90°。移动距离至少为标题视区短轴 40 点，使开始／结束时标题完全在对应边界之外。动画持续时间沿用当前标题切换的 0.25 秒缓入缓出。应把旋转后的标题作为一个整体放入未旋转的 40 × 275 点裁剪视区，再对这个整体应用“左入／右出”过渡；不得把移动过渡加到旋转前的文字坐标系。
8. 标题身份仍以当前会话 ID 区分。标题文本变化但会话 ID 不变时可直接更新；轮播到不同 ID 时触发过渡。纵向裁剪范围只能是中间标题区，不能用整个胶囊做唯一裁剪，否则过渡文字会短暂覆盖图标或三灯。
9. 横向标题保持当前“新标题从下方进入、旧标题向上方退出”的效果，不因本轮纵向方案改成左右移动。开启“减少动态效果”时，横纵两种标题都仅使用 0.25 秒淡入淡出，不发生方向移动。
10. 继续使用 macOS 原生材质、淡灰底调、胶囊边框及非激活面板；只有 HUD 内容会改变，不添加新的 HUD 点击操作。

### 3. 灯体及双层光晕

1. 28 点实体圆灯固定尺寸，状态颜色顺序固定红、黄、绿。未点亮保持原色低亮度（参考现有 0.18 透明度），不播放光晕或扩散。
2. 每盏灯的层级从后到前固定为：外层光晕 → 内层光晕 → 28 点灯体。点亮灯同时绘制两层；未点亮灯两层光晕透明度必须为 0。外层用模糊／渐变自然衰减，不用边缘可见的实心大圆。三层共享同一中心点，任何层都不能改变 HStack／VStack 的布局占位。
3. 使用以下参数作为第一版确定值，不让编码模型自行猜测。人工验收只有在出现明显硬边或两档肉眼无法区分时，才允许在不改布局尺寸的前提下小幅调整透明度／模糊半径：

| 档位 | 最大光晕缩放 | 内层模糊半径 | 内层峰值透明度 | 外层模糊半径 | 外层峰值透明度 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 标准 | 1.15 | 6 | 0.50 | 12 | 0.28 |
| 强烈 | 1.30 | 9 | 0.70 | 18 | 0.45 |

透明度还要乘以当前灯的状态亮度相位，最终限定在 0...1。扩散时两层使用同一个缩放相位；外层因模糊半径更大，自然看起来扩散更远。**仅两层光晕缩放，28 点实体灯体固定为 1.0 倍。**
4. 时间相位必须按以下规则实现，防止三种灯最终又变成同一种动画：

| 活跃状态 | 周期 | 灯体透明度 | 光晕缩放 |
| --- | ---: | --- | --- |
| 红灯／需要关注 | 0.56 秒 | 沿用现有急促分段：快速亮起、短暂停留、快速熄暗、短暂停留 | 与红灯分段相位同步快速扩张／收回 |
| 黄灯／运行中 | 2.30 秒 | 正弦呼吸，范围 0.65...1.0 | 同一正弦相位在 1.0...档位最大值变化 |
| 绿灯／已完成 | 2.80 秒 | 恒定 1.0，绝对不能闪烁 | 独立正弦相位在 1.0...档位最大值变化 |

相位到缩放的统一计算为 `1 + phase × (档位最大缩放 - 1)`，其中 `phase` 范围为 0...1。红灯灯体透明度仍为 `0.35 + phase × 0.65`；红灯相位为 0 时光晕可以完全收回但灯体仍以 0.35 可见。绿灯不能复用“完成态暂停时间线”的旧判断，否则其光晕不会持续扩散。
5. 开启系统“减少动态效果”时，所有活跃灯采用灯体透明度 1.0、光晕缩放 1.0，并显示所选档位的静态双层光晕；不得继续红灯闪烁、黄灯呼吸、绿灯光晕扩散或标题位移动画。未点亮灯仍为 0.18 且无光晕。关闭减少动态效果后无需从旧动画进度续播，可依据当前绝对时间重新进入周期。
6. 胶囊遮罩不得让光晕溢出窗口，也不得在靠近纵向 40 点边缘时呈现明显硬直线；须通过光晕自身柔和衰减处理，不能靠扩大窗口或让光晕影响相邻图标／标题来规避。保持 30fps 左右的现有帧率上限，避免不必要的长期高频重绘。

### 4. 偏好兼容与位置

1. 新装默认横向、光晕标准。光晕读取算法严格按以下优先级执行：
   1. 若新键 `hudGlowMode` 存在且值为 `standard` 或 `strong`，直接采用，停止读取旧键。
   2. 若新键不存在，读取旧键 `glowStrength`：0 或 1 写入并采用 `standard`；2 写入并采用 `strong`；缺失、负数、3 以上或类型错误均写入并采用 `standard`。
   3. 新设置只写 `hudGlowMode`。迁移后可保留旧键以兼容旧版本，但新版本永远不再次用它覆盖新键。
   4. 布局新键缺失／非法时写入并采用 `horizontal`；不存在旧布局键，不做其它猜测。
2. 横向首次位置：主屏幕 `visibleFrame` 顶部居中，距可见顶部 12 点；纵向首次位置：主屏幕 `visibleFrame` 右侧垂直居中，距可见右缘 12 点。使用可见区域避开菜单栏和 Dock。
3. 位置记录需明确分键存储，建议使用 `hudPositionHorizontalV3` 和 `hudPositionVerticalV1`。每条记录保留现有字段：版本、显示器 UUID、旧显示器 ID、显示器名称、像素宽高、相对 X、相对 Y。现有单一 `hudPositionV2` 只作为横向兼容来源：新横向键不存在时读取它，成功后写入新横向键；永远不能把它用于纵向。现有更旧的绝对 `hudFrame` 也只允许迁移为横向记录。
4. 切换方向必须执行以下原子顺序：
   1. 设置“正在程序化更新”保护，避免窗口移动回调误保存。
   2. 按旧布局和旧尺寸保存当前窗口位置。
   3. 更新当前布局状态与 SwiftUI 内容。
   4. 将同一个面板尺寸改为目标固定尺寸，同时更新内容容器 frame、玻璃视图 frame、托管视图 frame、遮罩边界及圆角；圆角始终为短轴一半，即 20 点。
   5. 读取目标布局自己的位置；存在且能匹配屏幕则恢复，不存在则计算目标默认位置。
   6. 将最终窗口完整夹取进目标屏幕 `visibleFrame`。
   7. 清除保护标记，并保存目标布局最终位置。

禁止在步骤 2 前先改尺寸；禁止通过销毁旧面板再创建新面板切换；禁止切换时调用会让 HUD 获取键盘焦点的方法。
5. 默认位置公式使用主屏幕 `visibleFrame`：
   - 横向：`x = visibleFrame.midX - 210`，`y = visibleFrame.maxY - 40 - 12`。
   - 纵向：`x = visibleFrame.maxX - 40 - 12`，`y = visibleFrame.midY - 210`。
   - 结果仍需夹取，确保 `minX/minY` 不小于可见区域，`maxX/maxY` 不大于可见区域。
6. 两布局各保留拖动后的显示器身份和相对坐标。恢复屏幕的匹配优先级沿用现状：显示器 UUID → 旧显示器 ID → 名称加像素尺寸 → 名称；全部失败时回退主屏幕该布局的默认位置。若屏幕仍可匹配但尺寸变化，则根据相对坐标计算并完整夹取，不要直接回默认位置。
7. 相对位置计算继续使用 `(frame.minX - visible.minX) / max(1, visible.width - frame.width)` 和 Y 轴同类公式，结果限定在 0...1。恢复时使用目标布局当前尺寸计算可移动范围，不能使用保存时的另一尺寸。若屏幕任一可见边长小于目标窗口边长，窗口以该可见区域起点为兜底，不得产生负可移动范围或 NaN。
8. “恢复 HUD 默认位置”只删除／覆盖当前布局的位置键，并立即将 HUD 放到主屏幕该布局对应默认位置；不得删除另一布局键。即使 HUD 被隐藏，也更新记录，使下次显示正确。屏幕参数变化事件应重新验证当前布局位置，不应修改非当前布局的保存记录。

### 4.1 设置变化的用户可见行为

| 操作 | HUD 可见时 | HUD 隐藏时 |
| --- | --- | --- |
| 横向切纵向 | 立即将同一个面板改为纵向并恢复纵向保存位置；“同一个面板”不代表保留横向屏幕坐标 | 不弹出 HUD，只更新布局；下次显示采用纵向位置 |

| 更改轮播会话 | 沿当前布局规定方向过渡标题 | 维持现有后台状态行为，不额外显示 HUD |

## Testing Decisions

- 只对有边界条件的偏好迁移、布局切换及跨显示器位置恢复等状态逻辑编写自动化测试；基于输入状态断言外部可见结果，不用测试断言内部 SwiftUI 图层数量、私有方法调用或逐帧像素。现有核心模块的 Swift 测试可作纯逻辑测试风格参考。
- 偏好迁移测试至少覆盖新安装、0／1／2 三种旧值、非法旧值、迁移后新值不会被旧键覆盖；可注入隔离的 UserDefaults suite，避免污染用户真实设置。
- 位置测试至少覆盖双布局首次默认坐标、从横切纵再切横、仅重置当前布局、同屏相对位置恢复、目标显示器消失和屏幕缩小后的完整可见性；条件允许时将位置几何规则提取为可独立测试的纯函数。
- 视觉与动效采用人工验收：横纵面板尺寸、三灯 28 点、6 点边距、长标题末尾省略、图示左进右出、红黄绿不同节奏、标准与强烈档视觉差异、减少动态效果、浅／深模式、强光晕柔和收束和不抢焦点。没有批准引入截图基线，不写脆弱的像素截图测试。
- 各阶段运行 `git diff --check` 与对应构建／测试；显示器、系统辅助功能和真实窗口焦点不能只靠单元测试替代，人工验收应记录实际完成情况与无法在当前环境验证的项目。
