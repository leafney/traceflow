## 实现者必读

本文是本功能唯一正式规格。实现者必须完整阅读本文后再修改代码，不能只交换两种灯的颜色，也不能只增加一个设置项。

本需求同时修改四部分：

1. 运行状态与黄／绿灯的视觉映射。
2. 红、黄、绿三级抢占和三级先进先出队列。
3. “统一时长／按状态分配”两种展示时长模式及展示周期快照。
4. 轮播诊断日志、自动化测试和已有文档中的旧颜色说明。

任何与旧文档冲突之处，以本文为准。内部业务状态名和 Hook 到状态的映射保持不变；只改变这些状态在 HUD 中的颜色、动画和轮播调度方式。

本文面向低智能编码模型，因此所有关键词按字面执行。不得擅自增加防抖、公平配额、旧设置迁移、状态文字、用户可调倍率或新的 Hook。

## Problem Statement

Traceflow 当前给所有活跃会话使用同一个轮播展示时长。红色权限等待可以抢占其他状态，但运行中和已完成状态共用普通事件队列，没有形成清晰的用户关注层级。

这会产生三个体验问题：

1. 需要立即处理的权限请求和无需处理的正常运行占用相同展示时间，紧急信息不够突出。
2. 一个会话已经完成、等待用户继续输入时，不能立即打断仍在运行的会话，用户可能较晚才发现工作已经完成。
3. 现有黄灯表示运行、绿灯表示完成，更接近构建流水线的成功语义，却没有直接表达 Traceflow 最重要的问题：“用户现在是否需要回来操作”。

用户希望 HUD 改为以介入紧急度为中心：红色表示必须马上处理，黄色表示已经完成并可以继续操作，绿色表示仍在正常运行。同时保留当前统一轮播时长，再增加固定的按状态分配时长模式。

## Solution

保持内部状态 `attention`、`completed`、`running`、`idle` 以及现有 Hooks 状态机不变，重新定义 HUD 映射：

| 内部状态 | HUD 颜色 | 用户含义 | 动画 | 抢占级别 |
|---|---|---|---|---:|
| `attention` | 红 | 等待用户立即选择或处理 | 急促快闪和光晕变化 | 3，最高 |
| `completed` | 黄 | 本轮已完成，等待用户下一步输入 | 常亮，沿用现有完成态缩放／光晕节奏 | 2 |
| `running` | 绿 | Codex 正在工作，无需用户介入 | 平缓呼吸和光晕变化 | 1，最低 |
| `idle` | 全暗 | 待机，不参与活跃轮播 | 无动画 | 0 |

横向和纵向 HUD 的实体灯顺序都继续保持红、黄、绿。

所有模式统一使用 `红 > 黄 > 绿` 抢占规则。新增“展示时长”设置：

- `统一时长`：每种颜色都使用用户选择的 3、5 或 10 秒，默认 5 秒。
- `按状态分配`：红色固定 6 秒、黄色固定 4 秒、绿色固定 2 秒。

每个展示周期开始时锁定当时的模式和时长。用户修改设置后立即保存，但当前周期不变；下一次会话切换、抢占或真实状态变化产生的新周期才采用最后保存的设置。

## User Stories

1. 作为同时运行多个 Codex 会话的用户，我希望权限请求红灯立即抢占其他会话，从而及时完成必须处理的选择。
2. 作为等待任务结果的用户，我希望已完成黄灯立即抢占运行中绿灯，从而尽快知道可以进行下一步操作。
3. 作为查看正常任务的用户，我希望运行中使用绿色呼吸灯，从而理解当前流程正常且无需介入。
4. 作为查看已完成任务的用户，我希望完成态使用黄色常亮灯，从而理解流程停在可继续操作的阶段，而不是仍在运行。
5. 作为偏好简单设置的用户，我希望继续使用统一轮播时长，从而不改变原有使用习惯。
6. 作为关注紧急状态的用户，我希望选择按状态分配，让红、黄、绿分别完整显示 6、4、2 秒。
7. 作为使用任一时长模式的用户，我希望两种模式都有相同的红黄绿抢占规则，从而避免模式名称影响状态优先级。
8. 作为正在查看当前会话的用户，我希望修改设置后当前展示不突然重置或跳走，从而保持视觉连续性。
9. 作为修改设置的用户，我希望下一展示周期使用最后一次保存的值，从而让新设置快速而可预测地生效。
10. 作为看到会话被抢占的用户，我希望被打断会话稍后获得完整展示时间，从而不会丢失它的信息。
11. 作为有多个同级事件的用户，我希望同色会话按到达先后显示，从而得到稳定顺序。
12. 作为有长期未处理红灯的用户，我希望该会话显示一次后回到正常轮播，从而不会永久遮住其他会话。
13. 作为有新运行会话的用户，我希望新绿色状态取得一次排队展示机会，但不打断正在显示的状态。
14. 作为收到重复 Hook 事件的用户，我希望相同状态不反复重置轮播，从而避免单个会话霸屏。
15. 作为状态快速变化的用户，我希望 HUD 始终使用会话最新状态，从而不显示已经过期的颜色。
16. 作为启用活跃历史会话的用户，我希望它立即按当前颜色应用优先规则，从而与实时发现的会话一致。
17. 作为关闭当前会话的用户，我希望 HUD 立即选择最高优先级待展示会话，从而不显示已关闭项。
18. 作为只启用一个活跃会话的用户，我希望 HUD 稳定显示它，不因时间到期重复播放标题动画。
19. 作为开启系统“减少动态效果”的用户，我希望灯保持静态但颜色含义、抢占和时长仍然准确。
20. 作为排查问题的用户，我希望日志说明每次切换的来源、目标、原因、状态和锁定时长。
21. 作为阅读项目文档的开发者，我希望正式规划统一采用新黄绿含义，从而不按旧规则错误实现。

## Implementation Decisions

### 1. 不修改内部状态和 Hooks 状态机

内部枚举继续为：

- `idle`
- `running`
- `attention`
- `completed`

Hook 到状态的现有映射继续保持：

| Hook 事件 | 内部状态 |
|---|---|
| `UserPromptSubmit` | `running` |
| `PermissionRequest` | `attention` |
| `PreToolUse` | `running` |
| `PostToolUse` | `running` |
| `Stop` | `completed` |
| `Interrupt`／`SessionEnd` | `idle` |

禁止为了匹配颜色而把 `running` 和 `completed` 枚举互换，禁止修改网络协议中的状态值，禁止修改持久化会话结构中的状态含义。

### 2. 颜色、灯位和动画映射

灯位保持：

- 横向 HUD：从左到右为红、黄、绿。
- 纵向 HUD：从上到下为红、黄、绿。

每种业务状态只能点亮一盏灯：

| 状态 | 红灯 | 黄灯 | 绿灯 |
|---|---|---|---|
| `attention` | 激活 | 暗 | 暗 |
| `completed` | 暗 | 激活 | 暗 |
| `running` | 暗 | 暗 | 激活 |
| `idle`／无会话 | 暗 | 暗 | 暗 |

动画跟随业务状态，不跟随旧颜色：

- `attention` 继续使用现有急促分段闪烁、0.9～1.1 缩放和同步光晕。
- `running` 继续使用现有约 2.30 秒平缓呼吸、0.9～1.1 缩放、从暗到亮和同步光晕；只是实体颜色从黄改为绿。
- `completed` 继续使用现有完成态常亮、0.9～1.1 缓慢缩放及稳定光晕；只是实体颜色从绿改为黄。
- 未激活灯继续使用当前暗态透明度，不增加新效果。

开启 macOS“减少动态效果”时：

- 激活的红、黄、绿灯都静态常亮并显示静态光晕。
- 不运行红灯快闪、绿色呼吸或黄色缩放动画。
- 抢占规则、队列和展示时间不变。
- 标题继续使用现有淡入淡出降级方案。

无障碍描述仍使用业务含义，例如“需要处理”“运行中”“已完成”，不把颜色名称当作状态名称。

### 3. 时长模式数据模型

新增独立枚举，语义固定：

```text
CarouselTimingMode
  uniform       // 统一时长
  byState       // 按状态分配
```

新增纯值配置对象，至少包含：

```text
CarouselTimingConfiguration
  mode: CarouselTimingMode
  uniformDuration: TimeInterval
```

统一时长只接受 `3`、`5`、`10`，默认 `5`。按状态分配不读取 `uniformDuration` 来计算当前周期，固定返回：

```text
attention -> 6 秒
completed -> 4 秒
running   -> 2 秒
```

`idle` 不产生展示周期，时长计算器不得为它启动计时。

把“根据模式和状态计算时长”封装成可独立测试的纯逻辑。调度器不得在各分支重复硬编码 6、4、2。

当前处于开发阶段，不实现旧版本迁移：

- 不读取废弃键来推导新模式。
- 不保留历史无效枚举值的转换表。
- 新模式字段缺失或无效时直接采用新版默认值 `uniform`。
- 统一时长字段缺失或无效时直接采用新版默认值 5 秒。

### 4. 设置页行为

在常规设置区增加一行：

```text
展示时长  [统一时长 | 按状态分配]
```

建议使用与现有 macOS 设置页一致的 Picker／分段选择器。具体行为：

1. 选择“统一时长”时，显示现有“轮播间隔”选择器，选项为 3 秒、5 秒、10 秒。
2. 选择“按状态分配”时，隐藏“轮播间隔”选择器，改为只读次要文字：`红 6 秒 · 黄 4 秒 · 绿 2 秒`。
3. 本版不显示“红色需要处理”“黄色已完成”“绿色运行中”等教学说明。
4. 用户切换模式时立即持久保存最新模式。
5. 用户修改统一时长时立即持久保存最新秒数。
6. 切换回统一时长后，显示本次运行期间最后选择的 3／5／10 秒。
7. 设置改变不能主动切换当前 HUD 会话，不能重播当前标题动画，不能修改当前周期的截止时间。
8. 当前周期结束后的第一个新周期使用最终保存值；期间连续修改多次，只采用最后一次值。

### 5. 展示周期快照

调度器必须显式维护“当前展示周期”，不能继续在每次定时 tick 时读取实时设置并用实时值比较。

当前周期至少包含：

```text
PresentationCycle
  sessionID
  runtimeState
  timingModeSnapshot
  durationSnapshot
  visibleFrom
  deadline
  generation
```

字段语义：

- `runtimeState`：周期开始时会话的真实状态。
- `timingModeSnapshot`：周期开始时最新设置模式。
- `durationSnapshot`：周期开始时已解析出的最终秒数；后续设置改变不能修改它。
- `visibleFrom`：标题过渡已经完成、内容开始完整可读的时刻。
- `deadline = visibleFrom + durationSnapshot`。
- `generation`：单调递增代号，用于使已经被后续抢占替代的旧动画完成回调失效。

以下操作开始新周期并读取最新设置：

1. 从一个会话实际切换到另一个会话。
2. 高优先级会话抢占当前会话。
3. 当前显示会话发生真实状态变化，即使会话 ID 不变。
4. 占位状态切换到第一个活跃会话。

以下操作不开始新周期：

1. 重复收到同一个状态，状态机返回 `stateChanged == false`。
2. 只更新项目名、标题摘要或最后更新时间。
3. 修改时长模式或统一轮播秒数。
4. 定时 tick。
5. 唯一活跃会话到达当前截止时间但没有其他可切换项。

若唯一活跃会话到期，调度器返回“无需切换”，不生成同 ID 决策、不递增 generation、不播放动画。未来出现第二个活跃会话后才恢复轮播。

### 6. 标题动画与计时起点

展示秒数不包含标题进入／离开动画。

实现必须保证：

1. 初次显示且没有切换动画时，`visibleFrom` 等于选择时刻。
2. 发生标题切换动画时，`visibleFrom` 不得早于动画结束。
3. 当前标题动画最大持续约 0.20 秒。可以由 UI 在完成时通知调度器，也可以用与动画统一的共享常量计算 `visibleFrom = switchTime + transitionDuration`；禁止在两个模块各写一个可能漂移的魔法数字。
4. 淡入淡出持续时间短于共享最大切换时长时，可以使用共享最大时长，保证完整可读时间不少于配置值。
5. 动画进行中出现更高优先级事件时，立即用新目标替换旧目标；旧 generation 的延迟回调不得修改新周期。
6. 被动画中断的旧目标会话重新进入其最新状态对应队列，之后取得完整周期。
7. 同一会话自身变色不切换标题，不播放标题进入动画；新周期从状态变化时刻直接开始计时。

### 7. 状态优先级与抢占矩阵

优先级数值只用于比较，不改变常规轮播顺序：

```text
attention = 3
completed = 2
running   = 1
idle      = 0，不可展示
```

当非当前会话发生真实状态变化，或者一个已处于活跃状态的会话被用户新启用时，严格使用以下矩阵：

| 当前显示 | 新事件红 `attention` | 新事件黄 `completed` | 新事件绿 `running` |
|---|---|---|---|
| 红 `attention` | 不抢占，红队列末尾 | 不抢占，黄队列末尾 | 不抢占，绿队列末尾 |
| 黄 `completed` | 立即抢占 | 不抢占，黄队列末尾 | 不抢占，绿队列末尾 |
| 绿 `running` | 立即抢占 | 立即抢占 | 不抢占，绿队列末尾 |
| 无当前活跃会话 | 立即显示 | 立即显示 | 立即显示 |

“同级不抢占”包含不同会话的同一种状态。新同级会话进入对应队列末尾。

抢占发生时必须执行以下原子步骤：

1. 读取当前显示会话的最新状态。
2. 若当前会话仍活跃且已启用，把当前会话追加到其最新状态对应队列末尾。
3. 从全部队列删除即将显示的新会话，防止重复。
4. 将新会话设为当前会话。
5. 生成新展示周期，使用最新时长设置快照。
6. 返回带动画的切换决策。

禁止只切换到新会话而丢弃被打断会话。

### 8. 三个优先队列

把现有红色队列和混合普通事件队列重构为三个队列：

```text
attentionQueue  // 红色，先进先出
completedQueue  // 黄色，先进先出
runningQueue    // 绿色，先进先出
```

队列必须满足以下不变量：

1. 同一个会话 ID 在全部三个队列中合计最多出现一次。
2. 当前显示会话不能同时留在任何队列。
3. 未启用、已删除或 `idle` 会话不能留在队列。
4. 队列中的会话实际状态必须与队列类型一致。
5. 会话真实变色时，先从全部队列删除，再依据最新状态处理。
6. 重复同状态事件不得重复入队，也不得改变其已有先进先出位置。
7. 会话变为 `idle` 时从全部队列删除。
8. 会话被用户关闭时从全部队列删除。

自然到期或当前项失效后，候选选择顺序固定为：

1. `attentionQueue` 第一个仍有效的会话。
2. `completedQueue` 第一个仍有效的会话。
3. `runningQueue` 第一个仍有效的会话。
4. 既有常规轮播顺序中的下一个活跃且已启用会话。
5. 若没有活跃会话，显示现有 Traceflow 占位和三盏暗灯。

出队时若队首已经失效，直接丢弃并继续查找，不得短暂显示错误会话。

### 9. 当前会话真实状态变化

当前显示会话变色时必须立刻更新灯，不等待原标题展示周期结束。

处理顺序：

1. 从三个队列删除当前 ID。
2. 更新状态镜像。
3. 若新状态为 `idle`，立即按“红队列 → 黄队列 → 绿队列 → 常规轮播 → 占位”选择下一项。
4. 若新状态仍活跃，检查队列中是否存在优先级严格高于新状态的有效会话。
5. 若存在，把当前会话按新状态放入对应队列末尾，立即显示最高优先级队首。
6. 若不存在，当前会话继续显示，但创建无标题动画的新展示周期，并使用最新设置。

示例：

- 当前红变绿，红队列有 B：当前 A 进入绿队列，立即显示 B 红。
- 当前红变黄，没有红队列：A 继续显示，灯改黄，开始新的黄色完整周期。
- 当前黄变绿，黄队列有 B：A 进入绿队列，立即显示 B 黄。
- 当前绿变红：A 仍是当前会话，灯立即改红，开始新的红色完整周期，不重播标题动画。

### 10. 新启用、关闭和会话集合更新

用户在设置页单项启用或项目批量启用会话时，调度器必须比较启用前后集合，识别“本次新启用且当前活跃”的会话，并将其视为一次获得展示资格的事件：

- 新启用红色会话按红色规则抢占或排红队。
- 新启用黄色会话按黄色规则抢占或排黄队。
- 新启用绿色会话排绿队，不抢占。
- 新启用 `idle` 会话不入队。

若一次项目开关同时启用多个会话：

1. 先按既有稳定会话顺序处理，禁止依赖字典遍历顺序。
2. 每个颜色内部保持该稳定顺序。
3. 允许其中最高优先级的第一个会话按矩阵抢占一次；其余会话进入各自队列。
4. 不连续播放多次瞬间抢占动画。

关闭行为：

- 关闭非当前会话：从队列删除，不改变当前周期。
- 关闭当前会话：当前周期立即失效，按固定候选顺序选择下一项。
- 全部关闭或全部待机：显示占位，三灯全暗。

会话同步、删除和完成超时也必须经过相同队列清理，不得留下幽灵 ID。

### 11. 常规轮播与长期红黄状态

颜色优先级不用于永久排序常规轮播。

插队队列全部清空后，继续使用现有 `rotationIndex` 稳定顺序选择下一活跃会话。假设常规顺序为 A绿、B红、C黄，并且期间没有新状态事件，轮播仍是 A → B → C；只根据当前时长模式为每项锁定不同秒数。

红色或黄色会话在一次新状态事件展示完成后，不因仍保持该状态而自动重新加入高优先级队列。它会在常规轮播中再次出现。因此长期未处理红灯不会永久独占 HUD。

不增加以下逻辑：

- 高优先级连续抢占次数上限。
- 低优先级公平配额。
- 红灯自动降级。
- 状态变化防抖。

真实的新红／黄事件始终可按矩阵抢占。事件高峰结束后，被打断项通过队列继续展示。

### 12. 完成超时保持十分钟

`completed` 仍从进入完成状态的时间开始计算 600 秒：

- 600 秒内为活跃黄色状态，参与队列和常规轮播。
- 达到 600 秒后转为 `idle`，黄灯熄灭并立即退出队列和轮播。
- 任意新状态事件到达后，旧完成计时失效。
- 重启仍按现有 MVP 行为恢复为待机，不跨重启恢复剩余时间。

本需求不得把 600 秒误改为黄色展示时长。黄色单次轮播时长是统一模式的 3／5／10 秒之一，或按状态模式的 4 秒；它与 600 秒生命周期是两个独立概念。

### 13. 决策原因和诊断日志

切换原因必须足够明确，至少能区分：

- 首次显示。
- 红色抢占。
- 黄色抢占。
- 红色队列出队。
- 黄色队列出队。
- 绿色队列出队。
- 常规轮播。
- 当前状态变化后继续显示同一会话。
- 启用／关闭导致的选择变化。
- 会话转待机或超时。
- 显示占位。

每次“实际产生新展示周期”记录一条日志。建议字段：

```text
carousel=switch
from_session_id="..."
to_session_id="..."
to_project="..."
to_state=attention|completed|running
reason=...
timing_mode=uniform|by_state
duration_seconds=...
```

如果来源或目标为空，使用明确的 `none`，不要省略到无法判断。

设置变化记录一条日志：

```text
carousel=settings_changed timing_mode=... uniform_duration_seconds=... applies=next_cycle
```

约束：

1. 不记录每 0.25 秒 tick。
2. 不记录提示词全文、工具参数、用户选择内容或终端文本。
3. 同一会话自身真实变色产生新周期时也记录；`from_session_id` 与 `to_session_id` 可以相同，原因必须是状态变化。
4. 重复同状态事件不产生轮播切换日志。
5. 日志继续遵守现有最多 5 个文件、每个最大 10 MB 的规则。

### 14. 调度模块接口要求

轮播调度器继续保持纯 Swift 逻辑，不直接访问 SwiftUI、UserDefaults、文件系统或日志器。建议把接口收敛为以下职责，实际命名可遵循现有代码风格，但语义不得省略：

```text
updateTimingConfiguration(latestConfiguration)
  保存供下一个周期使用的最新配置；绝不修改当前周期。

updateSessions(snapshots, now)
  更新稳定顺序、状态镜像和参与集合；处理新启用、关闭、删除及当前项失效。

reportStateChange(sessionID, newState, stateChanged, now)
  清理旧队列；只有 stateChanged=true 才产生新周期、抢占或新队列资格。

advance(now)
  仅在当前周期到期并且存在另一候选项时切换；不再接收实时 displayDuration。
```

切换决策至少携带：

```text
sessionID
reason
animated
presentationGeneration
timingModeSnapshot
durationSnapshot
visibleFrom
```

应用模型只消费调度器返回的一个最终决策。一次 Hook 事件不得先应用成员更新决策、再应用状态决策导致双切换；应先完成调度器内部状态更新，再返回唯一最终显示结果。

1. 加载和保存最新时长模式与统一秒数。

应用模型不得自行维护第二套红黄绿队列，不得在视图中判断抢占优先级。

## Testing Decisions

### 测试原则

- 测试外部可观察行为，不断言私有数组具体实现。
- 时间测试必须注入固定 `Date`，禁止真实等待 2、4、6、10 或 600 秒。
- 每个测试使用明确会话 ID 和稳定 rotationIndex，禁止依赖字典遍历顺序。
- 视觉动画计算测试纯参数；SwiftUI 外观使用构建检查和人工验收。
- 复杂调度属于本项目需要自动化覆盖的核心状态转换逻辑。

### 时长策略测试

1. 统一模式下 attention、completed、running 均返回选定的 3 秒。
2. 统一模式下三种状态均返回选定的 5 秒。
3. 统一模式下三种状态均返回选定的 10 秒。
4. 按状态分配下 attention 返回 6 秒。
5. 按状态分配下 completed 返回 4 秒。
6. 按状态分配下 running 返回 2 秒。
7. idle 不创建周期。
8. 缺失或非法模式使用新版默认 uniform，不执行历史迁移。
9. 缺失或非法统一秒数使用 5 秒。

### 展示周期快照测试

1. 当前统一 10 秒周期显示 4 秒后改成按状态分配，当前仍在原 10 秒截止时间结束。
2. 上述设置变化后，下一个红色新周期锁定 6 秒。
3. 当前周期内多次修改设置，下一周期使用最后一次值。
4. 修改设置不改变 currentSessionID、generation、visibleFrom 或 deadline。
5. 当前会话真实变色后创建新周期并使用最新设置。
6. 重复同状态事件不创建新周期。
7. 标题元数据变化不创建新周期。
8. 带动画决策的 deadline 从动画结束后计算。
9. 初始无动画决策从选择时刻计算。
10. 旧 generation 的动画完成回调不能覆盖新周期。
11. 只有一个活跃会话到期不产生自我切换或新 generation。

### 抢占矩阵测试

逐项覆盖九种当前／新事件组合：

1. 红 + 新红：不抢占，新红排红队。
2. 红 + 新黄：不抢占，新黄排黄队。
3. 红 + 新绿：不抢占，新绿排绿队。
4. 黄 + 新红：红立即抢占，旧黄排黄队。
5. 黄 + 新黄：不抢占，新黄排黄队。
6. 黄 + 新绿：不抢占，新绿排绿队。
7. 绿 + 新红：红立即抢占，旧绿排绿队。
8. 绿 + 新黄：黄立即抢占，旧绿排绿队。
9. 绿 + 新绿：不抢占，新绿排绿队。

每个立即抢占测试同时断言：

- 被打断会话仍可随后展示。
- 被打断会话恢复时取得完整时长。
- 新会话使用最新配置快照。
- 同一个 ID 没有重复队列资格。

### 队列与状态变化测试

1. 红、黄、绿队列都有项时严格按红 → 黄 → 绿出队。
2. 同色多个项按事件到达顺序出队。
3. 排队会话从绿变黄后只从黄队列出现。
4. 排队会话从黄变红后只从红队列出现。
5. 排队会话变 idle 后不再出现。
6. 排队会话被关闭或删除后不再出现。
7. 失效队首被跳过，直接选择下一个有效项。
8. 重复同状态事件不改变原先进先出位置。
9. 当前红变绿且红队列有项时，立即显示排队红，当前进入绿队。
10. 当前黄变绿且黄队列有项时，立即显示排队黄。
11. 当前红变黄且没有红队列时，当前会话继续显示并开启黄色新周期。
12. 当前绿变红时保持同一 ID、不播放标题切换，但开启红色新周期。
13. 高优先队列清空后恢复 rotationIndex 常规顺序，不按颜色永久排序。
14. 长期红色在无新事件时不会反复进入红队，其他会话仍可显示。

### 启用与关闭测试

1. 当前绿时启用活跃红，红立即抢占。
2. 当前绿时启用活跃黄，黄立即抢占。
3. 当前黄时启用活跃绿，绿排队不抢占。
4. 启用 idle 会话不入队。
5. 一次项目开关启用多个会话时，同色顺序稳定。
6. 批量启用只产生一个立即抢占目标，其余正确排队。
7. 关闭当前会话立即选红队、黄队、绿队或常规候选中的最高项。
8. 关闭非当前会话不重置当前周期。
9. 全关闭回到占位且三灯全暗。

### 完成超时测试

1. completed 在 599.9 秒仍为黄色活跃状态。
2. completed 到 600 秒转 idle、从黄队列移除并退出轮播。
3. 超时的是当前会话时立即选择下一项。
4. 完成后收到 running 时取消旧超时并点亮绿色。

1. attention 激活颜色为红，继续使用急促相位。

## Acceptance Criteria

1. `attention` 显示红灯、`completed` 显示黄灯、`running` 显示绿灯、`idle` 全暗。
2. 两种布局的物理顺序保持红、黄、绿。
3. 两种时长模式都执行红 > 黄 > 绿抢占。
4. 红可打断黄／绿，黄可打断绿，绿不抢占，同级不抢占。
5. 被打断项不会丢失，恢复后取得完整周期。
6. 三级队列按红、黄、绿顺序处理，每级内部先进先出。
7. 同一会话队列中只保留最新状态且最多出现一次。
8. 统一时长支持 3／5／10 秒；按状态分配固定 6／4／2 秒。
9. 设置变化不修改当前周期，从下一新周期生效。
10. 标题动画时间不侵占配置的完整可读时长。
11. 单一活跃会话不自我切换。
12. 重复同状态事件不重置周期、不重复入队。
13. 黄色完成状态 600 秒后转待机并退出轮播。
14. 设置页只显示约定的简短 6／4／2 文案，不增加教学说明或倍率控件。
15. 日志能解释每次真实切换及其锁定时长。
16. 正式文档无未标注的旧黄绿当前规则；历史讨论有覆盖说明。
17. 全部自动化测试和构建通过。
