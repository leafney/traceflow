# HUD 背景透明度 PRD

Related discussion: [docs/discuss/2026-09-28-hud-background-transparency.md](../discuss/2026-09-28-hud-background-transparency.md)

> 状态：所有开发阶段已完成，自动验证通过；真实桌面视觉与交互验收待完成。分割线移除已独立完成。

## Problem Statement

HUD 当前采用固定的系统磨砂材质，用户无法控制背景遮挡程度。用户希望保留标题与状态灯的清晰度，同时自由选择背景透明度；高透明度时隐藏装饰图标并缩短窗口。

## Solution

在常规设置中增加“背景透明度”滑块及百分比显示，范围 0～100%，步长 1%，默认 80%。拖动立即更新 HUD，松手保存，重启恢复。90% 及以上隐藏左侧图标并平滑收起空间；100% 时只显示标题与三个状态灯。

## User Stories

1. 作为用户，我希望通过滑块调整背景，以减少对下层应用的遮挡。
2. 作为首次或升级后的用户，我希望默认使用 80% 透明度，以直接获得半透明效果。
3. 作为用户，我希望拖动时实时预览，以选择适合当前壁纸的数值。
4. 作为用户，我希望松手后自动保存，以免额外点击应用按钮。
5. 作为重启应用的用户，我希望恢复保存的透明度，以保持外观。
6. 作为用户，我希望标题和状态灯不随背景变淡，以看清状态。
7. 作为高透明度用户，我希望图标自动隐藏并收起，以减少占用空间。
8. 作为用户，我希望窗口尺寸平滑变化，以避免跳动。
9. 作为全透明用户，我希望只看见标题与状态灯，以实现最小遮挡。
10. 作为多显示器用户，我希望透明度变化不破坏位置恢复，以保持已选择的位置。
11. 作为已钉住 HUD 的用户，我希望调整外观后继续鼠标穿透，以保持交互习惯。
12. 作为使用系统辅助功能的用户，我希望遵循减少动态效果与减少透明度，以适应系统设置。

## Implementation Decisions

### 1. 数值与保存

- 统一保存整数透明度 T，合法范围 0～100，默认 80。界面不能把“不透明度”误标为透明度；背景有效不透明度为 (100−T)/100。
- 缺失、非数字、布尔值或非有限数值回退 80；有限越界数值截断到范围内；旧的小数数值四舍五入为整数。使用独立偏好键，不修改已有布局、光晕或钉住键。
- 应用模型持有唯一当前透明度。滑块预览更新该属性，窗口与内容视图从该值推导，不能维护各自独立的滑块数值。
- 松手提交当前值；键盘、辅助功能等没有松手回调的离散调整也必须保存。避免仅依赖鼠标结束回调导致键盘修改重启丢失。关闭设置窗口或退出应用时提交尚未保存的预览值。
- 启动先加载值，再创建正确材质、内容和尺寸的 HUD；不能先显示 420 点再闪烁缩成 380 点。

### 2. 背景合成

- 现有背景包括 AppKit 磨砂、SwiftUI 淡黑底色、外边框与窗口阴影。必须协调全部层，不能只改其中一层，更不能修改窗口整体 alpha 或整个 HUD 内容的 opacity。
- 推荐独立背景容器，在其中组合符合浅色／深色模式的实色底与系统磨砂层；整体背景贡献随 T 减少。T=0 用完全不透的实色底保证下层内容不可见；中间数值呈现逐渐更透明的磨砂；T=100 背景容器贡献为零。
- 不将系统材质自身的视觉强度宣称为精确物理百分比；数值控制应用背景合成强度，模糊效果由系统材质决定。
- 外边框随背景强度变淡，T=100 完全隐藏；窗口阴影在 T=100 关闭，降到 99 以下恢复。阴影不能残留在全透明背景周围。
- 标题、状态灯、灯效亮度及已有动画不随 T 改变。两条分割线永久不存在，不能因透明度变化重新添加。
- T=100 时仍保留可拖动的窗口范围；钉住仍由窗口级鼠标忽略控制。外观透明不等于自动鼠标穿透。

### 3. 图标与几何

| T | 图标 | 横向尺寸 | 纵向尺寸 | 背景 |
| --- | --- | --- | --- | --- |
| 0 | 显示 | 420×40 | 40×420 | 完全不透 |
| 1～89 | 显示 | 420×40 | 40×420 | 磨砂半透明 |
| 90～99 | 隐藏并收起 | 380×40 | 40×380 | 磨砂半透明 |
| 100 | 隐藏并收起 | 380×40 | 40×380 | 背景、边框、阴影消失 |

- 90 精确包含在隐藏范围，89 恢复。隐藏时收起图标的 40 点，不留占位空白；标题和状态灯原有空间不压缩。
- 横向保持窗口右端与状态灯位置；缩短时窗口左边向右移动 40 点。纵向保持窗口下端与状态灯位置；缩短时上边向下移动 40 点。AppKit 坐标向上增长，纵向固定 minY。
- 几何策略集中计算显示尺寸、完整尺寸、固定端和边界约束。现有位置恢复、默认位置、布局切换、旧位置迁移都必须使用该策略，不能留下硬编码 420 的恢复路径。
- 位置偏好使用兼容的完整尺寸参考框。紧凑状态拖动松手时，将实际框按固定端换算为完整参考框再保存；恢复时先恢复参考框，再换算为实际显示框。普通位置沿用旧结构，边缘位置可增加可选固定端字段以保证重启不漂移；旧记录仍可读取。
- 程序化尺寸动画不能保存位置。边界约束只为保证窗口可见；恢复默认位置及用户明确完成拖动仍按原规则保存。

### 4. 平滑过渡与竞态

- 仅跨越 90 阈值时改变尺寸，约 0.2 秒缓动；图标渐隐／渐现、占用空间收起／展开与窗口 frame 同步，不能只对 SwiftUI 内容做动画而让 AppKit 窗口瞬间跳变。
- 0～89 内或 90～100 内调整不启动尺寸动画，背景随滑块实时更新。
- 快速来回跨越阈值时，从当前可见状态过渡到最新目标；旧动画完成回调不能覆盖最新尺寸或保存位置。
- 拖动开始时结束尺寸过渡并同步到最新目标，再用该框开始新拖动；拖动过程中发生阈值变化时延后几何更新到拖动结束，背景数值仍实时生效。避免改变拖动起点导致跳动。
- 切换方向、重置位置、显示器变化／唤醒时取消旧过渡，使用最新透明度计算新框；这些操作继续保持钉住与显隐状态。
- 初次创建／重启／首次显示不播放尺寸收起动画；隐藏时直接应用目标，再显示就是正确尺寸。

### 5. 设置与辅助功能

- 常规设置增加“背景透明度”，滑块 0～100、步长 1，显示整数百分比；说明端点“0% 不透明，100% 全透明”。不增加数字输入框、应用按钮或恢复默认按钮。
- macOS 开启减少动态效果时不播放尺寸和图标动画，直接显示目标；运行时切换系统设置也应生效。
- macOS 开启减少透明度时遵循系统材质效果，提示“系统已减少透明效果”；保留数值与 90% 图标规则。T=100 仍隐藏背景；关闭系统选项后自动恢复对应材质，无需重启。

### 6. 实施阶段

1. 偏好与纯计算策略：透明度规范化、图标阈值、尺寸转换、固定端参考框，并补边界测试。
2. 应用状态与设置：加载、预览、提交、键盘调整保存与退出兜底；增加滑块和辅助功能提示。
3. 背景与动画接线：统一合成层、窗口阴影、图标空间及 AppKit 尺寸过渡；处理布局、拖动和多屏竞态。
4. 集成验证：完整测试、构建、差异检查；记录真实 macOS 桌面验收结果。每阶段验证后按用户实施授权要求提交。

## Testing Decisions

- 沿用独立 UserDefaults 域，不污染真实设置。覆盖默认 80、0／100、异常类型、越界、保存后重载。

- 测试快速跨阈值后最终目标、旧动画失效、拖动中延迟几何、减少动态效果直接完成。只测试可观察行为，不为简单属性赋值写镜像测试。

- 人工验收 0／80／89／90／99／100、深浅模式、忙碌下层画面、快速往返滑块、系统辅助设置变化。重点检查 100 是否残留底色、边框、阴影，以及动画是否同步、标题和灯效是否清晰。

### A. 文件职责与数据流

1. `Sources/TraceflowCore/HUDPreferences.swift`：增加独立键 `hudBackgroundTransparency` 和读取／保存接口。保存整数百分比，默认 80，复用现有 defaults 注入方式。读取 NSNumber 时先排除 CFBoolean，再判断有限性和范围。
2. 在核心模块新增外观／几何策略：输入规范化的透明度与布局，输出背景权重、图标显隐、实际尺寸及参考框换算。该模块不依赖 NSWindow 或 SwiftUI，便于测试。
3. `Sources/TraceflowApp/AppModel.swift`：初始化透明度可观察属性；提供预览、提交两个入口及“有未提交预览”标记。不要在属性 didSet 中每次同步持久化，违背松手提交约定。
4. `Sources/TraceflowApp/SettingsView.swift`：新增滑块行。Binding setter 调用预览入口；onEditingChanged(false) 提交。为非连续调整安排主线程短延迟提交，后续调整取消旧提交；连续拖动期间禁止该兜底提交。设置窗口关闭和应用退出都提交一次当前值。
5. `Sources/TraceflowApp/HUDView.swift`：接入图标显隐与动态长轴，删除独立固定底色和外边框，或将其纳入统一背景强度。标题和灯不能包在背景 opacity 容器里。已有分割线不再出现。
6. `Sources/TraceflowApp/HUDPanel.swift`：持有背景容器／材质视图引用，创建和更新均使用外观策略。观察透明度变化时使用通知参数；`@Published` 在存储值改变前通知，不能在同步回调内重新读模型取得旧值。
7. `Sources/TraceflowCore/HUDPositionGeometry.swift`：接入实际框与完整参考框转换；保留旧记录格式和默认 420 点策略的兼容性。检查窗口创建、默认位置、恢复、迁移、savePosition、方向切换这六条路径。
8. `Sources/TraceflowApp/TraceflowApp.swift`：退出时先提交未保存预览；不添加快捷键，不改钉住和显示菜单。
9. 新测试使用现有 `Tests/TraceflowCoreTests`；测试真实转换与状态边界，不仅重复同一个属性表达式。

完整数据流：滑块 → 预览入口 → 可观察透明度 → 外观策略 → 背景更新／图标与窗口过渡；松手 → 提交入口 → 偏好；启动 → 偏好 → 应用状态 → 正确尺寸和效果 → 首次显示。

### B. 可执行的背景合成基线

- 定义 t=T/100，背景总权重 a=1−t；两个内部层从后到前为适配系统深浅模式的实色层和 `NSVisualEffectView` 磨砂层。实色层内部权重为 1−t，磨砂层内部权重为 t；背景容器整体权重为 a。
- 实色背景颜色必须本身为不透明颜色，例如系统窗口背景色；不能拿现有 0.06／0.18 的淡黑叠层充当 T=0 的不透明背景。
- T=0：背景容器 alpha=1、实色层 alpha=1、材质层 alpha=0，下层画面不可见。
- T=80：容器 alpha=0.2、实色层 alpha=0.2、材质层 alpha=0.8，保留磨砂质感并大幅减弱遮挡。
- T=100：背景容器 alpha=0，关闭窗口阴影，外边框不可见；内容容器 alpha 始终为 1。
- 实际 AppKit 材质合成需要实机确认；若系统对层 alpha 的合成行为不符合以上端点，允许调整内部配方，但必须满足端点、单调变透明、内容不变淡三项要求，记录最终配方。
- 系统减少透明度时让系统决定材质替代外观，不强行绕过辅助设置；不禁用滑块，不改存储值。

### C. 尺寸与参考框精确换算

- 完整长轴 420 点，图标区域 40 点，紧凑长轴 380 点，短轴恒为 40 点。移除分割线后的标题容器实际长度为 276 点，灯区域 104 点：40+276+104=420，276+104=380。标题文本原有内边距保留，不把图标的 40 点再分配给标题。
- 将完整参考框记作 C，显示框记作 F，delta=图标隐藏时 40，否则 0。
- 横向：F.x=C.x+delta，F.y=C.y，F.width=420−delta，F.height=40；由显示框保存时 C.x=F.x−delta、C.y=F.y、C.width=420、C.height=40。
- 纵向：F.x=C.x，F.y=C.y，F.width=40，F.height=420−delta；保存参考框 C.x=F.x、C.y=F.y、C.width=40、C.height=420。
- 参考框只用于位置计算，可以在左侧／上侧超出可见范围；紧凑显示框必须可见。先按原记录生成参考框，再转显示框，最后约束显示框到目标屏幕。夹紧引起的程序化位移不立即写入偏好。
- 用户在紧凑状态拖到屏幕边缘时，完整参考框的原有 0～1 相对范围可能不足。不能直接截断造成重启漂移。可在位置记录中新增可选固定端比例：横向记录右端在屏幕可见宽度内的比例及底端比例；纵向记录下端比例及左端比例。新字段存在时优先按固定端生成参考框，缺失时沿用旧相对位置解码。屏幕匹配规则和既有偏好键不变。
- 新字段使用可选 Codable 属性，旧记录缺字段仍解码成功；旧相对字段继续保留供兼容。增加紧凑状态左／上边缘拖动后重启、再展开到完整状态的测试。完整窗口放不下时按可见区域夹紧，但不覆盖原固定端记录。

### D. 动画与中断的确定处理顺序

1. 启动：计算目标状态 → 创建内容与窗口正确尺寸 → 设置背景／阴影／鼠标穿透 → 恢复位置 → 显示。禁用初次尺寸动画。
2. 正常跨阈值：读取当前显示 frame → 算固定端目标 frame → 分配递增过渡编号 → 同步开始窗口 frame 和内容占位／图标动画。时长统一 0.2 秒。
3. 动画回调：只有编号仍为最新时才能完成目标收尾；不得写位置偏好。新目标取消旧过渡的收尾资格。
4. 用户开始拖动：取消旧过渡 → 先落到最新目标 frame → 取得新的拖动初始 frame 与鼠标坐标 → 开始拖动。现有拖动视图先创建 tracking 再通知开始，必须调整顺序，避免 tracking 保存动画前的 frame。
5. 拖动期间发生阈值变化：更新背景和待完成目标；暂不收起／展开图标占位或改变窗口 frame。松手先以当前显示形态保存用户拖动参考框，再执行最新目标过渡。
6. 拖动中钉住：沿用现有取消拖动流程，不提交取消的手势位置；清除延期目标的旧回调，按已保存参考框和最新透明度生成最终显示框。
7. 方向切换、重置、屏幕变化：使旧过渡失效，按最新状态重新计算最终框；这些事件不启动阈值动画。隐藏窗口也直接更新最终形态，避免显示时播放旧动画。
8. 系统减少动态效果在动画中开启：立即取消动画并落到目标状态；减少透明度变化只刷新背景和设置提示，不改尺寸。

### F. 禁止出现的实现错误

- 禁止设置 `window.alphaValue` 调节背景，会把标题和灯一起变透明。
- 禁止只把图标 opacity 设为零却保留 40 点空白。
- 禁止只更改 SwiftUI frame 而保留旧 NSPanel 大小。
- 禁止动画完成时调用 savePosition，或使用动画中的中间 frame 保存偏好。
- 禁止把透明度为 100 当作钉住状态，二者独立。
- 禁止 T=90 仍显示图标；禁止 T=89 隐藏图标。
- 禁止为窗口层、视图层与设置层分别持久化三个透明度值。
