# 合盖后 HUD 多显示器位置恢复 PRD

Related discussion: [docs/discuss/2026-09-28-hud-display-position-recovery.md](../discuss/2026-09-28-hud-display-position-recovery.md)

> 状态：用户已批准，代码已实现，自动验证通过；真实双屏合盖与拖动手势待实机验收。本文覆盖既有位置恢复规格中“原屏缺席时立即把主屏回退位置保存为永久位置”的规则。本文只处理 HUD 位置，不改变会话、轮播或置顶区逻辑。

## Problem Statement

用户将唯一的 HUD 拖到外接显示器后，电脑合盖再打开，HUD 有时留在主显示器。现有位置记录本来包含原显示器与相对坐标，但外接屏短暂消失时，程序把 HUD 放到主屏并立即保存，导致原记录丢失。系统自动移动窗口也可能触发位置保存。多块同型号显示器又可能靠名称猜错目标。

## Solution

把“用户选定的永久位置”和“目标屏暂不可用时的临时主屏位置”分开。临时回退始终保证 HUD 可见，但不修改永久位置。唤醒或显示器变化后，原屏能明确识别时自动移回原相对位置；不能明确识别时留在主屏。只有用户实际拖动 HUD 或点击“恢复 HUD 默认位置”才改变永久位置。

## User Stories

1. 作为把 HUD 放到外接屏的用户，我希望合盖后再打开仍回到该屏原位置，以便继续观察。
2. 作为原屏暂时断开的用户，我希望 HUD 先出现在主屏，以便不会丢失。
3. 作为等待原屏重新连接的用户，我希望临时主屏位置不覆盖原记录，以便连接后自动恢复。
4. 作为在临时位置手动拖动 HUD 的用户，我希望这个操作成为新位置，以便之后不再自动跳回旧屏。
5. 作为启动应用时外接屏尚未连接的用户，我希望原屏接上后自动恢复 HUD。
6. 作为改变显示器排列的用户，我希望 HUD 仍停在原物理显示器的对应相对位置。
7. 作为改变显示器分辨率或缩放的用户，我希望 HUD 完整留在该屏可见区域。
8. 作为使用两台同型号屏幕的用户，我希望无法确认身份时 HUD 留在主屏，避免跳到错误屏幕。
9. 作为使用横向或纵向 HUD 的用户，我希望两种布局的位置记录各自保留。
10. 作为点击恢复默认位置的用户，我希望 HUD 到主屏默认位置，并把这个位置保存为新选择。
11. 作为从睡眠唤醒的用户，我希望屏幕连接尚在稳定时不会错误覆盖已保存的位置。
12. 作为正在输入的用户，我希望 HUD 恢复位置时不抢键盘焦点。

## Implementation Decisions

### 1. 位置状态与不变量

- 对当前布局明确维护两类状态：**永久位置记录**（现有持久化记录）和**临时回退状态**（仅内存）。临时回退状态表示原目标显示器尚未明确可用，HUD 目前暂放可用主屏。
- 原屏缺席、屏幕身份有歧义、系统自动挪动窗口、唤醒后屏幕尚未稳定时，不写永久位置。程序调用窗口设 frame 也不写永久位置。不要让 `restorePosition` 的 `defer`、`windowDidMove` 或布局切换中的预保存绕过此规则。
- 仅以下动作可写永久位置：用户真实拖动并完成、用户点“恢复 HUD 默认位置”、没有旧记录时首次确定默认位置、可信的旧格式迁移。布局变化本身不代表用户选择新屏幕。
- 程序内显式标记恢复／回退／调整尺寸操作，移动通知在标记期间不保存。单靠 `windowDidMove` 无法证明是用户拖动，因为显示器变化也能触发它；实现必须有独立的用户拖动证据。
- 记录按现有横向与纵向键分别保存；临时回退状态也须和当前布局对应。切换布局时，不得把临时主屏 frame 作为旧布局或新布局的永久位置。新布局若有记录，按它自己的记录恢复；没有记录才按主屏默认位置放置。
- HUD 全局仍只有一个。隐藏／显示 HUD 不改变保存记录；隐藏期间屏幕变化时，下一次显示前或显示时应用最新位置策略。

### 2. 真实拖动与用户显式重置

- 推荐由 HUD 窗口接收鼠标事件，跟踪从该窗口开始的按下、拖动、释放手势；只在窗口 frame 确实发生变化且手势结束时，确认“用户真实拖动”。拖动过程中的多个 `windowDidMove` 不逐次保存。若当前 AppKit 事件路由使窗口子视图消费事件，需在不改变 HUD 点击／拖动体验的前提下，在窗口层捕获该手势；不能用“窗口移动了”作为替代判据。
- 用户真实拖动完成后，依据拖动后窗口中心点所在屏幕（否则用最大相交面积）计算显示器身份与相对位置并保存；退出临时回退状态。即使是在原屏缺席时拖到主屏上的新位置，也视为永久新选择，原屏后来出现时不再自动移回。
- 用户按下但未移动、系统自动移动、布局切换的尺寸变化、代码恢复 frame，均不能提交新位置。若拖动结束后没有可用屏幕，不提交位置，继续保留先前记录。
- “恢复 HUD 默认位置”是明确的用户动作：选当前主屏，按当前布局的默认位置放置，并保存为永久位置；退出临时回退状态。横向重置不改纵向记录，反之亦然。

### 3. 显示器识别与恢复

- 匹配结果应区分“唯一匹配”“缺席”“歧义”，不能用不明来源的第一个数组元素冒充唯一匹配。
- 首选已保存的稳定显示器 UUID，且必须在当前屏幕列表中恰好匹配一块。唯一 UUID 命中时可忽略显示器名称、分辨率及排列变化，使用该屏当前 `visibleFrame` 恢复。
- UUID 不可用或旧记录没有 UUID 时，可使用现有显示器 ID、名称、像素尺寸作兼容判断，但**必须验证候选只有一块且信息不冲突**。同型号、同名、同像素尺寸产生两个候选时结果为“歧义”。不能因 UUID 找不到而盲用可能已复用的显示器 ID，亦不能只按名称取第一块屏。
- “缺席”或“歧义”时，把 HUD 临时放到当前可用主屏的当前布局默认位置，确保完整可见；**不写**永久记录。没有任何可用屏幕时不猜测坐标，等待下一次屏幕事件。歧义持续时停在主屏，等用户手动放置。
- 唯一目标重新可用时，用保存的 `relativeX`、`relativeY` 与该屏**当前** `visibleFrame` 计算 frame，并将完整 HUD 钳制在可见区域；完成后退出临时回退状态。无需把仅由分辨率变化算出的新绝对 frame 覆盖原相对位置。
- 首次运行没有位置记录时，放当前主屏默认位置，并保存当前布局的初始记录。损坏记录按现有日志规则报告并回到安全可见位置；不能把损坏数据误判为“用户已选择主屏”。旧绝对位置迁移仍按现有一次性转换规则处理。
- 旧 PRD 曾要求原屏缺席时立即保存主屏回退位置；本 PRD 对此条明确覆盖。其他原有规则，包括单 HUD、所有空间、全屏辅助、不抢焦点，保持有效。

### 4. 生命周期与屏幕事件

- 启动构建 HUD 时先尝试按永久记录恢复；原屏缺席就临时回退，等待屏幕变化。正常屏幕变化事件也重新检查目标，并应用唯一匹配／临时回退规则。
- 系统唤醒事件除现有会话完成态超时检查外，还要请求 HUD 位置恢复。唤醒后显示器列表可能分阶段更新：立即检查一次，并安排短时延后的复查，或把连续的屏幕变化通知合并为一次最终检查。复查必须以**当前**保存记录和**当前**屏幕列表为准；取消过期复查，避免用户在等待期间拖动后被旧任务又挪回。
- 程序化恢复使用不激活窗口的设 frame／显示方式；不得改变键盘焦点。位置操作仅在主线程执行。
- 在没有用户动作时，反复收到相同屏幕变化或唤醒事件，应保持相同保存记录和稳定 frame；不得发生主屏／外屏来回跳动。

### 5. 模块职责与实施顺序

1. **纯位置决策层：**输入当前布局的保存记录、可用屏幕身份和可见区域、主屏索引，输出“目标屏恢复”“临时主屏回退”“保持等待”之一以及目标 frame。显式输出是否可写永久记录，避免调用方自行猜测。
2. **显示器匹配层：**把“唯一／缺席／歧义”作为可测试结果；确定 UUID 优先与低可信标识的兼容条件。不把同型号屏幕的第一个匹配当作正确答案。
3. **HUD 控制器：**按决策执行位置变更；维护程序化移动和临时回退状态；记录真实拖动手势；修正当前恢复过程无条件保存及布局切换保存路径；保持显式重置行为。
4. **应用生命周期：**在唤醒和显示器参数变化时触发恢复与必要复查，确保旧复查不会覆盖新的手动位置。
5. **验证：**先跑纯逻辑和位置存储测试，再跑完整测试／构建，最后按下方场景人工验收真实双屏合盖。一个阶段的修复不得依靠改变 HUD 可见性、焦点策略或复制 HUD 实例。

### 6. 行为判定表

| 场景 | HUD 显示位置 | 永久记录 |
| --- | --- | --- |
| 原屏在，身份唯一 | 原屏原相对位置 | 不变 |
| 原屏断开／合盖期间不可用 | 主屏安全默认位置 | 保留原屏记录 |
| 原屏恢复，期间无用户拖动 | 自动回原屏原相对位置 | 原记录不变 |
| 原屏缺席，用户把临时 HUD 拖到主屏新位置 | 用户选定的新位置 | 改为主屏新记录 |
| 上一行后原屏重新出现 | 留在主屏用户选定位置 | 不变 |
| 启动时原屏缺席，后续连接 | 先临时主屏，后恢复原屏 | 全程保留原记录 |
| 原屏分辨率／排列改变但 UUID 唯一 | 原屏当前可见区域对应相对位置 | 相对坐标不变 |
| 两块候选同名同分辨率、无法唯一识别 | 主屏安全位置，等待用户 | 不猜测、不覆盖 |
| 程序化移动触发 `windowDidMove` | 按当前恢复决策显示 | 不因通知保存 |
| 用户点击“恢复 HUD 默认位置” | 当前主屏默认位置 | 保存为新选择 |
| 横向临时回退时改纵向布局 | 纵向记录对应位置；若无记录则安全默认 | 横向原屏记录不被临时 frame 覆盖 |

## Testing Decisions

- 自动测试只覆盖真实业务边界：匹配身份是否唯一、位置决策是否保存、拖动完成是否更新记录、唤醒／屏幕变化时重试与旧任务取消。不要编写仅检查私有标志或逐行镜像实现的测试。
- 扩充现有位置几何与存储测试：UUID 唯一优先、分辨率变化、缺席、不止一台同名同分辨率、旧记录无 UUID 的唯一兼容与歧义。断言目标屏、完整可见 frame、永久记录未改变。
- 为位置状态决策加入序列测试：原屏在 → 消失 → 临时主屏 → 恢复；消失 → 用户真实拖动 → 原屏恢复；启动缺屏 → 后续连接；临时回退 → 横竖布局切换；重复系统移动不保存。
- AppKit 手势和睡眠通知可通过可注入事件源或小型控制器测试验证外部保存结果；若无法稳定自动模拟真实屏幕，人工双屏验收是必须的，不以纯几何测试替代。
- 人工验收至少覆盖：外接屏拖动后合盖再开；断开外屏后主屏临时可见、重接恢复；断开期间在主屏手动拖动、重接不返回；应用在外屏未接时启动后再连接；调整分辨率／排列；横向与纵向各测一次；HUD 不抢键盘焦点。
- 运行相关 Swift 测试、完整 `swift test`、`swift build` 与 `git diff --check`，记录人工验收中实际显示器组合与结果。

## Out of Scope

- 不新增设置页中的屏幕选择器，也不增加每屏一个 HUD。
- 不实现跨不同物理设备同步 HUD 位置；仅处理本机显示器身份。
- 不保证 macOS 无法提供任何唯一身份信息且存在多块完全相同显示器时自动找回原物理屏；此时主屏等待用户操作。
- 不修改会话状态、最近动态置顶区、Hooks 或 HUD 轮播逻辑。

## Further Notes

- 本 PRD 供编码能力较低的执行者使用。若实现中发现 AppKit 的窗口拖动事件无法可靠区分真实用户拖动与系统移动，应先实现明确的 HUD 拖动手势，再接入保存；不可恢复 `windowDidMove` 直接保存的旧行为作为替代。
- 与旧位置规格有冲突时，以本 PRD 的“临时主屏回退不覆盖永久记录”为准。原始需求与逐问确认见顶部讨论纪要。

## 实现与验证记录

- 位置决策显式返回临时状态和是否保存；屏幕身份优先唯一 UUID，旧标识匹配有歧义时回退主屏。
- HUD 窗口内容层捕获真实鼠标按下并使用 AppKit 的窗口拖动操作，拖动结束且位置变化时保存；系统窗口移动回调不保存。横竖布局切换不再预保存临时位置。
- 唤醒和屏幕变化立即检查位置，并在 1 秒后用最新记录复查；新的屏幕事件、真实拖动和重置会取消旧复查。
- 相关位置测试 17 项通过；完整 `swift test` 共 139 项通过；`swift build` 和 `git diff --check` 通过。
- 当前环境未执行真实外屏拔插、合盖唤醒、AppKit 拖动手势与键盘焦点的人工验收；此项仍须在实际 macOS 多显示器设备上按本文清单验证。未部署应用。
