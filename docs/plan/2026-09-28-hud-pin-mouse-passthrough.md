# HUD 钉住与鼠标穿透 PRD

Related discussion: [docs/discuss/2026-09-28-hud-pin-mouse-passthrough.md](../discuss/2026-09-28-hud-pin-mouse-passthrough.md)

> 状态：开发与自动验证已完成，待真实桌面交互验收。本文增加 HUD 钉住状态和菜单入口，并移除设置菜单项的快捷键；不改变 HUD 的位置恢复、会话状态与轮播规则。

## Problem Statement

HUD 可以拖动，但也因此会挡住下方应用的点击与拖动。用户希望放好 HUD 后“钉住”它，让鼠标操作直接落到下方应用；需要调整位置时再从菜单取消钉住。

## Solution

在菜单栏现有下拉菜单中加入动态操作项。未钉住时显示“钉住 HUD”，钉住时显示“取消钉住 HUD”。钉住状态持久化；钉住时由 HUD 窗口忽略鼠标事件，取消后立即恢复鼠标交互。其他 HUD 功能继续工作。

## User Stories

1. 作为已摆好 HUD 的用户，我希望从菜单将它钉住，以便避免误拖动。
2. 作为使用 HUD 下方应用的用户，我希望点击 HUD 覆盖区域时由下方应用收到点击，以便正常工作。
3. 作为在下方应用拖动对象的用户，我希望拖动操作穿过 HUD，以便 HUD 不拦截手势。
4. 作为需要移动 HUD 的用户，我希望从菜单取消钉住后立即能拖动，以便重新摆放。
5. 作为重启应用的用户，我希望钉住状态保留，以便无需重复设置。
6. 作为首次使用的用户，我希望 HUD 默认可拖动，以便先选好位置。
7. 作为查看会话状态的用户，我希望钉住时文字、灯效和轮播继续更新，以便 HUD 仍有用。
8. 作为需要隐藏 HUD 的用户，我希望钉住时仍可用菜单隐藏或显示，以便控制可见性。
9. 作为需要重置位置的用户，我希望钉住时仍可通过设置恢复默认位置，以便不被锁在错误位置。
10. 作为多显示器用户，我希望钉住时显示器变化和合盖唤醒仍恢复 HUD 位置，以便窗口保持可见。

## Implementation Decisions

### 状态与存储

1. 使用一个布尔型“钉住”状态，首次无保存值时默认 `false`；写入现有用户偏好。读到非布尔异常值时按 `false` 处理，不能把任意字符串或数字误当作钉住。
2. 应用启动时先读取保存状态，再配置 HUD 窗口；HUD 第一次显示前必须已应用鼠标穿透状态，避免启动瞬间接收鼠标操作。切换后立即保存，新建或再次显示窗口仍按该状态配置。
3. 状态单一来源。菜单标题、持久化值和窗口是否忽略鼠标事件必须一致。不要分别维护互不关联的菜单布尔值与窗口布尔值。

### 菜单与窗口

1. 在菜单栏现有下拉菜单中加一个直接操作项，建议紧邻“隐藏／显示 HUD”。未钉住显示“钉住 HUD”；钉住显示“取消钉住 HUD”。不增加子菜单或设置页开关。
2. 点击菜单项只切换钉住状态，并立即改菜单标题和 HUD 窗口的鼠标事件处理；不隐式移动窗口、不隐藏 HUD、不改变会话选择。
3. 钉住时在**整个 HUD 窗口**启用 AppKit 的鼠标忽略能力，使单击、双击、鼠标按下、拖动、松手、滚轮等鼠标事件由系统送到下方应用。不要只禁用 SwiftUI 控件或将视觉透明度设为零；HUD 必须保持可见。
4. 取消钉住时关闭窗口的鼠标忽略能力，现有 `HUDDragView` 从下一次鼠标按下起恢复正常拖动。切换过程中若已有拖动手势，须清理该手势的暂存状态，避免残留“正在拖动”导致位置恢复停住或错误保存。
5. 钉住仅约束用户鼠标直接操作 HUD。代码控制的 HUD 隐藏／显示、恢复默认位置、横竖布局切换、唤醒／屏幕变化后的恢复、会话内容和灯效继续运行。HUD 继续不抢键盘焦点。
6. 鼠标穿透后用户无法从 HUD 本身取消钉住；菜单栏操作项始终可访问。HUD 隐藏时也允许切换钉住；再次显示立即按最新状态工作。

### 模块与顺序

1. **偏好层：**在现有 HUD 偏好模块加入钉住读写接口和独立键；保持旧用户偏好兼容。为默认值、异常值、保存后重载编写测试。
2. **应用状态与菜单层：**应用控制器持有或读取唯一钉住状态，增加菜单项及切换动作；显隐菜单当前行为不变。切换后同步标题和窗口状态，避免依赖菜单索引位置。
3. **HUD 窗口层：**启动配置和每次切换时设置窗口级鼠标穿透；钉住时不提交拖动位置；取消后可继续复用现有拖动路径。
4. **集成验收：**运行相关测试、完整 Swift 测试、构建和差异检查；在真实 macOS 桌面人工验证点击与拖动穿透。

### 给执行模型的接线清单

1. 在偏好模块定义单独的钉住键和两个公开操作：读取布尔值、写入布尔值。读取时检查存储值确实是布尔类型；缺失或类型错误返回 `false`。沿用现有偏好模块的 `UserDefaults` 注入方式，测试使用独立域，不能读写测试机的真实设置。
2. 在应用模型初始化时加载钉住状态，形成界面可观察的单一属性。属性变化时写回偏好。若选择把状态集中在应用控制器，也必须做到菜单标题与窗口状态从同一个值读取；不要让两处各自 `toggle()`。
3. 构建 HUD 窗口时立即把该状态赋给 `NSWindow.ignoresMouseEvents`。窗口 `orderFrontRegardless`、`orderOut`、设置页恢复位置、唤醒重试、横竖布局重建内容视图时，不能将其意外重置为 `false`。窗口是否可见与是否穿透是两个独立状态。
4. 菜单栏创建时保存钉住菜单项的直接引用或稳定标识。菜单项标题由当前状态计算；动作调用单一的状态切换入口，完成后更新 HUD 窗口属性和菜单标题。现有“隐藏／显示 HUD”菜单逻辑也应通过各自引用更新，不依赖 `menu.item(at: 0)` 在插入新项后仍处于原索引。
5. 钉住前若 HUD 拖动手势正在进行，不得让松手回调在钉住之后覆盖位置记录。实现可在切换时取消手势并忽略后续拖动／松手，也可先完成当前手势再钉住；必须选一种确定顺序并保持窗口和偏好最终一致。推荐取消手势并保留最后一次已保存的位置，随后启用穿透。
6. 取消钉住时仅关掉 `ignoresMouseEvents`，从下一次完整的鼠标按下手势开始允许拖动；不可把之前钉住期间从下层窗口发出的松手当作 HUD 拖动结束。
7. `ignoresMouseEvents` 影响的是 AppKit 对整块窗口的鼠标命中。不要用 `isEnabled`、`allowsHitTesting(false)`、降低层级或隐藏视图替代；这些方法不保证鼠标事件会送到下方应用。HUD 保持原 `nonactivatingPanel`、悬浮层级、所有空间与全屏辅助行为。

### 关键时序

1. **启动且已钉住：**读取保存值 → 创建 HUD → 创建时设置 `ignoresMouseEvents = true` → 首次显示 → 菜单标题为“取消钉住 HUD”。窗口不得短暂处于可点击状态。
2. **菜单钉住：**入口读取当前状态 → 取消 HUD 尚未完成的拖动 → 写入 `true` → 设置窗口穿透 → 将菜单标题改为“取消钉住 HUD”。完成时三者一致。
3. **菜单取消钉住：**入口读取当前状态 → 写入 `false` → 关闭窗口穿透 → 将菜单标题改为“钉住 HUD”。下一个鼠标按下才允许开始新拖动。
4. **钉住时显示器变化：**窗口照常程序化恢复位置；钉住状态和鼠标穿透不变；用户偏好中的 HUD 位置只遵循既有位置恢复规则保存。
5. **钉住时隐藏并切换：**隐藏状态下仍更新偏好与菜单；显示时应用当前钉住值，不使用上一次显示时的旧值。

### 判定表

| 操作与状态 | 菜单标题 | HUD 鼠标行为 | 保存状态 |
| --- | --- | --- | --- |
| 首次启动，无保存值 | 钉住 HUD | 可拖动 | 未钉住 |
| 点击“钉住 HUD” | 取消钉住 HUD | 点击和拖动穿透 | 钉住 |
| 钉住后重启 | 取消钉住 HUD | 启动首次显示即穿透 | 钉住 |
| 点击“取消钉住 HUD” | 钉住 HUD | 可拖动 | 未钉住 |
| HUD 隐藏时钉住或取消 | 随状态更新 | 再次显示按最新状态 | 随状态更新 |
| 钉住后点击设置中的恢复默认位置 | 取消钉住 HUD | 继续穿透，HUD 到默认位置 | 钉住 |
| 钉住后显示器变化或唤醒 | 取消钉住 HUD | 继续穿透，HUD 按现有规则恢复位置 | 钉住 |

## Testing Decisions

- 自动测试只覆盖有实际状态边界的偏好读写和切换结果，不编写与一行属性赋值完全相同的测试。可沿用现有 HUD 偏好测试的独立 `UserDefaults` 域，验证首次默认、异常存储、切换、重建偏好实例后的恢复。
- 菜单与窗口行为需在可运行的 macOS 应用中验收：打开菜单，观察标题与状态同步；在下方按钮／文本上方钉住 HUD，确认点击和拖动由下方应用接收；取消钉住后拖动 HUD，松手位置保持；隐藏再显示、重启、恢复默认位置、外屏变化后状态保持。
- 运行相关 `swift test --filter HUDPreferencesTests`、完整 `swift test`、`swift build` 与 `git diff --check`。在无法运行桌面交互的环境中，明确标注尚未完成的人工验收，不以构建成功代替鼠标穿透验证。

## Out of Scope

- 不增加 HUD 内的钉住图标、快捷键或设置页开关。
- 不改变窗口视觉、灯效、会话调度、跨屏位置保存格式或其他应用窗口的鼠标处理。
- 不让“钉住”阻止菜单命令或系统触发的位置恢复。

## Further Notes

- 用户确认使用动态标题的直接菜单项；“钉住”指窗口忽略鼠标事件，包含不可移动、不可点击和向下层应用穿透。
- 用户在集成阶段补充：设置菜单项不显示也不响应快捷键，仅通过菜单点击打开；移除该菜单项的 `keyEquivalent`。
- 本文按低智能编码模型执行编写；请按“偏好 → 单一状态 → 窗口 → 菜单 → 集成验收”的顺序实现，每一步核对判定表。不得仅改菜单文案而漏设窗口级鼠标穿透。
- 原始问答见顶部讨论纪要。
