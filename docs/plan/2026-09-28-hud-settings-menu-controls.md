# HUD 设置与菜单控制 PRD

Related discussion: [docs/discuss/2026-09-28-hud-settings-menu-controls.md](../discuss/2026-09-28-hud-settings-menu-controls.md)

> 状态：三个开发阶段与自动验证已完成，待真实桌面人工验收。菜单前两项采用固定文案加对勾。

## Problem Statement

用户在设置弹窗内看不到钉住开关，在菜单栏内无法直接切换 HUD 四种布局。显隐和钉住的菜单项使用动态动作文案，与用户希望的三个固定控制入口不一致。用户希望从设置和菜单都能快速查看并调整 HUD 可见、钉住与布局状态。

## Solution

设置弹窗“常规”分组顶部依次放置“显示 HUD”开关、“钉住 HUD”开关、“HUD 布局”四选一选择器。菜单栏下拉列表顶部按相同顺序放置“显示 HUD”“钉住 HUD”“HUD 布局”；前两项使用对勾表示开关状态，第三项展开二级菜单。二级菜单列出横向左、横向右、竖向上、竖向下，仅当前布局有对勾。所有入口直接读写应用现有唯一状态。

## User Stories

1. 作为用户，我希望在设置弹窗最上方看到三个 HUD 控制项，以便快速找到它们。
2. 作为用户，我希望在设置页切换显示状态，并看到菜单状态立即一致。
3. 作为用户，我希望在设置页钉住或取消钉住 HUD，以免必须切换到菜单操作。
4. 作为用户，我希望菜单中直接查看 HUD 是否显示、是否钉住，以便不必打开设置页。
5. 作为用户，我希望在菜单二级菜单中直接切换四种布局，以便快速调整桌面占用方向。
6. 作为用户，我希望当前布局只有一个对勾，以免误以为可同时启用多个布局。
7. 作为用户，我希望通过菜单改动布局后，设置页显示同一选项，HUD 立即切换并保留对应布局位置。
8. 作为用户，我希望隐藏 HUD 后仍能切换钉住和布局，下次显示时使用新状态。
9. 作为用户，我希望钉住时仍可通过菜单取消钉住，以便恢复拖动。
10. 作为用户，我希望重启后菜单和设置准确显示已保存状态。

## Implementation Decisions

### 设置页

- 在现有“常规”分组顶部插入“钉住 HUD”原生 Toggle；顺序为显示 HUD、钉住 HUD、HUD 布局。保留后续展示时长等行的原有顺序。
- 两个 Toggle 和布局 Picker 分别绑定既有可观察属性，不新增第二套开关或布局状态。
- 钉住开关在 HUD 隐藏时仍可用，因为钉住状态应为下次显示预设；布局选择同样保持可用。
- 不修改四种布局的名称和顺序，也不改变横向右默认值。

### 菜单栏

- 菜单开头依次为固定标题“显示 HUD”“钉住 HUD”“HUD 布局”。前两项点击时切换对应状态，勾选状态 `.on` 表示 true、`.off` 表示 false。布局父项仅展开子菜单，不直接切换布局。
- 子菜单按横向左、横向右、竖向上、竖向下顺序列出；点击某项把应用模型的布局设为对应四值。仅当前值为 `.on`，其他均为 `.off`；重复点击当前布局保持原值。
- “设置…”和“退出 Traceflow”保留在布局项之后；设置菜单项继续无快捷键。现有退出快捷键保持原样。
- 菜单打开前依据应用模型的最新状态刷新五类菜单项状态，不依赖某次设置页回调是否先到达。菜单项可保留稳定引用或标识，避免用脆弱的数组下标定位。
- 状态改变时也主动刷新已有菜单项：设置页、菜单项与程序启动的状态必须一致。菜单切换显隐只写一次模型属性，由现有模型观察者负责窗口显示或隐藏，不重复调用窗口动作。
- 菜单切换钉住后沿用现有窗口鼠标穿透处理；切换布局后沿用现有四布局位置恢复、拖动取消和透明度尺寸逻辑。
- 菜单使用 AppKit 原生 `NSMenu` / `NSMenuItem` 的子菜单及勾选状态；不在菜单中嵌入 SwiftUI 开关。

### 已确认文案决策

- 菜单前两项采用固定名称及对勾，已随本文获批确认。

## Testing Decisions

- 用应用测试核对设置页与菜单共享同一模型状态；选择布局后实际窗口布局变化，且菜单只有一项被选中。
- 对菜单状态更新建立轻量测试接口，覆盖首次创建、设置页改变后刷新、菜单点击、重启恢复、隐藏状态下改布局或钉住、重复点击已选布局。
- 验证显隐菜单动作只触发一次窗口显隐；钉住鼠标穿透和四布局独立位置继续运行既有回归测试。
- 运行 `swift test`、`swift build`、`git diff --check`。真实菜单二级展开、对勾呈现、设置窗口顶部排列及鼠标穿透需 macOS 桌面人工验收。

## 分阶段实施

1. 设置页：新增钉住开关并检查三个选项排列；运行设置相关构建或测试。
2. 菜单：增加布局二级菜单及统一状态刷新，移除显隐动作的重复窗口调用；运行菜单相关测试。
3. 集成：补双入口、重启与隐藏场景的回归测试，运行全量测试和构建并做人工验收清单。

## 低智能执行模型专用细则

### A. 先识别现有状态，禁止另建平行状态

| 控制项 | 当前唯一状态 | 已有持久化 | 设置页绑定 | 菜单操作 | HUD 窗口反应 |
| --- | --- | --- | --- | --- | --- |
| 显示 HUD | `AppModel.isHUDVisible` | `hudVisible` | `$model.isHUDVisible` | 对当前值取反 | `AppDelegate.visibilityObserver` 调用一次 `show()` 或 `hide()` |
| 钉住 HUD | `AppModel.isHUDPinned` | `HUDPreferences.pinnedKey` | 新增 `$model.isHUDPinned` | 对当前值取反 | `HUDPanelController.pinObserver` 改 `ignoresMouseEvents`，必要时取消拖动 |
| HUD 布局 | `AppModel.hudLayoutMode` | `HUDPreferences.layoutKey` | 现有 `$model.hudLayoutMode` | 赋值四值之一 | `HUDPanelController.layoutObserver` 恢复目标布局尺寸与独立位置 |

- `AppModel` 已加载并保存这三个属性。不要新增 `@State`、全局布尔值、第二个偏好键或菜单私有布局值作为真实状态。菜单项对象引用只用于显示。
- 当前设置页只有“显示 HUD”和“HUD 布局”；钉住需要插入其间。当前菜单有“隐藏／显示 HUD”“钉住／取消钉住 HUD”“设置…”“退出 Traceflow”；不要保留旧项同时再添加同名新项。
- `isHUDVisible` 为 false 只表示窗口隐藏；不把钉住开关或布局菜单禁用。钉住为 true 时窗口鼠标穿透，菜单仍是解除钉住的入口。

### B. 设置页逐项修改

1. 在 `SettingsView` 的 `Section("常规")` 最前面保持现有 `Toggle("显示 HUD", isOn: $model.isHUDVisible)`。
2. 紧接着加 `Toggle("钉住 HUD", isOn: $model.isHUDPinned)`，沿用系统 Toggle 样式，不加额外确认弹窗。
3. 紧接着保留原 `Picker("HUD 布局", selection: $model.hudLayoutMode)`，四项按横向左、横向右、竖向上、竖向下排列，tag 分别对应 `.horizontalLeft`、`.horizontalRight`、`.verticalTop`、`.verticalBottom`。
4. “展示时长”及后续设置保持原顺序。设置窗口已经打开时，从菜单修改模型属性应由 `@ObservedObject` 自动刷新这三行。

### C. 菜单结构与 AppKit 对象关系

期望层级如下，父项“HUD 布局”本身不带动作或勾选：

```text
显示 HUD          [选中时打勾]
钉住 HUD          [选中时打勾]
HUD 布局          >
    横向左        [仅选中值打勾]
    横向右        [仅选中值打勾]
    竖向上        [仅选中值打勾]
    竖向下        [仅选中值打勾]
设置…             [没有快捷键]
────────
退出 Traceflow     [保留既有快捷键]
```

1. 在 `AppDelegate.configureStatusItem()` 创建父菜单的三个顶部项目，顺序必须与设置页一致。把“HUD 布局”作为第三个 `NSMenuItem`，给它设置一个独立 `NSMenu` 作为 `submenu`，不要给父项设置业务切换 action。AppKit 安装子菜单后可能自动把父项的 `action` 变为内部的 `submenuAction:`，测试不得误判为布局切换 action。
2. 子菜单四项每项都设置对应选择 action 和 `target`。**现有** `for menuItem in menu.items { menuItem.target = self }` 只遍历父菜单，不会自动给子菜单项设置 target；子项必须逐个设定，或递归设置。
3. 子项使用稳定的 `representedObject`（四值的 `rawValue`）或明确映射，不通过显示标题、菜单索引推断布局。action 中校验值能解成 `HUDLayoutMode`，有效且不同于当前值才写 `model.hudLayoutMode`。父项不显示对勾。
4. 保存三个顶部菜单项及四个子项的稳定引用，或者封装一个接受模型快照并更新项目的菜单控制对象。勾选刷新不得重建整棵菜单，否则菜单正在展开时可能闪烁或丢失指向。
5. 设置菜单项继续 `keyEquivalent: ""`；退出菜单项保持现有 `"q"`。不为三个新控制项增加快捷键。

### D. 菜单状态判定表与刷新时机

| 模型值 | 顶部菜单显示 | 顶部菜单钉住 | 布局子菜单 |
| --- | --- | --- | --- |
| `isHUDVisible == true` | “显示 HUD”，`.on` | 由钉住值决定 | 由布局值决定 |
| `isHUDVisible == false` | “显示 HUD”，`.off` | 由钉住值决定 | 由布局值决定 |
| `isHUDPinned == true` | 由显隐值决定 | “钉住 HUD”，`.on` | 由布局值决定 |
| `isHUDPinned == false` | 由显隐值决定 | “钉住 HUD”，`.off` | 由布局值决定 |
| 任一四值布局 | 由显隐值决定 | 由钉住值决定 | 恰好对应的一项 `.on`，另外三项 `.off` |

- 菜单初建完就刷新一次，确保重启后第一眼看到正确勾选状态。每次菜单将要显示时再从 `model` **当前已存储的值**刷新一次，以处理设置页改值及可能的回调时序。可使用 `NSMenuDelegate.menuNeedsUpdate(_:)` 或等价的菜单即将打开回调；若使用代理，保留代理对象生命周期。
- 订阅现有显隐与钉住发布值，并新增布局发布值，用于菜单已打开或即将再次打开时及时更新。`@Published` 的 sink 可能早于属性真正赋值：若在 sink 中刷新单个勾选，应使用回调参数；若集中读取 `model` 三个属性，则延迟到主队列下一轮，并核对最新值。不要在 sink 中立刻读取对应属性又写回旧勾选。
- 布局子菜单刷新时，逐项对比 `HUDLayoutMode`，每次明确赋 `.on` 或 `.off`，不能只给当前项打勾而忘记清掉旧项。
- 点击显隐菜单只执行 `model.isHUDVisible.toggle()`；**删掉**当前 `toggleHUD()` 中直接调用 `panelController.show()/hide()` 的两行，保留 `visibilityObserver` 作为唯一窗口显隐调用者。点击钉住菜单只执行 `model.isHUDPinned.toggle()`；不能直接操作窗口 `ignoresMouseEvents`。点击布局子项只修改 `model.hudLayoutMode`；不能直接改窗口 frame 或持久化位置键。

### E. 事件顺序和边界场景

1. **菜单点击显隐：**菜单 action 改模型一次 → 模型保存偏好 → 显隐观察者改变窗口一次 → 菜单勾选同步；设置页开关自动同步。菜单和设置改值都走同一观察者。
2. **菜单点击钉住：**action 改模型一次 → 模型保存偏好 → HUD 窗口既有 pin 观察者切换鼠标穿透；若正在拖动，沿用现有取消手势与恢复已存位置流程。设置页开关自动同步。
3. **菜单点击布局：**action 改模型一次 → 模型保存偏好 → 窗口既有延迟布局观察者按最新值切换；菜单只重绘勾选。快速点不同子项时，旧延迟任务不得覆盖最终布局。关闭设置页也应生效。
4. **HUD 已隐藏：**仍可在菜单或设置修改钉住、布局；不因修改而把 HUD 意外显示。再次选择“显示 HUD”时应用最新状态，位置仍是目标布局自己的记录。
5. **已选布局再次点击：**不重新触发布局切换、拖动取消、位置恢复或写偏好；菜单保持单个对勾。
6. **重启：**模型先读取持久化显隐、钉住和布局，菜单初始化后据此打勾；不是一律默认勾选横向右。

### F. 最小可验证测试矩阵

| 场景 | 预期 |
| --- | --- |
| 默认新用户首次打开菜单 | “显示 HUD”有勾，“钉住 HUD”无勾，横向右有且仅有一个布局勾 |
| 从设置关闭显示，再打开菜单 | “显示 HUD”无勾，窗口隐藏，其余两个菜单仍可操作 |
| 从菜单开启显示 | 设置开关变开，窗口只显示一次 |
| 从设置钉住，再开菜单 | “钉住 HUD”有勾，HUD 鼠标事件被忽略 |
| 从菜单取消钉住 | 设置开关变关，HUD 可再次拖动 |
| 从菜单选竖向上，再看设置 | 设置选竖向上，子菜单仅竖向上有勾，HUD 呈竖向上布局 |
| 菜单连续选横向左、竖向下 | 最终布局及勾选都是竖向下，旧异步切换不回跳 |
| HUD 隐藏且钉住时改布局 | HUD 保持隐藏和钉住，再显示后使用新布局 |
| 点击当前已选布局 | 状态与位置不变，没有重复切换副作用 |
| 保存状态后重启 | 三种勾选、设置值及 HUD 行为与保存状态一致 |

- 优先用现有 `TraceflowAppTests` 的独立 `UserDefaults` 域及 AppKit 测试方式验证菜单模型和动作。若 `AppDelegate` 的私有模型阻碍测试，可提取小型菜单状态控制器或增加测试注入入口；不要为了测试构造第二套真实业务状态。
- 实际屏幕上还需检查二级菜单箭头、当前布局对勾、设置窗口前三行、菜单开启与关闭 HUD、钉住后的鼠标穿透。单元测试无法证明 macOS 菜单视觉与实际鼠标行为。

### G. 完成定义

- 设置页与菜单栏都能控制同一三个属性；菜单父项及四项子菜单的位置、文案、勾选规则完全符合上表。
- 不新增旧“隐藏 HUD”“取消钉住 HUD”重复菜单项；不存在两个入口状态不一致或显隐动作重复执行。
- 四布局位置、钉住、透明度及会话功能通过既有回归测试。全量 `swift test`、`swift build`、`git diff --check` 通过；真实桌面验收结果单独记录。

## Out of Scope

- 不改变 HUD 四种布局的实际排列、灯组顺序、独立位置记录、透明度 80% 图标隐藏阈值。
- 不新增快捷键、自动布局选择、自动取消钉住或新的持久化键。
- 不改会话列表、状态灯、Hooks 及设置页其他分组。
