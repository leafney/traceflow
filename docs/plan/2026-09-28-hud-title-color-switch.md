# HUD 标题颜色切换 PRD

Related discussion: [docs/discuss/2026-09-28-hud-title-color-switch.md](../discuss/2026-09-28-hud-title-color-switch.md)

> 状态：开发与自动验证已完成，待真实桌面视觉与交互验收；本版只支持手动黑／白选择。

## Problem Statement

HUD 背景透明度较高时，黑色标题放在深色窗口或壁纸上不易辨认。用户需要快速选择适合当前背景的标题颜色。

## Solution

在常规设置的“背景透明度”旁增加“标题颜色”Switch。Switch 左侧标“黑色”、右侧标“白色”；默认黑色。切换后横向和纵向 HUD 标题立即变色并保存，重启恢复。用户自己决定颜色，不根据透明度、系统深浅模式或屏幕背景自动切换。

## User Stories

1. 作为使用高透明度 HUD 的用户，我希望将标题切为白色，以在深色背景上读清文字。
2. 作为在浅色背景上使用 HUD 的用户，我希望切回黑色，以保持文字对比度。
3. 作为第一次使用的用户，我希望默认黑色，以获得已确认的初始设置。
4. 作为重启应用的用户，我希望保留自己选的颜色，以免重复设置。
5. 作为横向或纵向 HUD 用户，我希望两种布局颜色一致，以免切换方向后恢复旧色。
6. 作为暂无会话的用户，我希望占位标题仍使用选定颜色，以保持规则一致。
7. 作为纵向长标题用户，我希望截断省略号也使用选定颜色，以免末尾出现另一种颜色。
8. 作为使用钉住和透明度功能的用户，我希望切换标题颜色时位置、鼠标穿透、背景、图标和状态灯维持原有状态。

## Implementation Decisions

### 偏好与状态

- 新增仅有 `black`、`white` 两值的标题颜色偏好，默认 `black`。使用独立 UserDefaults 键，不复用背景透明度或系统外观设置。
- 缺失或未知存储值回退黑色；写入使用稳定原始值。已有用户没有该键时直接采用黑色，不改写其他偏好。
- 应用模型暴露可观察的唯一颜色状态；切换立即保存。HUD 横向、纵向标题与设置 Switch 都从该状态读取，不另存颜色副本。
- 选择白色后即使透明度调低或系统切到浅色模式，也保持白色；黑色同理。用户明确要求手动选择，本版不提供自动模式或对比度判断。

### 设置界面

- 放在常规设置的“背景透明度”滑块旁，标题为“标题颜色”。使用原生 SwiftUI Switch/Toggle，不使用菜单或自由颜色选择器。
- 左侧静态文字“黑色”，右侧静态文字“白色”；关闭对应黑色，开启对应白色。两侧文字清晰可见，不能只靠开关颜色表达当前值。为辅助技术提供含当前选择的标签／值。
- 点击或键盘切换时立即更新 HUD 并同步保存，不增加“应用”按钮。

### HUD 绘制

- 横向会话标题和“Traceflow”占位标题显式指定不透明黑色或白色，不再依赖 SwiftUI 环境 `.primary` 颜色。
- 纵向标题将颜色作为 `VerticalMixedTitleView` 输入，传给底层 AppKit 视图；颜色变化即使标题字符串不变也必须触发重绘。Core Text 的字形和用于截断的三个省略点使用同一指定颜色，不能留 `NSColor.labelColor`。
- 保持字体、位置、截断规则、标题动画、背景透明度、图标与状态灯原样。不要在 HUD 根视图上统一设置文字色导致图标跟着变化；颜色只作用于标题组件。

### 实施接线清单

1. 在 HUD 偏好模块定义颜色枚举及读写方法，沿用现有可注入 UserDefaults 的方式。
2. 应用模型初始化时先读取颜色，HUD 首次创建时使用正确颜色。属性变化时保存偏好。
3. 在常规设置的背景透明度附近添加 Switch 行。Binding 的开关值从颜色枚举映射，开切白色、关切黑色；避免再维护独立布尔变量。
4. 横向标题在 `Text` 自身设置颜色。纵向视图新增颜色输入，并在 `updateNSView` 更新底层视图颜色；底层颜色 `didSet` 应置 `needsDisplay = true`，独立于标题 `didSet`。
5. 检查纵向 `draw` 中的字形属性和省略号填充色；两者都用传入颜色。横向的标题过渡中新旧标题也从同一状态得到颜色。
6. 切换时不得重建 HUD 窗口、改变窗口 frame、重置拖动参考框或覆盖透明度设置；无需触发位置恢复。

## Testing Decisions

- 使用独立 UserDefaults 域测试默认黑色、保存白色后重载、切回黑色、无效存储值回退；不读取测试机真实偏好。
- 对纵向绘制验证颜色变化会触发视图重绘，以及字形和省略号共用颜色；如果现有测试目标无法导入 App 目标，可以采用精简的可测试颜色映射与必要的构建／人工检查，不为一行 SwiftUI 修饰符编写镜像测试。
- 运行相关测试、完整 `swift test`、`swift build`、`git diff --check`。
- 在真实 macOS 桌面人工检查黑／白两色、横向／纵向、占位标题与省略号、深浅背景、重启恢复，以及透明度 10%／50%／100% 下的效果。构建成功不代表视觉可读性已经实机验收。

## Out of Scope

- 自动读取 HUD 下方画面、屏幕录制权限、亮度采样、防闪烁阈值与自动配色。
- 自定义任意颜色、描边、阴影、对比度告警或自动建议。
- 图标、状态灯、设置页普通文字及 HUD 背景的颜色变化。

## Further Notes

- 用户明确本版先手动实现，自动背景识别留待后续需求。
- 默认黑色是本次对话确认的产品规则；即使当前环境文字色可能随系统外观变化，新实现也应按显式黑／白设置执行。
