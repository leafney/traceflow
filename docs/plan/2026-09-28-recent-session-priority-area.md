# 最近动态会话置顶区 PRD

Related discussion: [docs/discuss/2026-09-28-recent-session-priority-area.md](../discuss/2026-09-28-recent-session-priority-area.md)

> 状态：用户已批准，实施中。实施前须完整阅读本文。本文中的“置顶”只指设置页的快速选择区域，不改变 HUD 轮播优先级或项目列表排序。

## Problem Statement

现有设置页按项目折叠会话。新会话如果没有触发 Traceflow Hook，需要用户先点“同步 Codex 会话”，再找到对应项目、展开并启用。即使 Hook 已发现，用户仍可能要在项目列表里查找。用户希望打开设置后直接看到最近有动态的会话，并快速切换“参与 HUD”。

## Solution

设置页会话部分固定分为“置顶区”和“会话区”。置顶区跨项目平铺最近 10 分钟有真实动态的所有会话，按动态时间倒序；每条显示会话与项目，并在右侧提供“参与 HUD”开关。应用打开设置时立即自动读取 Codex 最近会话，窗口保持打开期间每 15 秒再读取；Hook 事件仍即时更新。会话区保留原有完整项目列表、删除操作和手动“同步 Codex 会话”按钮。置顶项超时自动移出，原记录和 HUD 开关不变。

## User Stories

1. 作为刚打开设置的用户，我希望直接看到最近动态的会话，以便不用先点同步。
2. 作为正在运行新会话的用户，我希望 Hook 事件后立即看到它，以便马上启用 HUD。
3. 作为未触发 Hook 的 Codex 用户，我希望设置页自动发现最近会话，以便不用手动同步。
4. 作为持续打开设置的用户，我希望新会话在约 15 秒内出现，以便及时选择。
5. 作为跨项目工作的用户，我希望置顶区按会话平铺，以便一次查看所有最近动态。
6. 作为有同名会话的用户，我希望置顶项显示所属项目，以便识别。
7. 作为有很多近期会话的用户，我希望全部符合条件的会话可见，以免被数量上限隐藏。
8. 作为要快速启用 HUD 的用户，我希望直接切换置顶项右侧的开关，以便一步完成。
9. 作为已启用会话的用户，我希望它也出现在置顶区，以便查看或关闭。
10. 作为从项目列表操作的用户，我希望两处开关同步，以免状态不一致。
11. 作为查找历史会话的用户，我希望下方项目列表完整保留，以便继续使用原有管理方式。
12. 作为需要导入全部历史会话的用户，我希望手动同步按钮仍可使用，且位于会话区。
13. 作为关注最近动态的用户，我希望置顶项在 10 分钟无动态后自动移出，以免列表积累旧项。
14. 作为已启用 HUD 的用户，我希望移出置顶区不关闭 HUD，以免影响展示。
15. 作为查看执行中会话的用户，我希望“执行中”本身不会让无新事件的会话永久置顶。
16. 作为删除会话记录的用户，我希望它在两处立即消失，且当前应用运行期间不会马上被自动导入。
17. 作为重新启动应用或手动同步的用户，我希望之前删除的会话可以重新出现。
18. 作为暂时没有近期会话的用户，我希望仍看见置顶区标题和空态，以便知道功能在工作。

## Implementation Decisions

### 一、数据含义与时间边界

1. 为持久化会话增加独立的可选时间 `lastActivityAt`，只表示最后一次**真实动态**。不要直接用现有 `lastUpdatedAt`：完成态自动超时会修改它。不要用 `settingsListSortAt`：它用于项目列表稳定排序，不会随所有动态更新。
2. 接受 Hook 事件时，把应用事件的接收／应用时间写入 `lastActivityAt`。沿用现有拒绝重复、乱序、内部来源和 `compact` 事件的判定；被拒绝的事件不能更新时间。
3. 从 Codex App Server 读取摘要时，用原始 `updatedAt` 更新 `lastActivityAt`，取现有值与 `updatedAt` 较晚者；不能用“本次同步时间”代替。重复读取相同摘要不能把旧会话重新置顶。
4. 手动切换“参与 HUD”、项目批量开关、自动完成态超时、展开／折叠项目、自动同步本身，不得修改 `lastActivityAt`。
5. 旧持久化记录缺少此字段时解码为 `nil`，不把旧 `lastUpdatedAt` 推断成真实动态。之后接受 Hook 或读取 Codex 摘要即可补齐。保持现有存储文件可读；必要时按现有存储版本机制做兼容，不要求用户清空旧数据。
6. 置顶资格：给定 `now`，只有 `lastActivityAt != nil` 且 `0 <= now - lastActivityAt < 600 秒` 才入选。刚好 600 秒时移出；未来时间不入选，避免时钟异常导致长期置顶。新的真实动态重新计算 10 分钟窗口。
7. 排序：`lastActivityAt` 较新的在前；同一时间按会话 ID 字典序稳定排序。不限数量。筛选与排序不使用项目名、HUD 开关、运行状态。
8. 把上述资格与排序封装成纯逻辑模块，输入会话集合和可注入的 `now`，输出置顶会话。它不读系统时钟、不修改会话、不控制界面。

### 二、自动发现与手动同步

1. 每次打开设置窗口都立即发起一次**最近会话自动发现**，包括关闭后再次打开同一个窗口；不能只在第一次创建窗口时发起。即使当前已显示本地置顶项，也继续后台刷新。
2. 窗口可见期间，以约 15 秒为间隔再次发起最近会话自动发现。窗口关闭／隐藏后停止周期请求；再次打开立即发起。复用应用已有定时检查并做时间门控，不在每次 0.25 秒 `tick` 中启动请求，不新增高频定时器。
3. 自动发现只读取并合并 `updatedAt` 落在当前最近 10 分钟内、且来源符合现有来源策略的 Codex 会话；旧历史会话不能因自动发现被首次批量导入。现有已保存历史会话继续保留。手动“同步 Codex 会话”仍读取并合并全部允许的会话。
4. Codex 请求当前按 `updated_at` 降序、每页 100 条读取。新增“最近会话”读取入口时，共用现有启动、握手、超时、解码、去重和来源策略；从第一页开始翻页，遇到更新时间已早于或等于截止点的分页可停止。仍需过滤页面内旧项，不能把整页全部导入。手动全量入口保持现有全分页行为。若服务端顺序不可信，应继续扫描剩余页以保正确性，不能错漏近期会话。
5. 自动与手动同步共用单次请求闸门：同一时刻最多一个 Codex 读取。自动请求运行时用户点击手动同步，记录一次“待执行全量同步”，当前请求结束后立即执行；手动请求运行时跳过自动请求，因为全量结果已覆盖近期发现。重复定时触发不排队。同步完成后再安排下一次 15 秒自动检查，避免慢请求造成紧密循环。
6. 手动同步结果可以让最近 10 分钟会话进入置顶区，但其旧历史会话只出现在会话区。同步失败不删除已有记录，也不清空置顶区；手动错误继续使用会话区原有状态提示。自动发现失败只显示非阻塞的简短提示，不弹框；下一轮继续尝试，不能覆盖用户刚收到的手动同步结果文案。
7. Hook 实时接受事件后，直接刷新置顶区，不等待自动发现。自动同步较晚返回时，合并 `lastActivityAt` 取最大值，不能覆盖较新的 Hook 动态或用户刚切换的 HUD 开关。用于置顶筛选的时间必须来自事件或摘要本身，而非网络响应完成时间。

### 三、删除、清空与恢复

1. 置顶项没有删除按钮。下方会话区的删除按钮继续使用原确认流程；确认删除后立即从项目列表和置顶区移除该 ID，并更新 HUD 调度。
2. 为自动发现设置**仅内存有效**的删除抑制表，以会话 ID 为键，过期时间为确认删除时间加 600 秒。抑制有效期间，自动 Codex 发现和 Hook 事件都不重新创建该 ID；其他会话照常处理。到期清理抑制表，若 Codex 此时仍报告最近动态，可再次出现。不要写入磁盘。
3. 用户主动点击“同步 Codex 会话”时，发起不受删除抑制限制的全量读取；读取成功后，在合并全量结果前清除删除抑制，因此可以立即恢复记录。读取失败时保留删除抑制，不恢复已删除记录。应用重启后内存表自然消失，打开设置即可自动恢复符合最近条件的记录。
4. “清空全部记录”仍清空原有所有会话；为当前已知 ID 同样设置短期自动发现抑制，避免 15 秒后立即回填。手动同步或重启仍可恢复。现有清空确认文案可补一句说明此恢复规则。
5. 删除与自动请求并发时，自动响应合并前再次检查抑制表；在请求进行中删除也不能被旧响应重新写回。手动同步若被自动请求排队，应在执行全量合并时明确清除抑制。

### 四、设置页结构与交互

1. 将现有单个“会话”区域拆为两个按顺序排列的区域，标题准确使用“置顶区”和“会话区”。两个标题始终可见。置顶区位于会话区上方；同步按钮、同步状态消息、项目分组、项目开关、每条会话的删除按钮、清空按钮均位于会话区。
2. 置顶区为空时，标题下显示“最近 10 分钟没有动态”。若正在首次自动发现，可同时展示轻量加载提示；完成后按实际结果替换。自动失败时保留已有列表或空态，并补简短失败提示。不要弹出打断操作的对话框。
3. 置顶区每条为**会话行，不是项目分组**：展示会话标题、所属项目名、最后动态时间、现有运行状态，右侧放“参与 HUD”开关；不显示删除按钮。项目名优先现有项目名称，缺失时用“未知项目”；必要时悬停可查看完整项目路径。列表不设人工条数上限，也不新增批量开关。
4. 置顶项开关放在**右侧**。这是用户在最终问答中对最初“左侧”要求的修订，仅适用于无删除按钮的置顶行。下方原会话行继续保持左侧开关、右侧删除按钮。两个位置调用同一按会话 ID 的设置方法，读取同一真实状态，任何一处切换后两处立即更新；数据不可写时沿用原有禁用规则。
5. 置顶行应有明确的开关无障碍标签，包含会话标题与“参与 HUD”；重复标题可用项目名或 ID 辅助区分。会话标题继续使用现有摘要／Codex 名称／“未命名会话”降级规则。
6. 窗口可见期间，至少每秒重新计算一次置顶资格，使没有新事件时也能在 10 分钟边界后自动移出；避免每 0.25 秒无条件发布整个列表。窗口重新打开时立即用当前时间计算，避免睡眠后显示过期项。移出只改变置顶显示，不修改 HUD 启用状态、持久化记录、项目排序或轮播状态。
7. 原项目列表保留所有未删除记录，包括置顶区正在显示的会话；原项目展开状态、整组开关、排序规则和手动同步入口继续工作。最近动态字段不用于重排原项目列表。

### 五、实施顺序与逐步验收

1. **数据层：**增加独立真实动态时间与旧数据兼容；Hook 接受路径更新它，超时路径不更新。先验证持久化读写与事件时间语义。
2. **纯筛选层：**实现注入 `now` 的 600 秒筛选与稳定排序，验证边界、跨项目、无限条数、已启用项及未知时间。
3. **读取层：**实现 Codex 最近分页读取，保持全量读取入口；只合并近期项。验证分页截止、过滤、去重和旧项不回填。
4. **应用协调层：**接入打开即发现、可见时 15 秒间隔、单请求闸门、手动同步优先、失败重试、删除抑制、Hook 即时刷新、睡眠恢复后的时间重算。每完成一项，核对 HUD 开关仍由原方法驱动。
5. **界面层：**拆成置顶区和会话区，移动同步按钮；置顶项复用会话标题和状态表达，但独立行布局实现右侧开关、项目提示和无删除按钮。保留下方原项目行操作。
6. **集成验收：**按下表逐项人工验证，再运行相关业务逻辑测试和 Swift 构建。每个阶段不得通过改动 HUD 轮播算法来实现设置页置顶。

### 验收判定表

| 场景 | 预期 |
| --- | --- |
| `now=12:00:00`，动态时间 `11:59:59` | 入选置顶 |
| 动态时间 `11:50:01` | 入选置顶 |
| 动态时间 `11:50:00` | 不入选；刚好 600 秒到期 |
| 动态时间晚于 `now` 或未知 | 不入选 |
| 同项目与跨项目混合、超过 100 条近期会话 | 全部显示，按动态时间倒序；同一时间按 ID 稳定排序 |
| 会话已启用 HUD | 仍入选；置顶右侧开关为开，下方左侧开关为开 |
| 未启用新会话收到 Hook | 立即出现在置顶区，开关默认关 |
| 未触发 Hook 的新 Codex 会话 | 打开设置后自动读取；窗口保持打开时下一轮约 15 秒内发现 |
| 手动开关、项目批量开关、自动完成态超时 | 不延长置顶 10 分钟时间 |
| 会话仍为“执行中”，但 600 秒无动态 | 从置顶区移出；下方记录与 HUD 开关不变 |
| 置顶项从下方项目行删除 | 两处立即消失；自动响应即使稍后返回也不恢复 |
| 删除后当前进程内自动发现 | 600 秒抑制期内不恢复；手动全量同步成功可恢复 |
| 删除后应用重启 | 抑制消失；最近动态仍有效时自动发现可恢复 |
| 自动读取失败 | 现有列表保持，提示非阻塞；下一轮重试 |
| 手动同步与自动请求重叠 | 无并行 Codex 请求；手动全量最终执行且不会被旧响应覆盖 |

## Testing Decisions

- 仅为时间边界、分页筛选、同步协调、删除抑制、旧数据兼容等业务逻辑与复杂状态变化写自动测试；界面排版、开关左右位置和空态做人工验收。测试断言用户可观察结果，不绑定私有数组或定时器内部结构。
- 纯筛选模块使用注入的固定 `now` 覆盖 599.999 秒、600 秒、未来、缺失时间、同时间排序、跨项目、已启用和大量结果；不得依赖真实等待 10 分钟。
- 持久化测试覆盖旧记录缺少新字段可读，新 Hook／App Server 更新时间被保存并可恢复，以及自动完成态超时不更新真实动态时间。沿用现有会话存储和状态机测试方式。
- Codex 读取测试使用可控分页响应覆盖 100 条分页边界、截止点同秒、来源过滤、重复 ID 和手动全量不受限制；可复用现有 App Server 测试设施。
- 同步协调测试覆盖打开、关闭、再次打开、15 秒门控、自动／手动重叠、自动失败重试、删除时响应正在路上、手动恢复、重启不持久化抑制。优先抽出可注入时钟与读取客户端的协调逻辑，避免依赖真实 Codex 进程。
- 验证方式：运行相关 Swift 测试、完整 `swift test`、`swift build`、`git diff --check`；随后在设置页人工检查两区、左右开关、项目名、空态、删除及到期移出。

## Out of Scope

- 不改变 HUD 轮播的状态优先级、时长、动画或是否参与的默认值。
- 不把置顶区作为持久化项目分组，不增加置顶数量限制、人工固定置顶、批量启用或置顶项删除入口。
- 不让自动发现批量导入旧历史会话；全部历史仍由会话区手动同步。
- 不对已删除记录做跨重启的永久屏蔽；不删除 Codex 原始会话。

## Further Notes

- 用户明确将本文交给低智能编码模型。实施时按“数据层 → 筛选层 → 读取层 → 协调层 → 界面层”推进，逐条核对验收表，不要只画出置顶区而遗漏自动发现、到期清理和删除后的重新导入竞态。
- 讨论原文与逐问回答见顶部 `Related discussion`。若实现发现现有 Codex API 排序不满足安全提前停止，正确性优先：扫描所有页后在本地过滤近期项。
