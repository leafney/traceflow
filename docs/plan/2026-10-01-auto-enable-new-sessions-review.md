# 新会话自动启用：部署前审查与修复方案

审查日期：2026-10-01
审查范围：7557921、4eaae8d、d22fca3、379db13，以及偏好、自动发现、手动同步、Hook、持久化和 HUD 调度的关联路径。
对应规划：[原 PRD](2026-10-01-auto-enable-new-sessions.md)。

## 结论

未发现本次改动引入的确定性功能代码错误。默认关闭、偏好保存、两类自动入口、手动同步排除、已有项保护及标题开关均已接入。发现一处规格/验收表述不一致、一处长期回归覆盖缺口，以及真实运行验收尚未完成。不能把“所有阶段完成”解释为全部部署前验收已完成。

本轮重新执行导入器、Hook 工厂与 HUD 调度相关测试，共 43 项通过、零失败。本轮只审查并编写修复方案，没有修改生产代码、测试代码或部署。

## 一、中优先级：启用与实际展示的验收条件不一致

证据：

- AppModel 的 mergeCodexThreads 对首次导入项创建 state 为 idle 的状态机。
- CarouselScheduler 的 eligibleIDs 要求参与值为 true 且 state 不为 idle。
- SessionStateMachine 的 SessionStart 事件也保持 idle。
- 原 PRD 的 HUD 条款及验收表写了“没有其他启用项时显示新项”，没有注明新项必须具有可展示状态。

复现场景：打开总开关，仅由自动发现导入一个新会话，且没有后续 Hook。行内开关为开启、记录参与值为 true，但会话待机，HUD 仍显示占位。只有 SessionStart 的 Hook 新项也具有相同表现。

这是既有调度规则与文档表述的冲突，不能据此断定调度器实现错误，也不能通过伪造 running 状态解决。已批准 PRD 同时明确要求保持调度规则和真实运行状态。

修复方案：

1. 将 PRD 条款改为“自动启用代表保存参与资格；待机项不展示，后续收到运行、等待权限或完成事件后按现有调度参与展示”。
2. 将验收条件拆成“只有启用待机项时显示占位”和“只有启用且非待机项时显示新项”。
3. 增加串联导入器/工厂、状态机、调度器的业务测试：自动新增 idle 项启用但不显示；收到 userPromptSubmit 后参与展示；SessionStart 项启用但保持占位。不得只重复现有 idle 过滤单元测试。
4. 若产品要求待机新项也立即展示，这属于变更既有调度规则，需先调整 PRD 并获得明确批准，不属于本轮直接修复。

## 二、中优先级：应用入口的关键验证没有长期回归保护

证据：长期新增测试位于 Core 测试中。testAutomaticImportDoesNotEnablePreviouslyImportedSession 直接传 false/true 给导入器，没有调用 AppModel 的 isManual 判断。临时应用入口验收驱动已移出测试目标。

风险：如果以后将 AppModel 的 `!isManual && autoEnableNewSessions` 错改为仅使用 autoEnableNewSessions，手动同步会错误启用历史项，而当前 Core 测试仍会通过。请求途中切换、总开关切换不修改已有项、两个入口同 ID 的行为也缺少持久的应用层防护。

修复方案：将临时验收中的关键场景整理为可重复的应用集成测试/验收脚本，纳入仓库并记录执行命令。优先通过现有 public/internal 应用入口和实际 socket 验证，不公开 private 方法，不增加生产测试专用入口。采用已有 TRACEFLOW_HOME、独立 UserDefaults suite、动态临时目录与模拟服务；不能依赖本机固定 `/private/tmp/tf-auto-qa`、残留 marker 文件或个人 shell 配置。

最低覆盖：自动新增两种开关值、手动新增始终关闭、手动新增后 Hook 不覆盖、请求途中切换以合并值为准、总开关不修改已有项、同 ID 两入口先后处理不覆盖选择。需要等待异步事件时按事件 ID/更新时间判断真正处理完成，不能只因会话原本就是 running 就提前通过。

## 三、部署验收缺口：真实操作与跨进程恢复尚未验证

已验证：真实 SettingsView 的深浅色空态渲染、模型绑定变化、模拟会话服务返回、实际 socket 接收、同进程新建模型读取保存数据。

尚未验证：鼠标/键盘操作标题开关、真实 Codex 会话发现与 Hook、退出应用进程后重启恢复、VoiceOver 操作。这些属于验证缺口，不是已证实的代码缺陷。

完成方案：使用隔离的应用数据与独立设置域，在真实进程中点击开关、退出并重新启动；检查总开关及单项选择恢复。另用受控的新 Codex 会话分别验证 Hook 与自动发现，确保两入口不会互相替代验证。检查焦点、空格键切换和可访问性名称。未具备真实服务环境时明确保留该验收项，不能以模拟服务结果声称真实环境已验证。

## 建议执行顺序

1. 修正文档中的待机展示条件，不改现有业务规则。
2. 补充长期回归保护及串联 HUD 状态测试，运行相关测试及完整测试。
3. 完成真实进程交互与重启验收，记录真实 Codex 验证结果。
4. 满足以上条件后再进入部署。
