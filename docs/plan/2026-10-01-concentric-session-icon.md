# 深蓝同心多环应用图标

日期：2026-10-01
状态：用户已批准，按阶段连续实施。

## 问题

Traceflow 缺少专属应用图标，菜单栏使用通用心电波形符号，难以表达同时管理多个会话的特点。需要一个紧凑、易辨识且与红黄绿状态提示呼应的标识。

## 方案

采用用户选择的 C1-A 深蓝同心多环。三个环表示多个会话，每个环带三个灯位，分别突出红、黄、绿亮灯，表达多个会话可以处于不同状态。应用程序和访达使用彩色图标，菜单栏使用相同结构的单色简化图形。

选定预览：`docs/design/icon-concentric.html` 中 C1-A。保留该版本的结构、配色、灯位和默认亮灯效果。

## 用户故事

1. 作为用户，我希望在访达、应用程序列表与系统搜索中看到专属图标，方便识别 Traceflow。
2. 作为用户，我希望图标表达多会话统一管理，区别于传统红绿灯。
3. 作为用户，我希望菜单栏与应用图标具有相同视觉特征，容易认出它们属于同一应用。
4. 作为用户，我希望深浅色菜单栏中的图标均清楚可见。
5. 作为用户，我希望安装或更新后图标资源随应用提供，无需额外下载或配置。

## 视觉规格

- 主体为三个完整同心圆环；不采用交错轨道或分散环组。
- 应用图标保留深蓝渐变背景、圆角方形轮廓与轻微边缘高光；阴影保持克制。
- 背景渐变从 `#344C78` 至 `#142039`；从外到内的轨道颜色为 `#9BBFE7`、`#8EADD7`、`#7999C9`。
- 灯色使用 `#FF797F`、`#F7CF6B`、`#61DFB0`。每环三个灯位，外环突出红灯、中环突出黄灯、内环突出绿灯；未亮灯位保持弱化。
- 采用选中预览默认的“每环亮一盏”效果；“三色全部显示”只是设计比较选项，不增加到应用设置中。
- 图标为固定品牌图形，不根据真实会话数量、轮播或运行状态变化，不增加动画。
- 菜单栏省略彩色背景和未亮灯位，保留三环与三个节点，使用系统模板图像自动适配深浅色。
- 菜单栏按约 18 点显示，单独调整小尺寸线宽与留白，不能直接缩小彩色应用图标作为菜单栏资源。
- 不加入文字、品牌缩写或其他公司的标识。

## 实现决策

1. 保留可编辑矢量母版，从母版生成透明画布上的应用图标多尺寸资源及标准 macOS 图标包。
2. 应用图标使用标准图标尺寸及对应高分辨率版本，生成过程可以在本机复现；避免重复套入两层圆角或阴影。
3. 应用包配置图标名称，构建流程将图标复制到资源目录，在应用签名前完成资源组装；不新增运行时网络依赖。
4. 菜单栏由独立 AppKit 绘制模块创建矢量模板图像，替换现有系统心电符号，保留可访问性名称 Traceflow；不加载外部图片或 Swift Package 资源。
5. 菜单栏使用非可选 NSImage 绘制接口，不设计资源加载或失败分支；保留菜单入口及其现有行为。原先的资源加载回退设想由本条替代，避免同时实现两套路径。
6. 本次只涉及视觉资产、菜单栏图标设置和打包配置，不调整会话状态机、轮播、设置布局或 HUD 中的星光符号。
7. 无需修改持久化格式、配置迁移或添加图标选择设置。

### 二、唯一坐标与灯位规则

应用图标设计坐标为 `128 × 128`，原点在左上角，x 向右、y 向下，与网页预览一致。所有像素尺寸由同一设计按比例缩放，不手工移动某一种尺寸的亮灯。

1. 透明画布；主背景矩形为 `(x:4, y:4, width:120, height:120)`，圆角半径 `28`。
2. 主背景从左上 `(4,4)` 至右下 `(124,124)` 做线性渐变：`#344C78` → `#142039`。
3. 边缘高光为 `(5,5,118,118)` 的圆角矩形，圆角半径 `27`，无填充，白色描边，透明度 `0.16`，线宽 `1`。
4. 三个环的圆心都为 `(64,64)`，半径按外、中、内为 `40、28、16`，线宽均为 `2.6`。描边颜色使用前面的三种蓝色。环内不填充，不增加中心实心点。
5. 灯位按下表计算。每环有三盏，灯索引 `j=0、1、2` 分别为红、黄、绿；环索引 `i=0、1、2` 分别为外、中、内。
6. 角度公式：`theta = (-90 + j * 120 + i * 35) * π / 180`。
7. 灯圆心公式：`x = 64 + radius[i] * cos(theta)`，`y = 64 + radius[i] * sin(theta)`。使用 Double 计算，绘制时转换为 CGFloat，不提前取整。
8. 所有灯半径 `4.5`，边框颜色 `#203354`，边框线宽 `1.2`。亮灯条件严格为 `j == i`。亮灯整体透明度 `1`，其他灯整体透明度 `0.23`。
9. “整体透明度”作用于灯的填充与边框整体，不能只把填充变透明而让暗灯边框保持不透明。原生绘制时每灯使用 save/restore graphics state 和 context alpha。
10. 绘制顺序必须是：背景 → 高光 → 三个环 → 九个灯，确保轨道在灯后面。

| 环 | 半径 | 红灯角度 | 黄灯角度 | 绿灯角度 | 突出的灯 |
| --- | --- | --- | --- | --- | --- |
| 外环 `i=0` | 40 | -90° | 30° | 150° | 红 |
| 中环 `i=1` | 28 | -55° | 65° | 185° | 黄 |
| 内环 `i=2` | 16 | -20° | 100° | 220° | 绿 |

不要把“每环一盏亮灯”实现为每环只绘制一盏：彩色应用图标必须有九个灯位。只有菜单栏才省略暗灯。

不把网页 CSS 的 `drop-shadow` 烘焙到 PNG：那是展示卡片的阴影。应用资源保留背景渐变和边缘高光即可，透明留白不能填成白色或深蓝。不要添加第二层底板、光晕、文字或动画。

### 三、应用资源生成器

用系统 Swift、AppKit、Foundation 与 `/usr/bin/iconutil`，不安装第三方依赖。

生成器约定：

- 接受两个必填参数：`--iconset <绝对目录>` 与 `--source-dir <绝对目录>`。参数缺失、未知或非法时写错误到标准错误并非零退出。
- `--iconset` 是临时 PNG 输出目录；`--source-dir` 是临时 SVG 输出目录。两者由外层脚本创建。生成器不猜测当前工作目录，不直接写系统应用目录。
- 在 Swift 中集中定义背景、环、灯位参数；PNG 与 SVG 使用同一组数值和灯位计算函数。SVG 不能通过剪贴网页 `<use>` 标签生成。
- SVG 必须含 `xmlns`、`viewBox="0 0 128 128"`、`<title>`，并在自身 `<defs>` 中定义需要的渐变。不得引用网页 CSS、网页内 symbol 或远程 URL。
- SVG 暗灯使用包含填充和描边的 `<g opacity="0.23">`，亮灯使用透明度 `1`，与原生绘制一致。
- PNG 使用 `NSBitmapImageRep` 创建 RGBA 位图：8 位/通道、4 通道、带 alpha、非平面布局；开启抗锯齿，生成后检查 `.png` 编码数据非空。
- 每个 PNG 的 `pixelsWide`、`pixelsHigh` 必须等于文件名要求的实际像素大小，不依赖屏幕倍率或窗口截图。
- 位图绘制时明确将左上设计坐标转换到 Core Graphics 坐标：先平移 `(0, pixels)`，再缩放 `(pixels / 128, -pixels / 128)`。只翻转一次；不能再额外使用 flipped AppKit context 重复翻转。
- 建议绘制背景路径、环和灯使用 Core Graphics；用显式 sRGB 颜色空间创建梯度。边框与路径随上述变换一起缩放。
- `NSBitmapImageRep`、`NSGraphicsContext`、渐变对象或 PNG 编码创建失败时明确报错退出，不生成空文件，不强制解包。
- 所有绘制保存与恢复 graphics state，避免 alpha、坐标变换或描边颜色影响下一张图。

必须输出以下十个文件，名称不可修改：

| 文件名 | 实际 PNG 像素 |
| --- | --- |
| `icon_16x16.png` | 16 × 16 |
| `icon_16x16@2x.png` | 32 × 32 |
| `icon_32x32.png` | 32 × 32 |
| `icon_32x32@2x.png` | 64 × 64 |
| `icon_128x128.png` | 128 × 128 |
| `icon_128x128@2x.png` | 256 × 256 |
| `icon_256x256.png` | 256 × 256 |
| `icon_256x256@2x.png` | 512 × 512 |
| `icon_512x512.png` | 512 × 512 |
| `icon_512x512@2x.png` | 1024 × 1024 |

48 像素只作为预览验收尺寸，不是 iconset 的必需文件，不把 `icon_48x48.png` 放进标准 iconset。两张同为 32 像素的文件可以使用同一绘制结果。

外层 `scripts/generate-app-icon.sh` 的执行顺序：

1. 使用 `#!/bin/sh` 与 `set -eu`，参考现有脚本计算 repo root；正确引用带空格路径。
2. 创建任务专用临时目录，通过 trap 清理；只清理本脚本创建的临时目录，不删除整个 `.build`、`dist` 或 packaging。
3. 在临时目录中创建 `Traceflow.iconset` 与 SVG 输出目录。
4. 用 `swiftc` 编译生成器到临时可执行文件，再运行它。不得把每个尺寸拆成十次编译。
5. 用 `/usr/bin/iconutil -c icns <临时图标集> -o <临时 Traceflow.icns>` 生成资源；检查文件非空。
6. 所有生成成功后再分别替换 `packaging/TraceflowIcon.svg`、`packaging/TraceflowMenuIcon.svg`、`packaging/Traceflow.icns`。使用同目录临时文件加 `mv` 进行单文件原子替换；不承诺三个文件之间的跨文件事务。
7. 输出三个仓库相对路径；脚本可重复执行。生成或转换失败时不进入替换阶段，保留旧资源并返回非零；若替换阶段发生文件系统错误，也必须非零退出并指出失败的目标文件，禁止报告全部成功。
8. PNG 尺寸集是临时构建产物，不纳入 Git；三个最终资源与生成器脚本纳入 Git。给 shell 脚本添加执行权限。

### 四、菜单栏绘制模块的具体实现

新增 `Sources/TraceflowApp/TraceflowStatusIcon.swift`，使用 `import AppKit`。禁止用彩色图标转灰度来代替专用绘制。

公开给当前应用目标的内部接口如下，无需声明 public：

```swift
@MainActor
enum TraceflowStatusIcon {
    static func makeImage() -> NSImage
}
```

该接口为内部模块约定，不修改应用对外接口。

实现要求：

1. 使用 `NSImage(size: NSSize(width: 18, height: 18), flipped: true, drawingHandler: ...)` 创建图像。返回图像是非可选，不添加不存在的“资源丢失”检查。
2. handler 根据传入的目标矩形计算缩放，不缓存固定 18 像素 PNG。使用 `NSGraphicsContext.current?.cgContext`；没有 context 时返回 false，不强制解包。
3. 设计裁切区域与预览的菜单栏母版一致，为 `(12,12,104,104)`。将它映射到目标矩形：先平移到目标 origin，缩放 `rect.width/104` 与 `rect.height/104`，再平移 `(-12,-12)`。由于 `flipped: true` 已使用左上坐标，不再手动翻转 y。
4. 使用纯黑不透明描边与填充，模板图像由系统着色。环心仍为 `(64,64)`，半径 `40、28、16`；环线宽 `5` 个设计单位，对应 18 点约 `0.865` 点。
5. 只绘制三个亮灯节点，沿用上一节 `j == i` 的三个位置；节点半径 `4.3` 个设计单位，对应 18 点约 `0.744` 点。节点无边框。
6. 不绘制背景、渐变、暗灯、阴影、中心圆点。开启抗锯齿，先环后节点，保存并恢复 graphics state。
7. 创建后设置 `image.isTemplate = true`、`image.accessibilityDescription = "Traceflow"`，返回图像。
8. 生成器输出的菜单栏 SVG 必须使用相同裁切范围、环线宽与三个节点，以便核对；但运行时直接绘制，不依赖该文件存在。

在 `TraceflowApp.swift` 的 `configureStatusItem()` 中，仅将现有赋值改为：

```swift
item.button?.image = TraceflowStatusIcon.makeImage()
```

保留 `NSStatusItem.squareLength`、`makeMenu()`、`item.menu`、`statusItem` 和所有动作。不要新增 timer 或监听会话状态。不要修改菜单文字或重新排列菜单。

### 八、禁止的误实现
