# 红黄绿灯亮度与增强光晕

Related discussion: [docs/discuss/2026-10-01-light-glow-animation.md](../discuss/2026-10-01-light-glow-animation.md)

状态：已获用户批准，实施中。用户授权所有阶段连续开发，各阶段验证并提交后立即继续。

## Problem Statement

当前点亮的红绿灯最暗时与未点亮灯一样只有 18% 不透明度，状态辨识不清。原增强光晕增加模糊后，与标准效果差别仍较小。用户通过网页对比选定更清晰但不过分抢眼的灯体和光晕同步动画。

## Solution

三色灯采用方案 B：点亮时灯体保持 55%～100% 不透明度，光晕随同一动画相位变化。增强光晕使用灯边明亮光圈和外围柔光，按网页初版新增强效果降低 30%，保留 70% 强度。未点亮灯保持 18%，无光晕。

## User Stories

1. 作为查看任务状态的用户，我希望点亮灯在动画暗段也能明显区别于未点亮灯。
2. 作为查看后方屏幕内容的用户，我希望未点亮灯继续保持 18% 不透明度。
3. 作为观察动态状态的用户，我希望灯体和光晕一起明暗变化。
4. 作为等待任务完成的用户，我希望黄灯也采用网页确认的呼吸效果。
5. 作为使用增强光晕的用户，我希望灯周围的光圈清晰可见，同时不过分抢眼。
6. 作为使用标准光晕的用户，我希望保留柔和的光晕选择。
7. 作为启用减少动态效果的用户，我希望点亮灯静态清晰显示。

## Implementation Decisions

### 动画参数

- 复用现有灯动画参数模块与状态灯视图，不新增设置项。
- 未点亮：灯体不透明度 0.18，缩放 1，光晕强度 0，停止动画。
- 点亮：灯体不透明度为 `0.55 + 0.45 × phase`；光晕强度为 `phase`；缩放为 `0.9 + 0.2 × phase`。此公式来自用户已确认的网页原型。
- 红灯保留 0.56 秒周期及原有闪烁相位；绿灯保留 2.3 秒正弦呼吸；黄灯保留 2.8 秒正弦相位，同时灯体和光晕加入呼吸，不再常亮。
- 减少动态效果时，点亮灯维持缩放 1、灯体不透明度 1、光晕强度 1，保持现有静态语义。
- 灯体直径 26、灯距 6、浮条高度 40；状态与颜色映射沿用现有实现。

### 光晕

- 标准模式保留现有光晕绘制参数，使用新的同步动画相位。
- 增强模式替换为网页定稿样式，两层均位于灯体后方，仅点亮灯绘制。
- 外围柔光：径向渐变起始半径 11、结束半径 20；位置 0、0.28、0.6、1 的不透明度分别为 0.56、0.455、0.175、0，再乘以当前光晕强度。
- 灯边光圈：半径 13.5、线宽 3、模糊半径 1.4；不透明度为 0.63，再乘以当前光晕强度。
- 上述数值来自网页原始新增强效果统一乘以 0.70，不是灯体亮度降低 30%。
- 复用现有颜色，保持光晕以灯中心向四周扩散。避免新增全局透明度或覆盖灯体的遮罩。
- 原生与网页模糊、颜色合成存在差异；验证时重点关注明亮灯边、外围渐淡、邻灯辨识度和背景内容遮挡。

### 2. 第一步：修改动画参数

在 `parameters` 中保留前两个 `guard` 原样：先处理未点亮，再处理减少动态效果。只替换正常点亮分支中的两行计算：

```swift
let phase = phase(for: state, referenceTime: referenceTime)
let bodyOpacity = 0.55 + 0.45 * phase
let glowIntensity = phase
```

后面的返回对象、缩放公式和 `isTimelinePaused: false` 保持不变。删除黄灯 `.completed` 的常亮例外；不要在其他地方重新加回黄灯例外。`phase(for:referenceTime:)` 不需要修改。

计算示例：

| phase | 点亮灯体不透明度 | 光晕强度 | 缩放 |
| --- | --- | --- | --- |
| 0 | 0.55 | 0 | 0.9 |
| 0.5 | 0.775 | 0.5 | 1.0 |
| 1 | 1.0 | 1.0 | 1.1 |

“光晕强度 0.5”表示把每一层光晕的不透明度乘以 0.5，不表示把灯体乘以 0.5。未点亮分支不使用此表，始终返回 `(scale: 1, bodyOpacity: 0.18, glowIntensity: 0, isTimelinePaused: true)`。

此阶段同步更新旧测试中对 18% 暗段和黄灯常亮的期望，运行动画测试后提交并继续第二步；不得为通过旧测试恢复旧行为。第三步补齐跨状态与红灯边界回归检查。

### 3. 第二步：替换增强光晕

当前 `StatusLight` 的 `ZStack` 先绘制两层光晕，再绘制灯体。将 `if active` 的内部按 `glow` 模式分支：

```swift
if active {
    switch glow {
    case .standard:
        // 保留现有两次 glowLayer 调用与标准参数。
    case .strong:
        enhancedGlow(intensity: visual.glowIntensity)
    }
}
// 此处继续保留现有 Circle 灯体，必须位于光晕之后。
```

新增 `private func enhancedGlow(intensity: Double) -> some View`，建议直接使用以下原生结构：

```swift
private func enhancedGlow(intensity: Double) -> some View {
    ZStack {
        Circle()
            .fill(RadialGradient(
                stops: [
                    .init(color: kind.color.opacity(0.56 * intensity), location: 0),
                    .init(color: kind.color.opacity(0.455 * intensity), location: 0.28),
                    .init(color: kind.color.opacity(0.175 * intensity), location: 0.6),
                    .init(color: .clear, location: 1)
                ],
                center: .center,
                startRadius: 11,
                endRadius: 20
            ))
            .frame(width: 40, height: 40)

        Circle()
            .stroke(kind.color.opacity(0.63 * intensity), lineWidth: 3)
            .frame(width: 27, height: 27)
            .blur(radius: 1.4)
    }
    .frame(width: 40, height: 40)
}
```

实现注意事项：

- 光圈路径直径为 27，即半径 13.5；使用 `.stroke`，不能换成 `.strokeBorder`，否则线条会向内缩进、更多地被灯体盖住。
- 外围渐变不要再加原增强模式的 18 像素模糊；定稿是更清楚的渐淡柔光，只有灯边光圈使用 1.4 的模糊。
- 上面 0.56、0.455、0.175、0.63 **已经乘过 0.70**。不得再次乘以 0.70，不得把 `intensity` 的最大值改成 0.70。
- 标准模式继续使用原参数：外层直径 40、模糊 12、峰值不透明度 0.28；内层直径 34、模糊 6、峰值不透明度 0.50。保留原渐变停止位置及原 `glowLayer` 实现。
- 可保持现有 `GlowParameters` 类型以缩小改动；`.strong` 不再调用旧的两层 `glowLayer`，其旧参数不得与新光圈叠加。不要为清理未使用参数扩大重构范围。
- 外层现有 `.scaleEffect(visual.scale)` 继续同时作用于灯体和光晕；不要再给新增光晕重复应用缩放。
- 外层最后的 26×26 占位尺寸必须保留。40×40 是绘制范围，不是灯的布局尺寸，否则灯距和整条 HUD 会改变。
- 灯体仍通过 `kind.color.opacity(visual.bodyOpacity)` 绘制。光圈和灯体使用同一个 `kind.color`，不要加入白色高光、黑色阴影、混合模式或新的色值。
- 不新增 `.clipped()`、`.mask()` 或 `.clipShape()` 来截断光晕。网页 Canvas 会在高度 40 边界裁切，原生可能有轻微溢出差异；先保持现有原生层级，由人工验收判断，不能擅自更改几何尺寸或光晕参数。
- `TimelineView` 的刷新间隔和暂停条件保持现有逻辑；不添加第二套动画或定时器。

完成此主要文件变更后运行构建与动画测试，提交后继续第三步。

### 5. 原生人工验收

1. 在设置页选择“光晕效果 → 强烈”。观察红、黄、绿各至少两个周期，对照网页右侧方案 B 与“新增强”的效果。
2. 红灯暗段、黄绿灯呼吸最低点仍有清晰灯体；另外两盏灯维持淡色，无自身光圈。光晕扩散可能轻微经过邻灯区域，不能因此把邻灯判为点亮。
3. 光晕最大时能看到彩色亮边，外围逐渐变淡；不存在额外白边，也没有原增强模糊层叠加造成的大面积色雾。
4. 切回“标准”，灯体仍按 55%～100% 变化，光晕恢复原柔和样式。
5. 检查横向及竖向布局，灯体中心、灯距、标题位置和浮条尺寸没有因 40 像素光晕而改变。
6. 在浅色和深色屏幕内容上观察；背景透明度可临时使用 10% 和 100% 比较，验收后恢复用户原设置。不要通过调整背景实现来补偿光晕差异。
7. 启用系统减少动态效果后，点亮灯静态全不透明、光晕维持峰值；未点亮灯仍为 18%。
8. 如果原生视觉与网页有明显差异，附上实际观察与原因，先修改 PRD、获得用户批准，再调参数。没有运行环境时标注“原生观感待验收”，不得自行宣称定稿已完全复现。

### 6. 交付与禁止误解

- 本功能完成意味着：三色参数符合表格，标准与增强分支正确，相关检查通过，原生观感验收结果明确记录。
- 55% 是**点亮灯动画的最低不透明度**，不是把所有灯设置成 55%。
- 18% 只用于未点亮状态；光晕强度为 0 时，当前点亮灯仍保持至少 55%。
- 降低 30% 只针对初版新增强光晕的各层不透明度，不修改灯体公式、动画周期、灯体直径或光晕半径。
- 网页定稿属于增强模式，不能直接把增强绘制强行应用于标准模式。
- 用户已要求每个阶段验证并创建提交。严格遵守 `type(scope): 简体中文描述`，type 和 scope 使用英文；将关联 PRD 的仓库相对路径放在提交正文，标题描述保持纯中文。
