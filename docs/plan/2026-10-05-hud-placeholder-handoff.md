# 默认名称与会话标题交接修订

Related discussion: [docs/discuss/2026-10-03-hud-layout-content-reset.md](../discuss/2026-10-03-hud-layout-content-reset.md)

状态：用户已批准本修订，三个阶段的开发、自动验证及发布构建均已完成，默认名称交接残影仍待用户实屏验收。此前布局整窗替换保持有效。

## 问题与证据

用户已实屏确认布局切换既无持续残影，也无瞬间残影。剩余问题：默认 `Traceflow` 切到首个会话标题后，默认文字持续留在画面上；标题改为 `-     -     -` 后仍清晰可见。横向左与右互换后恢复。

代码事实：布局变化会创建新面板并关闭旧面板；默认名称与首个会话之间仍在旧面板上切换标题分支。首次显示会话已有禁用标题过渡的语义。整窗替换有效支持复用这一方案，但没有直接证明 WindowServer 内部根因，不能声称已经确定是动画或系统资源故障。

## 目标和用户行为

1. 默认名称切到第一个参与显示的会话时，只显示当前会话标题，没有默认字形残留或瞬间叠加。
2. 最后一个参与显示的会话消失时，只显示默认名称。反向残影尚未用户实测，纳入对称保护与验收。
3. 会话 A 切到 B 保留现有标题动画，不因此重建窗口。
4. 会话重命名、状态改变、灯效变化不触发整窗替换。
5. 四种布局均适用；会话名恰好为 `Traceflow` 或未命名也按会话处理，不能按字符串判断是否默认名称。
6. 文字交接保持当前屏幕、位置、可见性、固定和透明度，隐藏期间更新后仍隐藏。
7. 快速变化只应用最终状态；布局与标题同时变化不能让多个浮窗共同显示。

## 实现规格

### 一、判定规则

以模型的 `displayedSession == nil` 区分默认名称模式和会话模式。不能按会话总数、标题字符串、状态灯是否亮或 `shouldAnimateDisplayChange` 判断。

控制器记录当前窗口已经应用的显示模式。首次初始化读取模型当前值；以后只有成功完成窗口交接才能更新记录。订阅实际显示会话变化，回调延迟到模型值提交后处理，读取模型最新布局与显示模式，不能使用过期回调参数重建。

使用同一协调入口比较目标与已应用状态：

- 布局变化：按已批准布局规则整窗替换，恢复目标布局的位置。
- 布局未变、显示模式变化：整窗替换，保持当前几何位置。
- 布局与模式均未变：不替换。会话 A 到 B、重命名和灯状态更新继续沿用现有更新机制。

`show()` 也要同步协调模型最新状态；不得先显示旧模式，再等待异步回调修正。布局和模式同一轮变化按最终组合创建新窗口，后到回调不得重复替换已应用组合。启动已有会话时直接创建会话模式窗口。

### 二、交接间隙中的内容

生产面板的承载在自身生命周期内保持默认名称模式或会话模式，防止旧窗口在关闭前先应用相反分支。保留现有布局快照。

默认模式承载直到退役都显示默认名称；会话模式继续动态读取当前会话，支持 A 到 B 和重命名。会话变为 nil 到旧窗口关闭之间，保留最后实际显示的会话快照，不能回退到默认名称；该快照必须随实际会话变化更新，不能永远回退到窗口创建时的首个会话。

采用仅供窗口承载使用的展示状态，普通 `HUDView(model:)` 的动态渲染用途保持原语义。所有标题、无障碍描述和灯状态使用一致的展示会话来源，不能标题与灯各读不同状态。不要冻结整个模型；透明度、颜色及正常会话更新仍动态有效。展示状态的订阅须随旧内容释放，不能让控制器缓存旧承载或旧窗口。

### 三、复用窗口装配与退役

继续使用唯一面板工厂、无窗口进出动画、唯一窗口控制器和新旧窗口同步交接顺序；不复制第二套窗口装配和旧窗口清理逻辑。

将现有窗口替换中的位置处理分为两种明确策略：恢复目标布局位置、保留当前几何位置。布局变化选择前者，仅显示模式变化选择后者。

文字边界交接必须：

1. 记录当前可见性、屏幕、frame 以及几何、透明度过渡与临时位置重试状态。
2. 若正在拖动，结束旧容器拖动并使迟到回调无效；不保存位置、不将当前 frame 恢复到上次拖动记录。
3. 若正在透明度尺寸过渡，结束旧定时器并使用当前透明度对应的最终几何目标；不能产生无目的的位置跳变。正常稳定场景 frame 必须完全不变。
4. 创建隐藏新窗口，连接交互；先隐藏旧窗口，再迁移唯一引用、清空旧内容和代理并关闭旧窗口，最后按原可见性显示新窗口。
5. 不调用布局位置恢复、位置播种或保存；不因文字变化启动新的十秒重试。保留现有临时位置及重试期限；重试若仍需执行必须作用于当前窗口，不操作旧窗口。
6. 新窗口继续固定穿透、相同空间行为、阴影和背景透明度，不抢设置窗口键盘焦点。

禁止强制重绘、移动窗口促刷、只换承载、临时透明度变化、延迟淡入淡出或每次会话事件重建窗口。

## 验证规格

只对本次复杂状态交接补充有意义的测试，不执行先写失败测试的流程。

1. 默认到首个会话、会话到默认：四种布局，新旧窗口身份变化；旧窗口退役并释放，新窗口仅一个内容树。
2. 交接间隙：模型已变而回调未运行时，旧承载保留原模式；新承载使用最终模式，不产生默认与会话的混合分支。
3. 会话 A 到 B、同会话重命名和灯状态变化：窗口身份不变，标题最新，原动画决策不变。
4. 字面标题 `Traceflow`、空标题回退以及 `-     -     -`：均按是否存在显示会话判定，不能按文本误判。
5. 位置不变：设置非默认 frame，包括跨屏和拖动中的 frame；仅文字边界变化不恢复旧位置，位置存储全部记录不变。
6. 固定、隐藏、透明度过渡、位置临时重试：状态正确迁移，迟到拖动不保存、不移动新窗口。
7. 快速 nil/会话交错、立即 show、布局与模式交错：最终组合正确，迟到回调不重复创建，同一时刻最多一个逻辑可见 HUD。
8. 实屏：窗口先显示默认名称，再通过真实会话事件出现标题，期间不切布局、不移动窗口、不强制刷新；检查第一批可采样帧、三百毫秒和一秒。参考窗口只能在被测采样结束且隐藏后显示。缺少权限明确跳过。

实屏验收包括默认到首个会话与反向、重复五次、横纵各方向、白/黑标题和透明度百分之八十六；正常 A 到 B 动画、隐藏再显示、固定及跨屏也回归。自动测试不得替代真实像素验收；若仍复现，记录窗口编号、frame、模式及采样，不叠加强制刷新补丁。

### B. 状态的归属与生命周期

采用以下职责形状，名称按此保留，避免发明多套相近状态：

```swift
enum HUDWindowDisplayMode: Equatable {
    case placeholder
    case session
}

enum HUDPanelPlacement {
    case restoreLayoutPosition
    case preserveCurrentGeometry
}
```

控制器中的 `layout` 继续表示当前窗口已应用布局，新增 `appliedDisplayMode` 表示当前窗口已应用模式。模式判断等价于 `model.displayedSession == nil ? .placeholder : .session`。这两个值不是模型目标值的镜像缓存；只有初始化或成功窗口交接才改变。

新增主线程 `HUDWindowPresentation: ObservableObject`，只负责“某个承载能显示哪类会话内容”。内部来源分三类：

- `live`：普通 `HUDView(model:)` 使用，直接读取模型当前显示会话，不创建窗口模式订阅。
- `placeholder`：生产默认窗口使用，展示会话永远为 nil，即使模型已出现会话。
- `session`：生产会话窗口使用，初始化保存当前非 nil 会话；之后同步接收模型发布的每个非 nil 会话快照，更新 `@Published` 的最后有效会话；收到 nil 时不清空。

实现最后有效会话的订阅必须用 `$displayedSession` 发布的参数值，不能在它的 `sink` 中回读尚未提交的 `model.displayedSession`。非 nil 更新不推迟到主队列，避免“先 A 后 B 再 nil”时退回 A。闭包弱持有展示对象，订阅由展示对象持有，避免自身循环引用；展示对象不得强持有窗口或控制器。

控制器的目标协调订阅与上述内容快照订阅用途不同：前者等模型提交后判断是否换窗口；后者只维护当前会话窗口的内容。每个当前会话承载最多一份快照订阅，每个控制器最多一份布局订阅和一份显示模式订阅；不能每次事件添加新订阅。

`HUDView` 保持原泛型类型，避免把所有 `NSHostingView<HUDView>` 改成其他承载类型。为其增加持有 `@ObservedObject` 展示状态的内部初始化路径：

- `HUDView(model:)` 创建无订阅的 live 展示状态，布局仍按现有初始化快照规则。
- 面板工厂创建 placeholder 或 session 展示状态，再交给生产承载的 `HUDView`。
- `displayedTitle`、`titleRegion`、`accessibilityDescription` 和 `lights` 中所有 `model.displayedSession` 读取改为同一个 `presentation.displayedSession` 来源；颜色、透明度、图标比例、光晕和 `shouldAnimateDisplayChange` 继续读取模型。
- 不改 `.id(session.id)`、会话标题 `.transition` 和动画时长。默认模式仍无会话标题过渡。

控制器不缓存旧展示对象。当前展示对象由当前根视图持有，根视图随承载释放；测试可弱引用展示对象验证释放。不要使用全局字典保存这些对象。

### C. 协调入口及订阅时序

增加唯一 `synchronizePresentation()`。保留 `switchLayout(to:)` 作为旧调用者兼容入口，但仅负责检查传入布局是否仍等于模型最新值，再调用协调入口；模式订阅不调用带旧布局参数的入口。

协调步骤严格如下：

1. 确认模型及当前窗口存在，否则返回，不修改状态。
2. 读取目标布局和目标模式，比较 `layout`、`appliedDisplayMode`。
3. 两者都相同直接返回。即使会话 ID 或标题变化也不创建窗口。
4. 只要布局不同，位置策略为 `restoreLayoutPosition`；否则只能是模式不同，策略为 `preserveCurrentGeometry`。
5. 按位置策略准备交接参数、取消旧交互和尺寸定时器；在旧窗口隐藏前不要改变其 frame。
6. 新窗口装配显式传入这次读取的目标布局及模式，不让工厂再自行混读模型目标。工厂建立与该模式一致的展示对象。
7. 按 E 节完成同步交接，完成后记录目标布局及模式；只有布局策略按原规则管理位置重试。

订阅规则：

- 布局观察者：保留 `dropFirst`；回调只安排弱引用控制器的主队列任务，任务执行时调用 `synchronizePresentation()`，不应用闭包捕获的旧布局。
- 模式观察者：将显示会话映射为上述模式、去重并 `dropFirst`；回调只安排相同协调任务。不能去重会话 ID 后错误触发 A 到 B 重建。
- 不需要新增固定毫秒延迟、取消合并定时器或调试开关。相邻任务执行时第一项应用最新组合，后续项按已应用状态返回。
- 所有控制器状态及窗口操作在主线程完成。

快速变化的明确结果：

| 当前已应用状态 | 模型同轮变化 | 协调时最终值 | 预期 |
| --- | --- | --- | --- |
| 默认、横向左 | nil → A → nil | 默认、横向左 | 不换窗，旧默认窗口未显示过 A |
| 会话 A、横向左 | A → nil → B | 会话 B、横向左 | 不因模式换窗，继续正常会话更新 |
| 默认、横向左 | nil → A，同时横向右 | 会话 A、横向右 | 一次换窗，恢复横向右位置 |
| 会话 A、纵向上 | A → nil，同时纵向下 | 默认、纵向下 | 一次换窗，恢复纵向下位置 |
| 默认、横向左 | nil → A，随后立即 show | 会话 A、横向左 | show 同步换窗，迟到回调不再换 |
| 任意状态 | 任务之间发生真实的新变化 | 不同的最新组合 | 可以再次换窗，每次都必须对应实际已提交目标 |

“一次换窗”指未让出主线程的同轮变更，不要求跨事件循环的真实新变化只换一次。

### D. 几何准备：禁止照搬布局位置恢复

不能在文字边界路径直接调用现有 `switchLayout` 的整套取消与恢复逻辑。必须先记录以下值，再使原取消方法清空定时器和拖动状态：旧 frame、是否拖动、是否存在尺寸过渡及其目标、原 `geometry.reference`、临时位置标记、原重试期限。

`preserveCurrentGeometry` 最终 frame 的优先级：

1. **拖动中**：取消拖动后，用旧窗口当前 frame 经现有 `referenceFrame` 算法建立新几何参考，结合当前透明度计算最终 frame；通常没有尺寸变化时 frame 原样保持。不保存拖动位置，也不恢复拖动前位置。
2. **未拖动但尺寸过渡中**：采用现有当前透明度对应的过渡目标（或由原几何 reference 重新算出的当前透明度最终目标），取消旧定时器；只对隐藏新窗口应用最终尺寸和锚点。图标比例立即达到当前透明度的最终值。
3. **稳定状态**：直接使用旧 frame，保留原 `geometry.reference`，不从屏幕限界后的展示 frame 重建参考，避免丢失靠边锚点意图。
4. **没有可用屏幕**：使用已记录原点和当前透明度最终尺寸，不跳到屏幕原点，不写位置记录。

计算最终 frame 只能复用现有几何和外观算法。不可自行按左上角、中心或任意偏移重新定位。如果屏幕在交接同时真实消失，沿用现有屏幕恢复事件的处理；本次文字交接本身不调用屏幕恢复。

重试状态：文字路径不取消已经排队的重试、不重设截止时间、不新增重试；保留 `isTemporaryPosition`。已有重试闭包弱持有控制器并在执行时操作当前窗口，这一点继续保留。若拖动此前已取消重试期限，则交接继续保留“无有效重试”的状态，不能重新激活。

布局策略继续取消旧重试、恢复目标布局位置，并按缺失显示器结果启动既有十秒策略。文字策略不允许调用 `restorePosition`、`seedIfMissing`、`savePosition`、`ensureVisible` 或 `resetPosition`。

`show()` 的兼容细节：先同步协调。若本次仅模式换窗，随后不能无条件调用 `restorePosition()` 覆盖刚保留的位置；可让协调返回“本次是否采用保持位置策略”的结果，据此跳过这一恢复。无待处理变化的普通 show 保持既有恢复语义；布局换窗仍按目标布局恢复。测试要覆盖该分支，不能只修改观察者路径。

### E. 窗口装配与提交状态的强制顺序

将现有 `replacePanelForCurrentLayout` 提炼为一个共用方法，接收目标布局、目标模式和已准备位置策略。删除旧的重复替换实现，不新增标题专属第二套窗口关闭逻辑。

1. 持有局部旧窗口，记录 `isVisible`；准备最终 frame 和几何状态。
2. 创建新面板与新的容器、背景、承载和展示对象，保持隐藏；每个面板均设置 `animationBehavior = .none`。
3. 新承载的布局及显示模式必须等于本次目标；设置新窗口初始 frame，不在默认零原点显示。
4. 给新容器连接三个拖动闭包，给新窗口设置代理；仍隐藏。
5. `old.orderOut(nil)`；清代理，取消旧拖动，三个旧交互闭包设 nil。
6. 控制器 `window`、`hostingView`、`background` 切到新对象；提交目标布局与模式，以及准备好的几何状态。此后只有新窗口属于控制器。
7. 布局策略在隐藏新窗口上恢复目标布局位置；文字策略只应用准备好的 frame，不调用持久化。
8. 旧窗口 `contentView = nil`，再 `close()`；不得在控制器字段保存旧引用。
9. 原来可见才显示新窗口；原来隐藏仍隐藏。
10. 布局策略按原规则重新判断重试；文字策略不改变现有重试期限。

步骤 5 到 9 同步完成，无延迟任务、动画或双窗口同显。建窗前 guard 失败直接返回；若装配无法完成，不得先修改已应用模式并继续旧窗口，须报告错误。不可将上述框架写成吞错后默认成功。

### F. 测试构造与具体断言

新增 `HUDPlaceholderHandoffTests` 或在现有标题测试中集中本次状态迁移测试；若新增测试类，阶段命令必须包含它。使用 `SessionIntegrationFixture` 通过真实 hook 产生会话，不新增生产公开 setter 强写 `displayedSession`。

| 测试 | 操作及必须断言 |
| --- | --- |
| 首会话入场 | 先 show 默认窗口，再真实 hook；等待协调，窗口不同、旧窗口无代理/内容且不可见，新标题正确，frame 不变 |
| 会话退场 | A 实际显示后通过真实排除/结束使 displayedSession 为 nil；新窗口显示默认名称，frame 不变 |
| 最后快照 | 先 A 后 B，确保 B 已更新展示；模型变 nil 后、协调前旧展示仍 B，不是 A 或默认文字 |
| 字面默认名 | 会话标题为 Traceflow；仍处于 session 模式，退场时必须按模式换窗 |
| 短标题暴露旧字形 | 首标题为 `-     -     -`，新展示不含默认字形；实屏比较旧默认文字区域 |
| 窗口不替换 | A 到 B、重命名、同 ID 状态改变前后当前窗口同一对象；内容变化正确、动画决策保留 |
| 保持位置 | 在可见屏幕内选一个与存储位置不同的 frame，触发文字交接；新 frame 等于该 frame，所有布局位置记录不变 |
| 近边锚点 | 屏幕边缘夹紧状态触发文字交接，原 reference 保留；之后改变透明度仍符合既有锚点算法 |
| 拖动中 | 旧容器开始拖动并移动窗口，文字边界交接；新窗口保持当前拖动位置，旧 finish 回调不能保存或移动它 |
| 临时位置重试 | 保存指向缺失显示器的记录后进入临时位置；文字交接后仍是当前窗口重试，存储不变，期限不重新计时 |
| 隐藏和 show | 隐藏期间两次模式变化，始终隐藏；立即 show 应只显示最终组合、保持文字交接位置，后续回调不再次更换 |
| 释放 | 窗口、容器、背景、承载、展示对象均用弱引用；清空测试自身强引用后让出事件循环，应释放 |
| 布局回归 | 沿用原四方向身份、窗口编号、动画禁用、焦点、固定和透明度测试，不能删掉绕过失败 |

旧模式间隙测试若真实 hook 自身会让出线程，不要假设 await 返回后协调一定尚未运行。可以直接测试展示对象：在同步模型更新路径中验证最后快照；控制器集成测试另外验证替换结果。不要为了构造间隙增加生产固定延迟。

位置记录比较前先准备全部布局记录，排除初始化合法播种；比较实际 `HUDPositionStore` 结果。弱引用释放测试不能同时把旧根视图或 parts 元组留在强引用局部变量中。

重试期限无需对外公开调试 API：优先通过已有核心重试策略及控制器可观察结果验证；必要时仅降低内部可见性供 `@testable` 读取，禁止增加可供用户切换的生产调试开关。

### G. 实屏采样不得误报通过

沿用 `HUDScreenFixture` 的权限检查。首个会话出现后，不得通过切布局、移动窗口、改变透明度或调用显示刷新来准备截图，这些动作可能恰好消除待测残影。

瞬间采样要记录事件开始时间、每张截图的实际开始与完成时间、新旧窗口编号。连续采样第一批可得到的帧，不把“第一个截图已经超过三百毫秒”记为瞬间验证通过。没有覆盖交接过程的采样明确报告验收不足；录屏权限缺失明确跳过。

稳定图检查三百毫秒与一秒；参考图在受测窗口采样完成并隐藏后生成。目标默认或会话模式必须与受测结果一致。比较标题区域可排除正常活动灯动画噪声，但不能排除旧默认标题区域。标题只剩短横线时旧 `Traceflow` 区域也必须被检查。

真实 A 到 B 在动画期间两份会话标题短暂存在属于正常行为，本次不能用“所有帧只能一个标题”断言误杀它；默认与会话边界才要求即时交接且无旧字形残留。
