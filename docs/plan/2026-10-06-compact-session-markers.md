# 精简 HUD 与会话颜色标记

日期：2026-10-06  
状态：四阶段功能开发完成。用户授权连续实施并逐阶段验证、提交；最终全量测试 271 项，7 项录屏权限相关检查跳过，零失败。详细验收与限制见 [实施验收记录](2026-10-06-compact-session-markers-review.md)。

## 一、问题与目标

当前 HUD 用标题区分会话，横向长边为 380 或 420 点，占用较多桌面空间。增加精简模式，用用户能记住的会话颜色代替标题，保留原有状态提示。

用户最终选定浏览器预览中的 **C 菱形、14 点**。预览在 `docs/design/compact-hud.html`，用于参考形状、尺寸与布局；其网页材质、灯光模拟不是原生实现标准。

本规格是正式开发依据。前面讨论中“悬停显示标题”“菜单显示当前会话名称”等建议已经取消，不得实现。

## 二、用户故事

1. 用户可以切换标准与精简模式，按需要选择文字辨认或减少占用。
2. 精简模式通过不同颜色的同形菱形辨认会话。
3. 用户仍通过原有三盏灯识别运行、完成、待处理状态。
4. 新会话自动获得未被现有会话使用的颜色，无需先手动配置。
5. 同一会话重启、轮播、同步和修改标题后仍保留原颜色。
6. 用户能在设置顶部会话行看到菱形，对应 HUD 中的颜色。
7. 用户能在会话区开关和标题之间看到同色菱形。
8. 用户点击菱形即可调用系统颜色选择器，更换该会话颜色。
9. 同一会话同时出现在两处设置列表时，颜色保持同步。
10. 用户可以手动选择与其他会话相同的颜色。
11. 用户从菜单栏与设置均能切换模式，两处状态一致。
12. 模式选择重启保留，新安装或旧版本升级后默认标准模式。
13. 钉住时仍能穿透鼠标；未钉住时仍能拖动 HUD。
14. 无参与显示会话时，灰色菱形和暗灯维持稳定占用空间。
15. 用户需要项目名称或标题时，在设置中查看现有信息。

## 三、确定的产品行为

### 3.1 模式与入口

新增全局“HUD 显示模式”：`标准`、`精简`。不要与现有“HUD 布局”、光晕“标准”、窗口占位／会话类型混为一个设置。

- 菜单栏：“HUD 显示模式”子菜单，两个互斥带勾选项“标准”“精简”。
- 设置：在“常规”中显示模式选择器，放在“HUD 布局”之前。
- 首次或读到无效值时使用标准模式。
- 两个入口读写同一 AppModel 属性，选择后立即保存。
- 切换模式不修改显示会话、参与 HUD 开关、轮播时长或当前轮播截止时间。
- “图标区域”“标题颜色”只作用于标准模式；精简模式下仍显示这些设置但禁用，附说明“仅标准模式生效”，保留其原值。背景透明度、光晕、钉住、布局仍正常生效。

### 3.2 精简布局的唯一参数

以下尺寸全部是 macOS 逻辑点，不是物理像素：

| 参数 | 固定值 |
| --- | --- |
| 横向窗口 | 144×40 |
| 竖向窗口 | 40×144 |
| 菱形视觉包围盒 | 14×14 |
| 标记区域沿长轴长度 | 40 |
| 状态灯区域沿长轴长度 | 104 |
| 灯径 | 沿用现有 26 |
| 灯间距 | 沿用现有 6 |
| 状态灯顺序 | 待处理红灯、完成黄灯、运行绿灯 |

菱形使用四个顶点组成的实心路径：在 14×14 本地坐标中为 `(7,0) → (14,7) → (7,14) → (0,7) → 闭合`。不要把边长 14 的方形旋转 45 度，这会形成约 19.8 点包围盒。无文字、描边、阴影、渐变、内置图案或独立身份动效。菱形位于 40×40 区域中心，空状态以外用会话 RGB 色填充。

四种布局必须一一对应：

| 原布局 | 精简排列 |
| --- | --- |
| 横向左 `horizontalLeft` | 灯区 → 菱形区 |
| 横向右 `horizontalRight` | 菱形区 → 灯区 |
| 竖向上 `verticalTop` | 灯区在上 → 菱形区在下 |
| 竖向下 `verticalBottom` | 菱形区在上 → 灯区在下 |

状态灯直接复用现有绘制与动效，不使用预览网页中近似颜色替换原生颜色。标准模式仍显示原有星光装饰、标题与状态灯；现有标题切换效果不变。

精简模式切换会话时，菱形填色和状态灯在同一会话快照中更新；第一版直接更新填色，不增加菱形动画。两种显示模式都继续保留 HUD 的无障碍会话名称和状态描述；无障碍名称不属于用户取消的可视标题提示。

无显示会话：菱形 `#808080`，三盏灯全部暗，保持精简窗口尺寸。此灰色是占位用色，自动分配排除它；手动选色不限制。是否存在“已保存的待机会话”不影响判定，必须看 `displayedSession == nil`。

### 3.3 设置中的标记

“置顶区域”在现有代码对应顶部“最近会话优先区”，使用已有 `recentSessionRow`，不新增置顶功能。

- 顶部会话行：`菱形选色按钮 → 现有标题及详情 → 状态 → 原有参与开关`。
- 会话区：`原有参与开关 → 菱形选色按钮 → 现有标题及详情 → 状态 → 删除按钮`。
- 两处标记均为 14×14 点，居中放入固定 28×28 点按钮区域，保留行内原有 10 点间距。
- 用真实按钮提供键盘焦点与点击范围；不要把整条会话行变成选色入口，不要嵌入标题编辑按钮。
- 可访问性名称：“修改会话颜色：<会话标题>”。标准和精简模式下均显示这些标记。
- 会话数据不可保存时禁用选色入口，沿用现有数据健康提示；失败时显示“颜色保存失败，未更改会话颜色”，不静默吞掉错误。

### 3.4 系统选色器

使用 macOS `NSColorPanel.shared`，点击菱形直接打开，不增加自制选色弹窗或中间页面。

- 每次打开绑定点击时的 `sessionID`，不可绑定轮播中的 `displayedSession`。
- 初始化为该会话已保存颜色；不提供透明度，`showsAlpha = false`，保存纯 sRGB。
- 使用连续选色，收到合法颜色变化后保存，成功才更新应用中的颜色。关闭面板只结束编辑，不回滚之前已保存的变化；第一版没有“确定／取消”流程。
- 从同一会话的另一列表入口打开仍编辑同一会话；点击另一会话重新绑定并装载其颜色。
- 面板由一个控制器统一管理，初始化颜色时暂时解除变更回调或设置装载标志，避免把初始化过程保存到上一个会话。
- 换目标会话后不得把旧面板回调写入新目标；会话删除、设置关闭或数据变为不可写时结束绑定并关闭面板。
- 保存失败：停止接收连续变更、恢复面板为上次已保存色或关闭面板、展示错误。不可更新 UI 后假装保存成功。
- 收到不可转换为 sRGB 的颜色时不写入，显示明确失败提示；正常颜色转换每通道乘 255、四舍五入并限制在 0…255。
- 不增加后台轮询、鼠标全局监听、权限申请、HUD 浮层或颜色编辑历史。

## 四、数据与自动分色：详细实现契约

本节算法与错误处理是为编码明确提出的实现决策，随整份规格审批。

### 4.1 数据字段

`PersistedSession` 增加 `markerColorHex: String?`，构造参数默认 `nil`，避免破坏现有调用。保存格式统一为大写 `#RRGGBB`，例 `#477EE8`，不存 NSColor、SwiftUI Color、透明度、色名或随机种子。新字段沿用现有 JSON 的驼峰字段名。`SessionDocument.schemaVersion` 保持 1。

新增纯核心类型 `SessionMarkerColor`，包含规范化、RGB 通道解析和分配逻辑。合法输入为去除首尾空白后符合 `^#[0-9A-Fa-f]{6}$` 的字符串；统一大写。其余值作为“缺颜色”。

兼容旧 JSON：字段不存在或为 null 时得到 nil。单独颜色字段为非法字符串、布尔、数字等错误类型时视为缺颜色，不因此让整份既有会话数据进入损坏保护。其他已有字段仍沿用原本严格解码，不用整体 `try?` 掩盖损坏。

若实现自定义 `init(from:)`，必须完整保留所有现有字段的键名、必填／可选规则；可先用现有会话 JSON 作为基线，新增颜色键只用局部容错解码。保持编码对称。不得重置 customTitle、项目、时间、参与开关、rotationIndex。

### 4.2 分配范围与稳定性

- 自动分配时检查全部已保存会话的有效颜色，包含未启用、非顶部区域、已待机的会话。
- 已有合法颜色保留，即使与其他会话重复；手动重复是允许行为，不做自动纠正。
- 不在 SwiftUI body、tick、轮播、标题变化或打开设置时重新分配。
- 旧数据及一批导入数据先收集整个批次的已有有效颜色，再对缺颜色记录按 `(rotationIndex 升序, sessionID 字典序)` 依次分配，并立即将新颜色加入占用集合。
- 删除会话后，该颜色可用于未来新会话；其他既有会话不重新分配。
- Hooks 新建、自动发现、手动同步、启动恢复四条路径都必须执行补色；同一会话同步不能覆盖已有颜色。
- 补色／改色不改变任意活动时间、设置排序时间、rotationIndex、状态或参与开关。

### 4.3 确定性的分色算法

第一版采用有界候选池和最大最小距离选择。目标是可复现、优先拉开色差，并保证自动颜色不与现有 RGB 数值完全重复；不是承诺任意数量会话的颜色都明显不同。

1. 规范化已有颜色为 `Set<String>`，排除 nil 和非法值；集合用于数值查重。
2. 候选池先包含预览的六个颜色：`#477EE8`、`#9963DD`、`#E458A3`、`#D77B23`、`#1597A4`、`#597344`。
3. 追加 HSL 候选：色相整数 0…359，饱和度依次为 0.65、0.80，亮度依次为 0.45、0.60。按 H→S→L 的固定循环顺序生成；HSL 转 sRGB 用标准分段公式，量化为 8 位通道，保留第一次出现的值并去重。颜色模块不依赖 AppKit。
4. 排除占用集合以及 `#808080`。没有已有颜色时优先返回 `#477EE8`。
5. 对每个剩余候选，计算它与每个占用颜色的距离平方：`0.30×(r1-r2)^2 + 0.59×(g1-g2)^2 + 0.11×(b1-b2)^2`，r/g/b 用 0…255 整数。该候选得分为这些距离的最小值。
6. 选择得分最大的候选；相等时取候选池中先出现者。比较距离平方即可，不需开平方。此加权 RGB 是第一版易实现的差异近似，不称为严格感知均匀色差。
7. 若候选池全部占用，按 RGB 整数从 `0x000000` 到 `0xFFFFFF` 查找首个未占用且不是 `0x808080` 的值；固定转换成六位十六进制。这个极端降级只保证不重复，颜色可能不好辨认，不偷偷覆盖已有会话颜色。
8. 所有可自动分配的值都被占用时返回明确的分配失败，禁止无限循环。调用方展示保存／分配失败，已有会话继续正常工作。

此方案无需“固定 6 色循环”、无界随机重试或外部颜色库。候选池生成可缓存；无需为自动颜色新增用户配置项。自动颜色对各种桌面背景不作绝对对比度保证，用户可在设置中修改。

### 4.4 写入顺序与失败

手动改色沿用标题编辑的“先保存候选集合，再发布状态”策略：

1. 验证数据可写、目标会话仍存在、颜色合法；相同颜色直接成功返回。
2. 复制目标持久化记录，仅修改颜色。
3. 用候选记录替换全部记录集合中同 ID 的记录，按 rotationIndex 与 ID 排序，调用现有 SessionStore 原子保存。
4. 保存失败时更新数据健康并抛错，不修改 machines、设置列表和 displayedSession。
5. 保存成功后写回对应状态机，通过 `publishSessions()` 更新列表。当前 HUD 若显示该 ID，用现有 `updateDisplay(id)` 更新快照。
6. 不调用 `refreshSessions()` 重新喂调度器来完成纯改色，不制造一次会话切换或重置轮播时钟。

启动恢复：加载成功后建立补色后的内存记录；有变化时批量保存一次，不逐条写磁盘。若补色保存失败，保留原有内存颜色分配供本次使用，按现有机制标记不可写并允许重试；明确不能保证重启保留，不覆盖损坏文件。

新建与导入：在对应既有批量保存之前完成补色，沿用原路径的失败处理；已存在记录 merge 时明确保留 live.markerColorHex，不能让发现结果中的 nil 覆盖用户选色。

## 五、显示模式、窗口几何与生命周期

### 5.1 类型与设置

新增 `HUDDisplayStyle: String, CaseIterable, Identifiable, Sendable`，值 `standard`、`compact`。不要复用已有 `HUDWindowDisplayMode`，后者只表示 placeholder/session。

`HUDPreferences` 增加键 `hudDisplayStyle` 与 load/save 方法；缺失或无效值返回 standard。AppModel 新增 `@Published var hudDisplayStyle`，初始化从偏好读取，didSet 保存。

现有 `HUDBackgroundAppearance.compact` 表示“标准 HUD 隐藏装饰图标”，并不等于此次精简显示模式。必须在代码命名／注释中明确区别。建议新增 `resolvedIconFraction`、`displaySize` 等明确接口；禁止把旧 compact 布尔值直接当作新模式开关。

### 5.2 唯一尺寸与参考坐标

继续使用现有 420 点参考长轴和每种布局的位置记录，不增加按模式区分的位置文件或偏好键。

长轴实际长度 L：

- 标准模式：现有装饰图标可见时 420；隐藏时 380；过渡过程仍为 `380 + 40×hudIconFraction`。
- 精简模式：144，始终不随图标隐藏设置或透明度变化。

参考矩形 R 为横向 420×40 或竖向 40×420。由 R 转实际显示矩形 D 的公式，采用 AppKit 屏幕坐标，y 向上：

| 布局 | D.origin | D.size |
| --- | --- | --- |
| horizontalRight | `(R.maxX-L, R.minY)` | `(L,40)` |
| horizontalLeft | `(R.minX, R.minY)` | `(L,40)` |
| verticalTop | `(R.minX, R.maxY-L)` | `(40,L)` |
| verticalBottom | `(R.minX, R.minY)` | `(40,L)` |

从 D 反推 R：horizontalRight 的 x=`D.maxX-420`，verticalTop 的 y=`D.maxY-420`，其余对应轴沿用 D.min；参考 size 固定 420×40 或 40×420。这与旧 380 点隐藏图标的锚点策略一致，切换模式时三灯一端位置稳定。

几何接口应接受显示样式，或通过 HUDGeometryState 携带；旧调用默认 standard 保持兼容。不能只改 SwiftUI frame 而不改 NSPanel 尺寸，也不能在保存位置时把 144 点矩形直接写成 420 点参考矩形。

所有 `appearance.size`、`displayFrame`、`referenceFrame` 调用都逐个核对，包括初始化、重建、拖动完成、布局切换、恢复位置、保存位置、重置位置、显示器断开／恢复及 legacy migration。已有参考记录版本保持 3。

屏幕边缘按现有 clamped 方法保证当前显示矩形在可见区域内；不要因临时屏幕钳制或模式切换保存漂移后的锚点。精简模式下真实拖动结束则按照上述逆变换保存新参考位置。

### 5.3 模式切换流程

第一版模式切换不新增缩放动画，用现有面板替换机制同步更新窗口与内容，降低标题残影和尺寸错位风险；标准模式原有透明度／装饰图标动画仍保留。

1. 观察 AppModel 的样式变化。Combine `@Published` 会在存储属性更新前发送值，回调必须携带传入样式，或像现有菜单刷新一样推迟到主队列后读取，禁止同步读旧值。
2. 结束正在进行的大小动画；如正在拖动，取消旧拖动并按当前可见位置反算参考矩形，避免继续拖动已退休窗口。
3. 不更改当前会话快照或调度器；用目标样式、当前布局、当前 placeholder/session 类型重建面板。
4. 由参考矩形计算目标显示矩形，再做屏幕钳制；继承显示／隐藏、钉住穿透、背景透明度、屏幕信息等现有状态。
5. 同一面板生命周期中，HUDView 捕获的布局与样式应与窗口对应；不要让旧 SwiftUI 树读取新样式而绘制进旧尺寸窗口。
6. 快速连续切换时，以最新设置为准，不保留多个可见 HUD；延迟回调检查目标是否仍有效。
7. 应用隐藏 HUD 时仍可更改样式，下次显示使用最新尺寸；无会话与有会话之间仍走现有 placeholder/session 替换路径，并继承样式。
8. 精简模式改变透明度只改背景，不改变 144 长轴或标记可见性。切回标准模式按保存的图标设置和当前透明度恢复 380／420 长轴。

## 七、实施顺序与阶段验收

按用户工作流：批准后逐项实施，每个主要文件改动完成后暂停等待用户确认。除非用户随后明确授权连续实施。此规则不代表每阶段自动批准所有文件。遇到规格变更先更新本文件并取得批准。

### 阶段 1：数据与纯逻辑

建立颜色模块、增加持久化字段、接入四种补色与改色路径。验收旧会话可读取、新会话自动分色、手动改色保存、导入不丢色、排序与状态不变。界面暂不要求显示颜色，但核心可验证。

### 阶段 2：显示模式与几何

新增偏好与样式、共享菱形视图、HUD 两种分支、面板尺寸与位置规则。验收四种精简布局、标准回归、空状态、透明度、钉住、拖动、切换位置稳定。没有完成窗口几何前不得把仅缩小 SwiftUI 内容报告为已实现。

### 阶段 3：菜单与设置选色

增加双入口模式切换与系统选色控制器，把同色菱形放到两种会话行规定位置。验收点击正确会话、跨列表联动、轮播期间目标稳定、关闭／删除后不误写、失败反馈。

### 阶段 4：整体验收与文档

运行必要检查与既有测试；在真实 macOS 窗口中验证视觉及交互，更新 README，记录无法验证项。浏览器预览不能代替原生 HUD 验收。不自动安装到系统目录；按用户本次授权逐阶段提交，不发布远端。

## 八、测试决策

不采用 TDD，不给纯视图布局、按钮文字或设置 getter 编写镜像测试。新增测试集中在有边界的数据与复杂窗口状态转移；优先沿用现有测试风格与 fixture。

| 范围 | 必验外部行为 |
| --- | --- |
| 颜色模块 | 规范化；非法输入；空集合首色；避开有效占用及占位灰；手动重复不改写；同分确定性；多条补色互不重复；候选耗尽降级；无法分配时终止 |

## 十、范围外与禁止误解

1. 不做 HUD 悬停标题、会话信息菜单、浮层或钉住悬停检测。
2. 不做按会话单独选择显示模式、形状、大小；第一版固定全局模式与 14 点菱形。
3. 不把菱形颜色改为状态色，不用同一颜色同时表达身份与状态。
4. 不增加置顶功能；“置顶区域”指已有顶部最近会话区域。
5. 不改变状态机、轮播规则、完成超时、自动启用、项目分组或标题编辑。
6. 不修改应用图标、菜单栏品牌图标、应用包图标资源。
7. 不把“颜色有很多”实现为固定 6 色循环；不承诺百万颜色肉眼可辨。
8. 不新增透明度选色、颜色重置按钮、调色板管理、颜色搜索或批量重配。
9. 不把新精简模式与旧隐藏装饰图标造成的 compact 状态混用。
10. 不因为新选色功能重排会话、更新 lastActivityAt 或重置轮播。
11. 不为颜色数据另建 JSON 文件，不在视图渲染时随机生成颜色。
12. 不新增第三方依赖、外部服务或系统权限。
