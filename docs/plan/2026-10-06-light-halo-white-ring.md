# 标准与强烈光晕收缩白圈修订

Related discussion: [docs/discuss/2026-10-06-light-halo-white-ring.md](../discuss/2026-10-06-light-halo-white-ring.md)

状态：用户已批准连续实施。第一阶段诊断及验证已完成，静态与连续离屏均未复现浅白环，实屏测试缺少录屏权限跳过。按本文证据停止条件，第二阶段暂未选择生产修正，第三阶段未执行；详细阻塞记录见文末。不要改动已通过实屏的布局和默认标题窗口交接。

## 问题与目标

标准和强烈模式在灯体变暗、缩小时出现浅白环。用户怀疑外圈不同步；当前代码实际无独立 stroke，半径同帧计算，此怀疑尚未证实。目标是消除灯体与光晕之间明显浅色分隔环，保留正常同色柔光，不能要求渐变全部不透明或把自然淡出误判成白圈。

1. 红黄绿、标准强烈均覆盖。
2. 保留尺寸缩放、周期、状态映射及点亮 55%～100%、未点亮 18%。
3. 光晕随进度收拢、变淡，q=0 消失；不能靠固定灯体或取消光晕掩盖缺陷。
4. 保持 26×26 灯位、灯距、窗口尺寸与标题行为。
5. 强烈保留相对标准更明显的扩散及强度，不叠加白色补边。

## 先诊断，后选择实现

读取 `HUDView` 中 `StatusLight → StatusLightFrame → synchronizedHalo`，以及核心动画参数、原生渲染测试和旧 `2026-10-01-light-halo-radius-sync` 规格。现有 R=13×scale，W=模式最大宽度×q，光晕内侧 R-1、外侧 R+W；不能把它误读成固定半径。

### 第一阶段：原生证据

不改生产灯效，增加可重复诊断与对应验证：

- 三色、两模式，固定 q=0、0.02、0.05、0.1、0.25、0.5、0.75、1；重点低进度，旧测试只有四分之一间隔不足。
- scale=1 与 2 像素倍率，透明、浅灰、白、深灰背景，保持足够大的画布，不让光晕被测试边界裁切。
- 比较透明 alpha 与合成后的 RGB/亮度。沿八个径向采样检查：有没有接缝附近亮度向背景跃升，随后外侧又回到明显灯色的分隔带。自然向外变淡、单像素抗锯齿不能算失败。
- 输出固定帧诊断图和径向曲线供检查；记录具体颜色、模式、q、倍率及背景。不能只检查中心 alpha 或整个环平均值后宣称无白圈。
- 连续视图按上升再下降序列更新同一对象，比较相同 q 的当前结果与新绘制参考，检查上一个较大半径轮廓是否残留。离屏相等只是辅助证据，真实窗口仍需连续采样。
- 真窗口采样不得切布局、移动窗口、重建窗口或改变透明度促刷；缺录屏权限明确跳过，不把离屏通过写成系统合成通过。

记录分支：静态也出现分隔带、仅连续更新出现旧轮廓、仅实屏出现、当前无法复现。不能强行将所有结果解释为半径错误。

### 第二阶段：最小修正

按诊断证据选择，不能一次叠加全部候选：

1. **静态渐变颜色问题**：验证 `.clear` 的插值颜色与预乘透明度是否引入异常。候选为仅使用当前灯色的透明端点，或用同色填充加连续 alpha 遮罩；选择原生像素验证有效的一种，不能假定换透明端点必然修复。
2. **边界合成衔接问题**：检查灯体抗锯齿与光晕内侧覆盖；将灯体与光晕在同一绘制对象、同帧路径中合成，并设计连续的边缘 alpha 衰减。允许调整衔接形状，但不能改灯体中心目标 alpha、峰值扩散范围、颜色或动画进度。不得简单拉高整圈亮度形成另一种描边。
3. **连续更新残留问题**：候选为单一 Canvas 绘制完整灯体与光晕，每帧完整替换绘制内容，明确更新 bounds 与绘制范围；先在同实例连续测试验证。不能通过随机 id、每帧重建窗口、额外时钟或强制 display 解决。
4. **只有实际窗口出现或无法复现**：继续收集真实帧证据；不提交“已修复”生产补丁。若缺权限且无静态/连续诊断证据，说明阻塞原因，请求必要实屏信息，停止猜测叠补丁。

实现修改以应用灯效绘制模块为限；若采用 Canvas，保留 `StatusLightFrame` 输入与固定布局占位，调用者和核心时间源不变。删去被替代的旧绘制实现，不保留叠加保险层。

可以自主选择上述已批准范围内的最小候选，不需要每个技术选项重复申请批准。若需要改变产品亮度、周期、缩放幅度或峰值强度，则更新规格并取得用户批准。

### B. 构造固定帧，不依赖运行时恰好落在哪个相位

对每个 q，正常点亮参数按以下方式构造：

```text
scale = 0.9 + 0.2 × q
bodyOpacity = 0.55 + 0.45 × q
glowIntensity = q
R = 13 × scale
W = (standard ? 4 : 7) × q
outer = R + W
```

这是测试固定帧，不得替换生产 `HUDLightAnimation.parameters`。未点亮使用 active=false，实际半径13、alpha0.18、无光晕；即使传入旧峰值参数也不得画光晕。减少动态效果使用原参数函数输出的 R=13、alpha1、q=1，不能直接套正常动画峰值 R=14.3。

q=0.02 时标准 W 仅0.08点、强烈仅0.14点，小于一个屏幕像素。此时不得要求“外侧必须出现一个完整有色像素”或除以零；q=0 不创建光晕、不得生成重复停止位置。弱光或亚像素帧若无法可靠测量某项指标，单独报告该指标不适用，其他中心、范围和连续序列检查仍执行。

测试画布为64×64逻辑点、圆心(32,32)。渲染倍率 s=1 或2，像素尺寸必须是64s×64s。像素中心转逻辑坐标：`((x+0.5)/s, (y+0.5)/s)`，半径按该坐标到(32,32)距离计算。不能固定使用原测试的倍率2索引，也不能把倍率当作光晕半径倍数。

背景固定为透明、sRGB白(1,1,1)、浅灰(0.85,0.85,0.85)、深灰(0.2,0.2,0.2)。离屏背景不使用动态毛玻璃、材质或系统窗口背景色，以免不可重复。实际毛玻璃效果另由真实窗口验证。

### C. 像素读取与合成不能混用预乘数据

建立唯一测试图像解析辅助：将 CGImage 绘制到明确 sRGB、RGBA8、premultipliedLast 的 CGContext，记录 width、height、bytesPerRow。不能假设任意 CGImage.dataProvider 的原始字节已经是 RGBA。

读取透明图时，若 RGB 是预乘值，alpha>0 才除以 alpha 获取颜色；alpha接近零时不要比较色相。与背景合成使用预乘公式 `C = P + (1-alpha) × B`，P是预乘RGB；不能再乘一次alpha。RGB误差和径向指标统一在同一色彩空间计算；要使用线性亮度时先转换sRGB到线性，不能把sRGB和线性结果放进同一阈值。

当前灯色使用生产 `kind.color` 经相同渲染路径获取基准，不硬编码“绿色=(0,1,0)”。SwiftUI 系统红黄绿实际颜色不一定等于纯RGB原色。

### D. 白圈判定与测试校准

“白圈”指灯体附近出现连续浅色分隔带，随后外侧又有可见灯色或上一帧轮廓。普通向外单调淡出到背景不算白圈；中心变暗后整体更接近浅灰背景也不算白圈。

每帧输出透明alpha、合成RGB、相对背景颜色距离及可选线性亮度。沿八个方向，在 R-2 到 outer+2 区域按真实像素采样，并输出径向环带均值作为辅助。倍率1的重复最近邻采样不算多个独立点。

颜色距离可采用三通道归一化欧氏距离。检查是否存在“距离背景减小到局部谷值，随后外侧又明显增大”的结构。亮度则检查“局部接近浅色背景，随后又下降”的对应结构。二者联合识别，不只判断某一通道大或小。

阈值先校准再固定：

1. 渲染同一灯色的单圆控制样本，没有外圈；取得抗锯齿与亚像素边缘允许误差。
2. 构造测试专用故障样本：同色灯体外人为留1～2点透明间隔，再绘制同色外环；诊断器必须在两倍率、浅背景识别它。
3. 构造连续单调alpha渐变控制样本；诊断器不得将自然淡出误报为白圈。
4. 将控制样本导出的阈值、宽度容差与校准结果写入记录。然后测试生产帧，不能看到生产失败后再放宽阈值。
5. 抗锯齿区的一像素波动不单独判产品失败；亚像素阶段依靠多方向、控制样本和连续帧综合，不武断要求所有径向曲线数学单调。

诊断器测试验证实际图像，不能直接从 R/W 公式生成“生产预期像素”来证明生产没有缺陷。第一阶段的缺陷报告可记录检出的分隔带而不让整套诊断测试故意长期红灯；该阶段必须断言诊断器能分辨故障样本和正常控制样本。第二阶段才断言已定位生产缺陷消除，不采用 TDD 流程。

### E. 连续下降必须复用同一承载

测试创建一个仅测试使用的 ObservableObject，保存当前 visual；测试视图从它读取参数并创建 `StatusLightFrame`。整个序列只创建一个 NSHostingView 和一个根展示对象，不在每个q重新安装 contentView。

建议序列：`0 → 0.25 → 0.5 → 0.75 → 1 → 0.75 → 0.5 → 0.25 → 0.1 → 0.05 → 0.02 → 0`，重复两轮，三色两模式均覆盖。更新参数后允许SwiftUI处理主循环，不调用 needsDisplay、displayIfNeeded、layoutSubtreeIfNeeded、移动或重装承载。每帧记录目标q和采样完成时间，不混入下一帧。

可用同一 ImageRenderer 做离屏更新辅助，但它不等于当前 NSHostingView 的持久渲染，也不等于 WindowServer。必须标明每份结果属于参数、离屏、新鲜绘制、承载更新还是实际屏幕。

参考帧可用独立新鲜渲染生成；实际窗口采样期间不得显示参考窗口。比较同q上升、下降、新鲜渲染的外侧残留，特别检查“上一个R附近的环带”，不仅当前outer外两点。不要逐字节比较实屏PNG来判断动画，使用校准过的区域容差。

真实窗口使用真实 Hook 让当前灯保持对应状态，至少观察两个周期。记录事件、referenceTime或采样时间、模式、屏幕倍率、frame和窗口编号；采样期间这些位置与身份应不变，不能通过换窗使旧轮廓消失后再判通过。

### G. 如采用单一Canvas，必须遵守的结构

Canvas不是默认选定方案，只有相应证据支持时采用。

- 先计算一次 R/q/W/中心/最终范围，再同一绘制闭包绘制完整灯效，使用普通source-over同色合成，不使用加亮、screen或白色补边。
- 绘制画布固定且足够容纳最大半径；不能让Canvas自身尺寸随q缩小，以免较大帧区域不在下一帧更新范围。
- 正常最大半径21.3点，单灯绘制画布可用44×44逻辑点、中心(22,22)；外层布局占位仍26×26，居中不改变灯距。不添加 clipped 剪掉该画布边缘。实际40短轴窗口裁切仍独立验收，不扩大窗口。
- 更新同一Canvas的输入，不使用随机id；不将光晕拆到第二个不同时间源的Canvas。
- active=false只画半径13、alpha0.18的灯体；q=0只画正常点亮最低帧，不保留上一帧渐变。
- 清空画布采用Canvas本身每次完整绘制语义，不对整个应用截图或用背景色覆盖透明区域。若使用CoreGraphics位图替代，须显式清透明再绘整张位图，不能复制上一帧缓存。
- 同色衔接不得提升中心alpha；灯体与光晕重叠边缘的最终alpha可按现有source-over处理，但不得把整圈改成与中心同样不透明。
- 删除被替代的 `synchronizedHalo` 及旧ZStack双路径；保留外部 `StatusLightFrame` 接口、无障碍与布局契约。
