# HUD 适中模式与标题循环滚动

日期：2026-10-09。状态：2026-10-10 已获用户批准并完成全部开发阶段；构建与完整测试通过，实屏权限限制见验证记录。已补充面向编码模型的详细执行附录。

## 问题陈述

标准 HUD 标题区较长，占用空间较多；精简 HUD 只有会话标记和状态灯，无法直接阅读标题。用户需要介于两者之间的显示模式，通过较短标题窗口阅读完整长标题，并在会话轮播或抢占后继续上次阅读进度。

## 解决方案

新增“适中”模式。标题区固定 100 点，保留精简版彩色菱形与三盏状态灯。能完整容纳的标题静止，超长标题匀速无缝循环。横向向左，竖向向上。每会话独立保存本次运行的滚动进度，切走暂停，切回续播；会话切换时机保持现有规则。

## 用户故事

1. 作为用户，我希望从标准、适中、精简三档选择 HUD 大小，以兼顾阅读和空间。
2. 作为用户，我希望适中模式保留彩色菱形，以识别当前会话。
3. 作为用户，我希望短标题静止，以便快速阅读。
4. 作为用户，我希望长标题显示完整内容并循环，以读到被窗口裁剪的部分。
5. 作为用户，我希望横向文字向左、竖向文字向上移动，以按正常顺序阅读。
6. 作为用户，我希望滚动无停顿、无位置跳变，以保持连续视觉效果。
7. 作为用户，我希望会话按原轮播和抢占规则切换，以及时看到状态变化。
8. 作为用户，我希望返回某个会话时继续之前进度，以逐次读完长标题。
9. 作为用户，我希望 HUD 隐藏或切换模式后保留进度，以恢复此前阅读位置。
10. 作为用户，我希望横竖切换保留相对进度，以避免重新从头阅读。
11. 作为用户，我希望标题修改后从头阅读，而灯色和状态变化不打断进度。
12. 作为用户，我希望应用重启后重新开始滚动，以避免不必要的进度存储。
13. 作为用户，我希望系统减少动态效果时停止滚动，并仍可获取完整标题。
14. 作为用户，我希望三种模式切换不产生窗口残影、尺寸错位或位置漂移。

## 实现决策

### 模式与几何

- 模式顺序为标准、适中、精简；新增独立存储值，保持旧值及默认标准模式兼容。模式选择继续持久化，滚动进度不持久化。
- 适中标题区域总长度为 100 点，包含两端内边距；沿用每端 6 点，实际文字窗口为 88 点。溢出判断按实际文字窗口测量，而非按汉字数量估算。
- 复用精简模式 40 点标记区、104 点灯区，适中总长为 244 点、短边为 40 点。横向为 244 × 40，竖向为 40 × 244。边框不额外扩大窗口尺寸。
- 四种布局沿用现有区域排列与固定边缘锚点。横向左/右均向左滚动，竖向上/下均向上滚动；灯的位置不决定滚动方向。
- 适中彩色菱形固定保留，不受标准模式图标显示设置与透明度阈值影响。图标区域设置仅标准模式可用；标题颜色设置在标准和适中模式可用。更新相关设置说明。
- 保留原透明度、灯光、钉住、拖动、屏幕位置恢复与完整无障碍标题。

### 循环运动与文本绘制

- 使用真实排版尺寸判断溢出。文字长度小于或等于有效窗口时静止；超出才滚动。初次展示从标题开头可见的位置开始，不先等待文字从窗口外进入。
- 默认速度 20 点/秒，循环副本间隔 24 点，本次不增加速度、间距或长度设置。
- 循环周期长度为完整文本沿滚动轴长度加 24 点。绘制相邻副本，裁剪到标题窗口；上一副本移出时下一副本进入，周期边界不得出现整段闪回或长时间空白。
- 横向保持现有字体、字号、颜色和单行排版。竖向复用现有中英文分段规则：中文直立，连续拉丁片段保持现有旋转方式；完整测量所有片段，不预先省略、不拆坏字符簇。
- 标准模式继续使用原静态省略展示；适中正常滚动展示完整文本。开启减少动态效果时才使用静态省略方案。
- 会话切换沿用现有入场、退场动画；滚动只影响内层文本，不移动菱形、灯或 HUD 外框。出场内容冻结最后可见偏移和标题快照，避免旧文本读取新会话内容。

### 会话滚动状态模块

- 应用级内存状态仓库按稳定会话标识保存记录，独立于窗口、标题视图及会话占位切换。设置预览不能推动正式 HUD 的进度，也不能重复计时。
- 记录至少包含完整标题身份、循环相对进度、当前排版周期长度、活动计时基准。提供激活、暂停、采样、更新标题/排版、删除记录等操作；纯状态逻辑允许注入单调时钟。
- 只为当前可见、处于适中模式、确实溢出且允许动态效果的正式会话累计滚动时间。按单调经过时间计算距离，避免系统时间调整引起跳动。
- A→B：同步保存并暂停 A，激活 B 的独立记录。B→A：恢复 A 的冻结进度。相同会话的状态更新不得反复重新激活或重置计时。
- HUD 隐藏、离开适中模式、没有活跃会话、开启减少动态效果时暂停。恢复显示后续播，暂停期间经过的时间不补算。
- 窗口因模式、布局、占位切换重建时，先冻结旧窗口进度，再交接新窗口；退役窗口和预览不能继续写入活动记录。
- 横竖转换前取得循环相对进度 p，新排版偏移为 p × 新循环长度。由新长度重新计时，之后仍保持 20 点/秒；不得直接复用旧方向的点数。
- 如果排版变化后标题不溢出，停止计时并静态显示，保留相对进度供再次溢出时使用。
- 同一会话标题内容变化，无论当前是否展示，均重置为开头；状态、标记颜色、标题颜色变化不重置。记录在再次激活时也必须验证标题身份，避免漏掉后台修改。
- 暂时待机、取消参与显示不清除记录，重新展示仍续播。会话真正删除时清理对应记录，清空会话时清空仓库，退出应用时自然释放。无会话占位标题静止，不创建会话进度记录。
- 系统休眠期间不计入可见滚动时间，唤醒后继续冻结位置；订阅必要的生命周期事件，避免补算休眠时长。

### 可访问性与性能

- 系统减少动态效果开启时，冻结内部进度，但视觉显示标题开头及必要省略号；关闭后恢复冻结进度。会话过渡继续遵循现有减少动态效果策略。
- 读屏始终提供完整原始标题和状态，不包含循环副本；循环副本不重复进入无障碍树。
- 活跃长标题采用约 30 帧/秒的采样即可；隐藏、短标题和非适中模式不持续刷新。缓存文本测量和绘制布局，颜色或时间更新不重复解析文字。

## 实施顺序

1. **模式与布局**：增加适中枚举与存储兼容；统一三档几何；接入菜单、设置、窗口尺寸、标记和标题颜色可用性。验收四种布局中尺寸正确、锚点稳定、只出现一个菱形。
2. **进度状态**：建立可独立验证的会话滚动仓库；完成暂停、续播、标题重置、排版进度转换与清理。验收 A→B→A、模式切换和时间边界。
3. **完整标题渲染**：实现横向与混合竖向全文测量、裁剪、副本循环。验收短标题不动，长标题匀速、无缝、无额外省略。
4. **生命周期接入**：对接正式展示、窗口交接、隐藏、减少动态效果及休眠；退场内容使用冻结快照。验收窗口重建续播、快速切换无残影、轮播时长不受滚动影响。
5. **验证与记录**：完成必要状态与集成测试，人工查看四种布局、混合文字和跨周期画面，记录验证结果。

### 三、状态数据与计算公式

推荐将记录保存在纯 Swift 字典 `[String: Record]`，键是 `SessionSnapshot.id`，不是标题、项目名或轮播序号。

```text
Record:
    title: String             // 实际 sessionListTitle，作内容身份比较
    phase: Double             // 最近冻结/配置时的相对进度，0 <= phase < 1
    cycleLength: Double       // 最近一次有效排版的完整长度 + 24
    startedAt: Double?        // 正在活动时的单调时间，暂停时 nil

Store:
    records: [sessionID: Record]
    activeSessionID: String?  // 最多一个活动会话
```

纯状态 API 应覆盖：`configure`（标题与排版变更）、`activate`、`pauseActive`、`sample`、`synchronizeTitles`（标题重置及删除清理）。所有时间参数显式传入，单位秒；测试传入 0、1、2 等数值即可，不等待真实时间。

核心公式：L 为完整文字长度，W=88，G=24，v=20，C=L+G。

```text
如果 L <= W：画面 offset = 0，不活动，内部保留原 phase

如果 L > W 且未活动：
    p = record.phase

如果 L > W 且活动：
    elapsed = max(0, now - startedAt)
    p = positiveModulo(record.phase + elapsed * v / C, 1)

offset = -p * C
第一个文本副本起点 = offset
第二个文本副本起点 = offset + C
```

横向起点指 x，竖向起点指从顶部向下为正的 y。负值在屏幕上表示左移或上移。NSView 使用 `isFlipped == true`；Core Text 的坐标翻转仅用于绘制字形，不再把滚动方向翻转一次。

滚动时 L>W，所以 C>W，两个副本足以覆盖可见窗口。文本尾部到下一轮头部之间保留 24 点空隙；允许该空隙移动经过窗口，禁止人为把整窗清空后再从窗外开始。p 从接近 1 回到 0 时，第二副本成为下一周期的第一副本，画面位置应连续。

`sample` 必须只读取，不改变 `phase` 或 `startedAt`。每一帧若同时累加 phase 又使用从 startedAt 起的全部时间，会重复累计并越来越快。

冻结操作：

```text
pauseActive(now):
    如果没有 activeSessionID：直接返回
    record.phase = sample(activeSessionID, now).phase
    record.startedAt = nil
    activeSessionID = nil
```

重新激活：

```text
activate(id, now):
    如果同一 id 已活动，且标题/排版/运行条件完全未变化：直接返回
    pauseActive(now)
    若此 id 的文字不溢出或运行条件不满足：返回
    record.startedAt = now
    activeSessionID = id
```

配置/排版变更：

```text
configure(id, title, L, now):
    若 id 正活动：先按旧周期 sample，再冻结旧记录
    若是新记录：phase = 0
    若 title 与记录不同：phase = 0
    否则：保留刚冻结的 phase
    将 cycleLength 更新为 L + 24，保存 title
    此函数不自行决定是否激活；交给协调器统一 reconcile
```

协调器必须比较标题、方向、字体、可见性等配置是否真的改变；每次绘制或每次相同会话状态发布时，不重复 configure/activate。

标题在后台改名时，`synchronizeTitles` 用已提交的 `[id: sessionListTitle]` 比较仓库记录，变化即归零。删除只按完整会话列表的 ID 判断，不能使用“当前参与轮播列表”清理，否则取消参与或待机会丢进度。无需为从未显示过的会话预先分配记录。

对 NaN、无限长度、非法时钟值使用静态显示并暂停的保护分支，禁止除以 0；正常有效测量值不额外取整来改变溢出判断。

### 四、协调器与展示生命周期

职责固定：AppModel 持有长期状态；HUDPanelController 决定正式窗口的可见性与代际；HUDWindowPresentation 传递当前会话；标题 NSView 只绘制。禁止标题视图使用 `.onAppear` 重置会话进度。

协调器使用 `@MainActor`，时钟默认 `ProcessInfo.processInfo.systemUptime`。创建递增 `generation` 作为正式窗口令牌；旧窗口晚到的回调带旧 generation，必须直接忽略。预览没有正式 generation，只接收静态 phase=0 的展示，不启动计时或写入仓库。

活动条件全部为真才启动刷新与计时：

```text
有有效的当前正式窗口令牌
&& 正式窗口已经显示
&& 当前窗口模式为 medium
&& 当前有真实会话
&& 完整文字长度 > 88
&& 系统未要求减少动态效果
&& 未处于系统/屏幕休眠
```

统一用 `reconcile` 根据以上条件暂停或激活。计时器放在协调器，最多一个，使用主线程 common 模式约 30Hz。每帧只向当前标题展示订阅发送 frame；不要发布整个 sessions 数组或触发轮播调度。停用时 invalidate，协调器释放时清理计时器及通知订阅。

| 输入事件 | 必须按顺序执行 |
| --- | --- |
| A→B | 同一次主线程操作读取 now；冻结 A 并生成 A 的出场快照；验证 B 标题身份并取得 B 记录；配置 B 排版；用同一 now 激活 B；发布新展示内容。 |
| B→A | 冻结 B；读取 A 保存的 phase，不归零；激活 A；发布 A。 |
| 同会话状态变化 | 更新灯与无障碍状态；标题不变则保留 startedAt 和 phase，不执行重启。 |
| 同会话标题变化 | 冻结旧标题，保存旧出场快照；配置新标题归零；符合条件时激活新标题。标题相同则不重置。 |
| hide | 在 `orderOut` 前冻结并关闭刷新，标记窗口不可见。 |
| show | 先同步布局/模式，完成 `orderFrontRegardless` 后标记可见，再 reconcile。隐藏时不能提前开始累计。 |
| 窗口替换 | 旧窗口尚在时冻结并使旧 generation 失效；保持现有旧窗退休顺序；新窗口创建后取得新 generation；完成显示后按当前条件续播。隐藏状态替换仅配置，不激活。 |
| 开启减少动态效果 | 冻结内部 phase，停止刷新，画面 offset=0 并启用静态省略；不能把仓库 phase 改为 0。 |
| 关闭减少动态效果 | 关闭省略，用仓库原 phase 配置当前排版并续播。 |
| 系统/屏幕休眠 | 收到 NSWorkspace willSleep/screensDidSleep 通知立即冻结，置休眠标记，停止刷新。 |
| 唤醒 | 根据 didWake/screensDidWake 清除对应休眠标记；只有所有暂停条件均解除才重新激活，不能补算睡眠时长。 |
| 删除/清空会话 | 在会话列表完成修改后同步有效 ID；停止被删除的活动记录，清理字典；不要等待下一帧才停止。 |

现有 Combine 的 `@Published` 回调在属性真正赋值前执行：

- 会话标题和 ID 使用 sink 的传入快照，不立即回读 `model.displayedSession`。
- 现有布局/模式同步通过主队列延后执行，保持这种“读取最终组合”的方式；实际渲染使用窗口创建时固定的 `layout/style`，不能在旧窗里提前画新布局。
- 协调器正式展示输入应由当前 presentation 与 panel 的令牌共同确认；旧窗口不能因晚到的 sink 恢复活动。
- AppModel 的 `publishSessions` 在 sessions 赋值后同步标题身份和 ID；失败的标题编辑尚未提交时不要提前重置仓库。

会话过渡快照至少包含 sessionID、title、方向、文字布局、颜色、冻结 offset。旧标题 NSView 保留自己的最后一帧；它失去活动令牌后不再订阅新 frame，也不读取当前新会话的 title。保留现有外层 transition，不给循环偏移套 `.animation`、`repeatForever` 或 `autoreverses`，避免与数学进度叠加。

### 五、全文排版与绘制细节

横向以现有 13 点 medium rounded 字体建立完整 `CTLine`，通过 `CTLineGetTypographicBounds` 测量 L，再用同一 CTLine 绘制。禁止先 `.lineLimit(1)` 加 `.truncationMode(.tail)` 得到短字符串后滚动，也禁止用字符数乘字号估算。

竖向目前 `MixedTitleNSView.draw` 调用 `VerticalTitleMeasurer.layout(maximumLength: ...)` 得到截断结果。适中正常滚动必须绕过该截断调用，测量所有 segment 的 advance 之和作为 L，依次绘制完整 segment 列表，再由外层 88 点窗口裁剪。

现有竖向 parser 会把部分标点/表情变成分隔，不保证全文无损。为适中增加 `segments(for:preserveUnsupportedCharacters:)` 参数，默认 false 保留标准行为；适中调用 true。新增 `.upright(Character)` 分段保留未被汉字/拉丁/合法连接符规则接纳的非空白字符，单个表情使用完整 Swift Character，不能拆 Unicode 标量。为新增 case 补齐测量与绘制 switch；标准模式默认解析结果不变。空白继续沿用原分隔与拉丁内部空格规则。

- `.han`：沿用原直立字形及 advance。
- `.latin`：整个片段顺时针旋转，与标准版一致；按完整 CTLine 宽度作为沿竖轴长度，不能按 88 点先裁掉后半个英文单词。
- `.upright`：直立绘制完整字符簇；advance 至少为原汉字 advance 与该字符实际字形高度中的较大值。
- `.gap`：沿用 4 点间隔。
- 跨轴超宽的单个字形只在必要时等比缩小至 40 点可用宽度；测量与绘制使用相同缩放结果，不裁掉半个字形。

新布局对象保存每段的绘制位置、沿轴 advance 与必要缩放。缓存键包括 title、横竖方向、字体描述、backingScaleFactor；颜色不影响测量。窗口跨显示器后 backingScaleFactor 改变要重建布局并保留相对 phase。

适中区域的坐标顺序：外层 100 点容器 → 前端 6 点留白 → 88 点 clip rect → 后端 6 点留白。对 clip rect 内设置 CGContext clip，再平移绘制两个全文副本，不能把整个 244 点 HUD 一起 clip/offset。保留各自保存/恢复 graphics state，Core Text 坐标变换沿用现有方法。

短标题只画一份，沿滚动轴左对齐/顶部对齐，从有效窗口起点显示。无会话时 `Traceflow` 占位同样只画一份且不创建记录。减少动态效果时，使用标准省略算法，但 maximumLength 改为有效窗口 88，不使用标准区长度。

### 八、禁止的简化实现

- 不用每次 `.id(session.id)` 创建视图后的局部 State 作为唯一进度来源。
- 不把未展示时间加入进度，不使用全局墙上时钟直接对全部会话取模。
- 不以标题字符串为记录键，不把相同标题的两个会话合并。
- 不按轮播时间强制滚完，不改 CarouselScheduler 或展示时长。
- 不用 autoreverses 左右往返，不把循环设置为反方向，也不每轮停顿。
- 不滚动省略后的短文本，不把竖向全文先截到 88 点。
- 不通过隐藏菱形套用标准图标设置，不给适中多画一个图标。
- 不将进度写入 UserDefaults、会话记录或日志持久化文件。
- 不让旧窗口/预览启动第二个计时器，不在每帧重解析/测量全文。
- 不修改标准和精简现有行为来迁就新增模式。
