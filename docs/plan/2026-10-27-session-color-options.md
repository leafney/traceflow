# 会话固定颜色候选

Related discussion: [docs/discuss/2026-10-27-session-color-options.md](../discuss/2026-10-27-session-color-options.md)

## 问题与目标

当前所有会话的颜色浮层使用同一组六个预设色。用户希望不同会话具有不同推荐，同时同一会话重复打开时颜色位置稳定。

## 用户可见行为

- 每个会话依据其稳定会话标识，得到六个固定的基础候选色。多次打开、应用重启，以及其他会话颜色变化，都不改变这组基础候选。
- 不同会话尽量获得不同组合；允许部分或全部颜色碰巧相同，不承诺全局唯一，也不随其他会话动态避让。
- 当前颜色位于基础候选中时，保留候选顺序，并在对应色位显示选中标记。
- 当前颜色不在基础候选中时，第一色位显示当前颜色并标记选中，第二至第六色位显示基础候选的第二至第六项。若当前颜色尚不存在或无法解析，显示完整基础候选，不虚构选中状态。
- 用户选择预设色或自定义颜色后继续使用现有保存逻辑；保存成功后按照以上规则显示当前颜色。保留“自定义”入口和系统颜色面板。
- 颜色显示不只依赖颜色本身：保留勾选标记和可访问名称。

## 实现说明

- 当前浮层位于 `Sources/TraceflowApp/MenuWindowView.swift`；当前色值来自 `session.persisted.markerColorHex`。在共享核心模块增加纯函数，根据会话 ID 和当前颜色返回六个展示色及选中状态；视图只消费结果，不另存候选颜色。
- 从固定、版本明确的颜色池选择六种不同颜色；使用跨进程稳定的确定性算法，不能使用 Swift 的 `hashValue`、`Hasher` 或随机种子。相同输入在重启和不同运行环境中得到相同顺序。
- 颜色池及算法一旦发布便影响用户的固定位置，后续变更需考虑兼容；不改写已有会话颜色，也不影响自动颜色分配规则。
- 对当前色做现有规范化处理；大小写差异不影响选中。当前色替换首位时保证展示列表中没有重复颜色。
- 保持现有颜色异步保存、失败反馈、会话绑定及取色器生命周期。

## 验证

- 测试相同会话标识多次调用结果一致、六个基础色不重复，以及不同标识的代表性结果存在差异。
- 测试当前色位于候选中、位于候选外、大小写不同、无效或为空时的展示与选中状态。
- 检查预设选择和自定义选择后，菜单、设置页与 HUD 保持同步；保存失败时保留已保存颜色。
- 运行相关测试和构建，人工检查浮层中的色位、勾选与自定义入口。

## 不包含

- 保证不同会话之间所有色值均不重复。
- 根据其他会话当前颜色动态重排候选。
- 改动会话自动分配颜色或已有保存格式。

## 详细开发步骤

1. 在 `Sources/TraceflowCore` 新增独立的颜色候选模块。接口接收会话 ID 和可选当前颜色，返回有序的六项；每项至少包含标准化颜色字符串和是否选中。接口不读取时间、进程状态、其他会话或持久化数据。
2. 生成六个基础候选时，使用下面固定颜色池和确定性算法。先取得基础列表，再单独计算展示列表；不要用当前颜色参与洗牌。
3. 用 `SessionMarkerColor.normalized` 规范化当前颜色。有效颜色已在基础列表中时，六个色位不变，仅标记对应项。有效颜色不在列表中时，复制基础列表，把索引 0 替换为当前颜色并选中；索引 1 至 5 不变。不存在或无效时不替换，也不选中任何项。
4. 修改 `Sources/TraceflowApp/MenuWindowView.swift` 中的 `colorPicker`，遍历候选模块的输出。继续调用现有 `requestMarkerColor`，不直接写入模型；“自定义”入口、错误反馈和取色器生命周期不变。选中状态使用返回值，不自行比较原始字符串。
5. 在 `Tests/TraceflowCoreTests` 增加针对纯函数的行为测试，运行相关测试；运行菜单窗口和颜色面板现有测试，再构建应用。人工验证只在具备原生桌面环境时进行；若无法验证，应明确说明。

## 固定颜色池和算法

颜色池顺序如下，首个版本发布后不得随意更改：

```text
#477EE8 #9963DD #E458A3 #D77B23 #1597A4 #597344
#6C7FE8 #E4A665 #67B7A0 #E16F7F #AC80CF #8192A5
#C55D54 #5587A6 #A68140 #598C6C #C46182 #7869B5
```

使用以下明确步骤，保证不同进程结果相同：

1. 会话 ID 按原始字符串的 UTF-8 字节处理，不转换大小写或去空格。初始值为无符号 64 位整数 `14695981039346656037`。
2. 按字节顺序，对每个字节执行 `state = (state XOR byte) × 1099511628211`。所有乘加按无符号 64 位溢出回绕；Swift 中使用 `&*`、`&+`，不要使用可能触发溢出崩溃的普通乘加。
3. 复制上述颜色池，执行倒序 Fisher–Yates 洗牌。索引 `i` 从 17 递减到 1：先执行 `state = state × 6364136223846793005 + 1442695040888963407`，同样按 64 位回绕；令 `j = state % (i + 1)`，交换索引 `i`、`j`。
4. 取洗牌后前六项作为基础列表。所有颜色均使用大写 `#RRGGBB` 格式。

以下测试向量用于验证实现，而非供界面写死：

| 会话 ID | 六个基础候选 |
| --- | --- |
| `session-a` | `#D77B23`、`#1597A4`、`#598C6C`、`#67B7A0`、`#597344`、`#5587A6` |
| `session-b` | `#67B7A0`、`#E4A665`、`#477EE8`、`#E16F7F`、`#C46182`、`#6C7FE8` |
| 空字符串 | `#A68140`、`#597344`、`#E16F7F`、`#E4A665`、`#7869B5`、`#477EE8` |

## 边界示例与验收

- `session-a` 当前色为 `#1597a4`：显示上述完整基础列表，第二项选中，比较前需规范化大小写。
- `session-a` 当前色为 `#123456`：依次显示 `#123456`、`#1597A4`、`#598C6C`、`#67B7A0`、`#597344`、`#5587A6`，第一项选中。
- `session-a` 当前色为 `nil` 或 `invalid`：显示完整基础列表，无选中项。
- 从候选外的当前色切换到基础列表第二项后，首位恢复基础列表第一项，第二项选中；切换到自定义颜色时，只替换首位。
- 至少覆盖固定向量、同 ID 重复调用、不同 ID、六项唯一性、上述当前颜色情况、其他会话状态不影响结果。无效颜色不得传入保存接口。
- 浮层空间应能容纳六色和“自定义”，原有勾选标记、辅助功能、错误提示、保存行为不退化。
- 按已授权阶段工作流：实现前等待 PRD 明确批准；实施期间每个阶段运行相关验证并提交，然后继续下一阶段。提交标题遵循项目中文 Conventional Commits 规范，正文引用本 PRD 的仓库相对路径。
