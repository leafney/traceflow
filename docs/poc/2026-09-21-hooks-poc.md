## 目标

在正式工程实现前，验证 Traceflow 所依赖的 Codex Hooks 配置格式、公共字段与基本生命周期事件。PoC 只记录字段名和脱敏会话标识，不记录 prompt、工具输入、工具输出、完整路径或原始 payload。

## 环境

- macOS 14.1.2
- Swift 5.9.2
- Xcode 15.1
- Codex CLI 0.152.1
- `/Applications/ChatGPT.app` 已安装
- 用户级 Codex 配置位于 `~/.codex/config.toml`

## 官方依据

[OpenAI Hooks 官方文档](https://learn.chatgpt.com/docs/hooks)列出了本项目使用的七类事件，并说明：

- CLI 与 Codex 桌面体验使用活动配置层旁的 `hooks.json` 或 `config.toml` 内联 Hooks。
- 公共输入包含 `session_id`、`cwd`、`hook_event_name` 和 `model`。
- 回合事件额外包含 `turn_id`。
- 后台 Hook 可能乱序完成。
- 会话结束时，尚未完成的后台 Hook 会被取消。
- `SessionEnd` 始终同步运行。

## 可重复验证

```bash
chmod +x scripts/poc/*.sh
scripts/poc/run-cli-poc.sh
```

脚本通过 CLI 临时配置注入七类 Hook，并使用 `--dangerously-bypass-hook-trust`，不会写入用户长期配置。捕获结果默认写入 `/tmp/traceflow-hooks-poc.jsonl`。

## 验证范围与结论

### 自动验证

- CLI 能加载与官方结构一致的 Hook 配置。
- `SessionStart`、`UserPromptSubmit`、`Stop` 和 `SessionEnd` 可由一个普通非交互回合触发。
- 捕获事件包含稳定的 `session_id`、`cwd` 与 `hook_event_name`；回合事件包含 `turn_id`。
- PoC Hook 输出惰性 `{}`，不会审批、拒绝、改写或继续 Codex 流程。

本次脱敏实测字段如下：

| 事件 | 公共字段 | 事件字段 |
|---|---|---|
| `SessionStart` | `session_id`、`cwd`、`hook_event_name`、`model`、`permission_mode` | `source=startup` |
| `UserPromptSubmit` | 公共字段齐全 | `turn_id`、`prompt` |
| `Stop` | 公共字段齐全 | `turn_id`、`stop_hook_active`、`last_assistant_message` |
| `SessionEnd` | `session_id`、`cwd`、`hook_event_name` | `reason` |

实测还确认：若 `Stop` 设为后台异步，短生命周期的 `codex exec` 可能在后台 Hook 完成前进入 `SessionEnd`，导致绿色完成事件丢失。因此成品配置将 `Stop` 设为同步，但保持转发器快速本地发送；其他非结束事件仍可异步。

### 需要特定交互才能触发的事件

- `PermissionRequest`：只在工具需要审批时触发。
- `PostToolUse`：只在实际工具调用完成后触发。
- `Interrupt`：只在用户中断活动回合时触发。
- `SessionEnd`：在归档、删除、正常关闭或满足官方空闲关闭条件时触发。

这些事件的字段与时机由官方文档定义，成品阶段使用真实交互再次验证。

### 桌面端说明

本机安装的是 `ChatGPT.app`，Codex 桌面体验与 CLI 读取同一用户级 Codex 配置层。PoC 阶段验证共享配置前提和 App 存在；完整桌面端事件到 HUD 的可视端到端验证安排在阶段 5。若成品实测发现桌面端未触发所需 Hook，必须按 PRD 停止交付并请求用户决定替代方式，不得将 CLI-only 宣称为双端完成。
